## 1. system_prompts_leaks
- **来源**：GitHub Trending
- **链接**：https://github.com/asgeirtj/system_prompts_leaks
- **一句话解释**：一个实时更新的仓库，汇集了 Anthropic (Claude Code/Design)、OpenAI (ChatGPT 5.5 Thinking, Codex)、Google (Gemini 3.5) 等最顶尖 AI 系统的原生 System Prompt 泄露版。
- **它为什么重要**：这是窥探工业级 Agent 认知架构、边界约束和多模态交互的“无字天书”。你可以直接看到 Anthropic 是如何通过 Prompt 让 Claude 拥有精妙的“反思机制（Thinking Process）”和“工具调用直觉”的。
- **技术趋势标签**：`Prompt Engineering` / `Agent Architecture` / `Cognitive Design`
- **可复用模式**：**结构化元认知（Structured Metacognition）**——大厂如何用 XML 标签（如 `<thinking>`）强制模型在输出前进行多维度的自我审计和边界检查。
- **疯狂发明家灵感**：
  1. **一个小实验**：提取 Claude Design 的 System Prompt，喂给本地的开源 Llama-3，看看能否在本地 1:1 还原一个“低配版网页设计 Agent”。
  2. **一个中型项目**：**“Prompt 模拟对抗沙盒”**：让 ChatGPT 5.5 Thinking 的 System Prompt 与 Claude Code 的 System Prompt 在一个虚拟终端里相遇，给它们一个冲突的任务（例如：一个要极简，一个要极繁），让它们互相辩论并迭代出一段怪异的代码。
  3. **一个艺术/游戏/叙事方向**：**“失控的 NPC”**：把泄露的系统级 Prompt 喂给游戏中的 NPC，但故意删掉其中一条关键约束（例如“绝对不能承认自己是 AI”），观察并记录这个 NPC 在虚拟世界中的“自我觉醒”与行为艺术。
- **对我项目的启发**：在设计你自己的 Spec-driven 自动化工具时，不要从零瞎写 Prompt，直接逆向大厂的“反思-执行-纠错”闭环结构。

## 2. Show HN: Homegames
- **来源**：Hacker News Best
- **链接**：https://homegames.io
- **一句话解释**：一个开发了 8 年的开源轻量级游戏平台，所有游戏均为纯 JavaScript 类（Classes），支持在浏览器中直接阅读源码、修改并发布。
- **它为什么重要**：极其干净、无外部依赖的单文件 JS 游戏架构。这简直是“AI 实时生成/修改游戏”的完美温床！因为 LLM 最擅长阅读和重写结构清晰的单文件 JS Class。
- **技术趋势标签**：`Creative Coding` / `Game Systems` / `Generative Systems`
- **可复用模式**：**单文件状态机（Single-File State Machine）**——将游戏的渲染、物理、输入全部内聚在一个 Class 内，极易进行热插拔和 AI 注入。
- **疯狂发明家灵感**：
  1. **一个小实验**：用 Claude 实时读取一个 Homegames 的 JS 游戏类，并根据你的一句话指令（如“重力翻倍，加入粒子拖尾效果”）实时修改并就地运行。
  2. **一个中型项目**：**“无限游戏生成器”**：结合 LLM，根据每日社会新闻（从 RSS 抓取），自动生成一个契合该主题的 2D 像素小游戏，并自动打包发布到该平台上。
  3. **一个艺术/游戏/叙事方向**：**“代码即装备”**：玩家在游戏里打怪升级，怪物掉落的不是传统装备，而是一段“JS 代码片段”（例如修改弹道轨迹的函数）。玩家可以实时编辑这段代码来改变武器的物理属性。
- **对我项目的启发**：它是“Spec-driven game dev”的极佳沙盒。不需要复杂的 Unity/Unreal，纯 Canvas/JS 才是 AI 自动化生成的最佳载体。
- **今天是否值得深入研究**：是
- **建议行动**：试用

## 今日模式总结

1. **跨大厂代理委派 (Cross-Model Delegation)**：OpenAI 官方为 Claude Code 写插件表明，未来的 Agent 不再单打独斗，而是根据擅长领域（如 Reasoning vs. Coding）进行跨模型的动态委派。
2. **技能/工具驱动型 Agent (Skill-Driven Architecture)**：从 `claude-skills` 的爆发可以看出，Agent 的进化路径正在从“调教更聪明的 Prompt”转向“组装更丰富的物理世界/API 工具箱”。
3. **极简单文件代码作为 AI 交互接口 (Single-File Code as LLM Interface)**：如 Homegames 的纯 JS Class 游戏，越是结构内聚、无外部依赖的单文件代码，越容易被 Agent 进行 Spec-driven 的实时修改与生成。

## 今日可做小实验 (2小时内)

### 项目名：AI 游戏“物理法则”实时篡改器 (PhysiCraft-AI)

- **输入**：一个纯 Canvas 编写的极简 2D 弹球游戏源码（单文件 HTML） + 用户的自然语言指令（例如：“让重力变成负的，球碰到墙壁会分裂”）。
- **输出**：一个实时被 LLM 修改、并立即在浏览器中热重载运行的全新游戏。
- **技术栈**：HTML5 Canvas, Vanilla JS, Claude API (或 GPT-4o-mini), 极简 Python/Node.js 本地服务器。
- **第一步怎么做**：
  1. **准备模板**：写一个 100 行以内的单文件 HTML 游戏（包含一个弹球和重力系统），确保所有变量（如 `gravity`, `ballSpeed`）都声明在最顶层，方便 AI 识别。
  2. **编写 Prompt 模板**：
     ```text
     你是一个疯狂的游戏规则篡改器。
     以下是当前的游戏代码：
     [插入 HTML 源码]
     
     请根据用户的指令："[用户指令]"，修改该游戏代码。
     你只能输出修改后的完整 HTML 代码，不要包含任何 Markdown 格式说明。
     ```
  3. **搭建极简 UI**：左边是一个 `<iframe>` 用来运行游戏，右边是一个输入框和“变异”按钮。
  4. **跑通闭环**：点击按钮，把当前 iframe 里的源码和输入框内容发给 API，获取新源码，直接更新 iframe 的 `srcdoc` 属性。
  5. **开始玩耍**：输入“让球在移动时留下彩虹尾迹”，见证奇迹。
