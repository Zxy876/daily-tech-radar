## 1. [ARIS：在睡眠中让 Claude 为你做研究]
- 来源：GitHub Trending / wanshuiyin
- 链接：https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep

- 疯狂发明家灵感：
  1. **一个小实验**：写个脚本，每晚睡前把一个模糊的艺术构思丢给它，醒来时它已经跑了 50 次 Stable Diffusion 提示词优化并选出了前 3 名。

## 2. [从 CoT 中提取搜索树：揭示 LLM 的“近视”规划]
- 来源：arXiv cs.AI (2605.06840)
- 链接：https://arxiv.org/abs/2605.06840
- 一句话解释：研究者通过解析 LLM 的推理轨迹（Chain of Thought），将其还原成一棵动态搜索树，发现模型其实在“走一步看一步”。
- 它为什么重要：它提供了一种**“思维可视化”**的脚手架。如果你能实时提取这棵树，你就能在 Agent 走错路之前强行修剪分支。
- 技术趋势标签：#Interpretability #ReasoningTrace #SearchTree
- 可复用模式：**“推理树修剪”**：将不可见的 token 流转化为可见的决策图，引入外部启发式算法干预。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个 p5.js 程序，实时读取 LLM 的推理过程，并将其绘制成一棵不断生长的分形树。
  2. **一个中型项目**：**“决策回滚编辑器”**：一个可视化写代码工具，你可以看到 Agent 尝试过的所有错误分支，并手动点击某个节点让它“从这里重新开始”。
  3. **一个艺术/游戏/叙事方向**：**“多线结局推理机”**：在叙事游戏中，玩家可以看到 Agent 脑中正在生成的 5 种不同结局的概率树，并可以“剪掉”不喜欢的结局。
- 对我项目的启发：对 HCI 极其重要。不要只给用户看一个 Loading 动画，给他们看那棵正在生成的决策树。
- 今天是否值得深入研究：是
- 建议行动：**收藏**（作为可视化组件的技术储备）。

## 3. [Behavior Cue Reasoning：通过“行为暗示”实现监控推理]
- 来源：arXiv cs.AI (2605.07021)
- 链接：https://arxiv.org/abs/2605.07021
- 一句话解释：通过训练模型在执行危险或关键动作前发出特定的“Token 暗示”（Behavior Cues），让监管者能提前拦截。
- 它为什么重要：这是一种**“预感知”**机制。对于艺术装置或游戏系统，这意味着你可以捕获 Agent 的“意图”而不必等它完全输出。
- 技术趋势标签：#AI_Safety #Interactive_AI #Oversight
- 可复用模式：**“意图拦截器”**：在生成最终文本前，先检测特定的“元标记”来触发外部系统动作。
- 疯狂发明家灵感：
  1. **一个小实验**：在 Minecraft 中，让 Agent 在放置方块前先输出 `<THINK:BUILD>`，你的插件捕获这个词并闪烁光效提示玩家。
  2. **一个中型项目**：**“情绪预防 UI”**：当 Agent 的推理轨迹中出现攻击性倾向的“暗示”时，UI 背景色自动变红。
  3. **一个艺术/游戏/叙事方向**：**“读心术 NPC”**：NPC 会把它的“内心独白”作为 Behavior Cue 发送，玩家必须通过特定的交互才能“听到”这些暗示。
- 对我项目的启发：非常适合 Agent Workflow 的自动化，利用特殊 Token 作为不同状态机切换的信号。
- 今天是否值得深入研究：是
- 建议行动：**试用**（在 Prompt 中加入自定义 Tag 模拟这种行为）。

## 5. [GraphDC：分治法多 Agent 系统处理图算法推理]
- 来源：arXiv cs.AI (2605.06671)
- 链接：https://arxiv.org/abs/2605.06671
- 一句话解释：用“分而治之”策略，让多个 Agent 协作解决复杂的图拓扑推理问题。
- 它为什么重要：世界生成和叙事逻辑本质上都是图。单 Agent 处理大规模关系会崩掉，GraphDC 提供了一种分布式解决思路。
- 技术趋势标签：#MultiAgent #GraphReasoning #DivideAndConquer
- 可复用模式：**“拓扑拆解”**：将一个巨大的逻辑图拆成子图，分发给不同 Agent 处理，最后由 Leader Agent 汇总。
- 疯狂发明家灵感：
  1. **一个小实验**：用 3 个 Agent 共同编写一个复杂的、充满人物关系的短篇故事剧本，A 负责家族树，B 负责冲突图，C 负责整合。
  2. **一个中型项目**：**“无限生成城市逻辑”**：一个 Agent 负责城市规划（图），另一个 Agent 负责具体街道填充，第三个负责交通流模拟。
  3. **一个艺术/游戏/叙事方向**：**“活着的社会网络”**：在游戏中模拟一个拥有 1000 个节点的社交网络，Agent 们自动在图中通过“分治”来演化谣言的传播。
- 对我项目的启发：当你的世界生成逻辑变得太复杂时，参考它的拆解策略。
- 今天是否值得深入研究：否（除非你现在正卡在图算法上）
- 建议行动：**忽略**（暂存，需要时再看）。

## 今日模式总结
1. **异步自主性 (Asynchronous Agency)**：不再等待用户输入，Agent 开始在后台利用“睡眠时间”或“闲置 CPU”进行自发性的实验和研究。

## 今日可做小实验：Behavior-Cue 艺术评论员
- **项目名**：Meta-Critic Agent
- **输入**：一张你的设计稿图片或一段代码。
- **输出**：在给出最终评价前，先输出它内心真实的、未经过滤的“第一反应”标签。
- **技术栈**：Python, Claude 3.5 Sonnet (API), Simple Console UI。
- **第一步怎么做**：
  1. 编写 System Prompt：“你是一个毒舌艺术评论家。在输出任何正式评价前，你必须先输出一个 `[INTERNAL_MONOLOGUE]` 块，里面包含你看到作品的第一印象、你想吐槽的点以及你认为最失败的地方。然后才输出正式的、客气的评价。”
  2. 运行对话，观察它的“内心戏”是否比正式评价更有启发。
  3. 进阶：用代码捕获 `[INTERNAL_MONOLOGUE]`，如果包含“垃圾”字样，直接终止程序并弹出一个巨大的红色警告。
