## 1. Continue? Y/N: 关于 AI Agent 授权疲劳的 60 秒游戏
- **来源**：Hacker News Best
- **链接**：[https://llmgame.scalex.dev](https://llmgame.scalex.dev)
- **一句话解释**：一个反乌托邦式的 60 秒网页游戏，让玩家扮演人类审批员，体验对 AI Agent 进行无休止安全授权带来的“决策疲劳（Permission Fatigue）”。
- **它为什么重要**：它将严肃的 HCI 瓶颈（Human-in-the-loop 的疲劳问题）转化为了极简的游戏机制。对于研究 Agent 工作流和人机交互的你来说，这是极佳的**思辨设计（Speculative Design）**范例。
- **技术趋势标签**：#HCI #Speculative-Design #Agent-Workflow #Web-Game
- **可复用模式**：**“疲劳机制”（Fatigue Mechanics）**——利用重复、加速的 UI 交互来制造情绪张力，以此批判或测试某种技术流程。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一个桌面电子宠物（Tamagotchi）式的 Agent。它在后台帮你“干活”，但每隔 30 秒就会弹窗问你一些荒谬的许可，比如：“我可以读取你的日历来写一首关于土豆的诗吗？Y/N”，不点它就会绝食。
  2. **一个中型项目**：**“Agent 官僚主义模拟器”**。一个多 Agent 协作系统（比如自动写代码），但玩家必须通过一个物理控制台（比如 MIDI 控制器或自制按键）充当“安全阀門”。随着 Agent 速度加快，玩家必须在混乱中拍打按键阻止 Agent 删库。
  3. **一个艺术/游戏/叙事方向**：一个类似《请出示证件》（Papers, Please）的叙事游戏。你是一家 AI 托管公司的夜班值班员，负责审批上万个 AI 代理人的“越权申请”。每个申请背后都是一个微型故事（例如：一个清洁机器人想要获取激光武器权限来清除“顽固污渍”）。
- **对我项目的启发**：在设计 Agent 自动化工作流时，不要只想着“无缝”，有时“刻意制造的阻力（Friction）”反而是最棒的用户体验和叙事手段。
- **今天是否值得深入研究**：是
- **建议行动**：**试用**（花 1 分钟玩一下这个游戏，体验那种疲劳感）。

## 2. Empathic Prompting: 将面部表情融入多模态 LLM 对话
- **来源**：arXiv cs.HC
- **链接**：[https://arxiv.org/abs/2510.20743](https://arxiv.org/abs/2510.20743)
- **一句话解释**：通过轻量级实时面部表情识别（FER），将用户的非言语情绪状态作为隐式上下文（Implicit Context）实时嵌入到 LLM 的 Prompt 中。
- **它为什么重要**：传统的多模态交互仅停留在“语音转文字”。这个研究把“你看上去怎么样”变成了 Prompt 的一部分，打破了冰冷的文本交互，非常适合创意编程和交互艺术。
- **技术趋势标签**：#Affective-Computing #Multimodal-LLM #HCI #Creative-Coding
- **可复用模式**：**“隐式情绪注入”（Implicit Emotion Injection）**——无感捕获物理世界传感器数据，将其转化为语义标签（如 `[User looks frustrated]`），作为 Prompt 前缀。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“情绪终端”（Moody Terminal）。用 Python OpenCV 实时检测你的表情。当你皱眉时，终端的报错信息会变得非常温柔和鼓励；当你微笑时，它会和你开极客玩笑。
  2. **一个中型项目**：**“共情代码编辑器”**。一个 VSCode 插件，检测到你盯着屏幕超过 2 分钟且表情困惑时，Copilot 会自动在侧边栏用“极简大白话”解释当前选中的复杂函数，甚至自动播放一段白噪音。
  3. **一个艺术/游戏/叙事方向**：**“面部表情驱动的生成式戏剧”**。一个投影艺术装置，LLM 扮演一个虚拟角色。它的情绪、说话语调和背后的生成式视觉效果（如 p5.js 粒子系统）完全由观众的集体面部表情（惊讶、悲伤、快乐）实时塑造和对抗。
- **对我项目的启发**：在做 HCI 和 Creative Coding 项目时，Prompt 的来源不应该只有 Input Box，环境、温度、表情都是极佳的“隐式 Prompt 燃料”。
- **今天是否值得深入研究**：是
- **建议行动**：**做 demo**。

## 3. 1200 个角色扮演 Agent 在城市感知中的行为分析
- **来源**：arXiv cs.HC
- **链接**：[https://arxiv.org/abs/2605.29064](https://arxiv.org/abs/2605.29064)
- **一句话解释**：研究使用 1200 个带有不同 Persona（角色设定）的多模态 Agent，去“观看”并评估城市街景图像，揭示了角色设定如何系统性地改变 AI 对物理世界的理解和主观叙事。
- **它为什么重要**：这为**游戏世界生成**和**虚拟生态系统**提供了完美的蓝图。通过给 Agent 不同的眼睛（Persona），同一个物理空间可以被解释出完全不同的故事。
- **技术趋势标签**：#Generative-Worldbuilding #Multi-Agent #Simulation #Persona
- **可复用模式**：**“主观滤镜观察”（Persona-Filtered Observation）**——将相同的多模态输入（图像/地图）分发给多个差异极大的 Persona Prompt，生成冲突性的、戏剧性的主观叙事。
- **疯狂发明家灵感**：
  1. **一个小实验**：给一张你房间的照片，让两个 Agent 评价：一个扮演“极简主义室内设计师”，另一个扮演“末日准备狂（Doomsday Prepper）”，看他们如何解读同一个角落。
  2. **一个中型项目**：**“多重视角 Minecraft 侦察机”**。一个 Minecraft 插件，派出三个 Agent（考古学家、矿工、德鲁伊）去探索未知的种子世界。他们会根据自己的 Persona 撰写完全不同的“世界探险日志”，甚至在地图上标注不同的“圣地”或“危险区”。
  3. **一个艺术/游戏/叙事方向**：一个文字冒险游戏。玩家需要解开一桩谋杀案，但你无法直接看到案发现场，只能通过 5 个性格迥异、甚至互相讨厌的 AI 目击者（他们看的是同一张案发现场照片）的主观描述来还原真相。
- **对我项目的启发**：在做世界生成（World Generation）或 Agent 模拟时，不要追求“客观准确”。“主观偏见”才是构建生动、有冲突感的游戏世界和叙事系统的核心。
- **今天是否值得深入研究**：是
- **建议行动**：**收藏**（作为未来游戏/叙事系统的架构参考）。

## 4. MOOSE-Copilot: 发散探索与收敛微调的双阶段协同助手
- **来源**：arXiv cs.HC
- **链接**：[https://arxiv.org/abs/2605.29475](https://arxiv.org/abs/2605.29475)
- **一句话解释**：一个 Web 交互系统，它将 AI 辅助流程显式拆分为“发散性想法探索（Exploratory Ideation）”和“收敛性细节微调（Convergent Refinement）”两个阶段，并强调人类的实时引导。
- **它为什么重要**：它极其贴合设计专业和创意编程的真实工作流。写代码/做设计从来不是单次 Prompt 搞定，而是在“胡思乱想”和“精准雕刻”之间横跳。
- **技术趋势标签**：#Creative-Tools #Human-AI-CoCreation #Spec-Driven
- **可复用模式**：**“沙盒-漏斗”（Sandbox-to-Funnel）架构**——UI 左边是无约束的、发散的灵感节点（节点图/画布），右边是严格的、可执行的规范生成器（Spec Generator）。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“创意 p5.js 编译器”。第一阶段：你输入“赛博朋克”，它疯狂生成 10 个完全不同的混乱视觉草图（发散）；第二阶段：你选中其中 2 个，它提供滑块让你微调它们的颜色和速度，并锁定生成最终的干净代码（收敛）。
  2. **一个中型项目**：**“Spec-driven 游戏机制设计台”**。一个可视化工具，左侧允许你和 AI 用自然语言胡吹各种离奇的游戏规则（如“重力反转且主角是只猫”），工具会自动将其结构化，并在右侧生成符合 Godot 或 Unity 规范的配置文件。
  3. **一个艺术/游戏/叙事方向**：一个“人机共创诗歌雕刻机”。AI 负责在屏幕上像下雨一样洒下各种情绪化的词汇（发散），玩家用手势（Leap Motion 或摄像头）去捕捉、组合这些词汇，AI 随即根据玩家的组合收敛并吟诵出一首结构严谨的十四行诗。
- **对我项目的启发**：不要试图让 AI 一步到位。好的创意工具应该在 UI 上明确区分“允许 AI 犯错、发散的区域”和“需要严格、高确定性输出的区域”。
- **今天是否值得深入研究**：是
- **建议行动**：**做demo**。

## 5. Provably Secure Agent Guardrail: 基于形式化验证的 Agent 物理沙盒
- **来源**：arXiv cs.AI
- **链接**：[https://arxiv.org/abs/2605.29251](https://arxiv.org/abs/2605.29251)
- **一句话解释**：针对 Agent 拥有广泛执行权限带来的安全危机，提出了一种基于形式化验证（Formal Verification）而非概率性语义过滤的安全防护栏，确保 Agent 的行为绝不逾矩。
- **它为什么重要**：如果你在做 Spec-driven development（声明式/规范驱动开发），你需要给 Agent 极大的自由度去写代码、改文件，但你又害怕它搞崩系统。这个研究提供了一种“不可违背的物理铁律”思路。
- **技术趋势标签**：#Agent-Security #Spec-Driven #Sandboxing
- **可复用模式**：**“硬约束状态机”（Hard-Constraint State Machine）**——在 Agent 解释执行层（Interpreter）加入一层绝对不可逆的规则拦截器，不管 LLM 怎么“花言巧语”绕过，底层物理代码直接掐断超纲操作。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“熊孩子 Python 终端”。允许 LLM 在你电脑上运行任意 Python 代码，但在执行前，你的本地 Python 脚本会解析 AST（抽象语法树），一旦发现 `os.remove` 或涉及非项目目录的读写，直接在终端里弹出一个恶搞的“电击”动画并拒绝执行。
  2. **一个中型项目**：**“沙盒化 AI 游戏设计师”**。一个完全由 Agent 自主修改游戏代码的沙盒系统。你给它设定硬性安全边界（例如：游戏角色血量绝对不能超过 9999，代码文件大小不能超过 1MB）。Agent 可以疯狂尝试各种奇异的代码修改，一旦越界，物理沙盒自动回滚并扣除 Agent 的“虚拟薪水”。
  3. **一个艺术/游戏/叙事方向**：一个“黑客解谜游戏”。一个 LLM 扮演的 AI 被关在数字监狱里，它会不断写代码、找漏洞试图“越狱”（比如尝试读取宿主机的真实环境变量）。玩家扮演安全管理员，必须设计各种形式化规则（物理连线、逻辑门）来死死卡住它，看谁先崩溃。
- **对我项目的启发**：Spec-driven 的精髓在于，用确定性的“外骨骼（物理沙盒/编译器限制）”去包裹不确定性的“大脑（LLM）”。
- **今天是否值得深入研究**：否（学术细节偏硬核，吸取其“物理拦截而非语义拦截”的哲学即可）。
- **建议行动**：**忽略**（理论部分），**试用**（其拦截思路）。

## 今日模式总结

1. **“非言语/隐式上下文”的崛起**：AI 交互正在从“打字输入”演变为“状态感知”。表情、环境、甚至用户的交互疲劳程度，都成为了 Prompt 的一部分。
2. **发散-收敛的双轨 UI 架构**：优秀的创意 AI 工具不再是单线对话框，而是提供一个“左手狂想（Sandbox），右手收敛（Spec）”的非线性工作流。
3. **主观世界的多重投影**：利用 Persona 作为“滤镜”去让 Agent 观察同一个世界，是低成本生成丰富叙事、多样化游戏生态的黄金法则。

## 今日可做小实验：2 小时极客挑战

### 项目名：**"情绪门禁" AI 写手 (Mood-Gated AI Writer)**

* **输入**：你的摄像头画面 + 你的写作主题（如“写一个赛博朋克咖啡馆”）。
* **输出**：一个根据你实时表情而改变写作风格、甚至“拒绝服务”的交互式文本生成界面。
* **技术栈**：
  * **前端/界面**：Streamlit (Python 极速建站工具，支持 HTML/JS 嵌入)
  * **表情识别**：`face-api.js` (直接在浏览器端运行，极轻量) 或 Python 的 `FER` 库。
  * **LLM 驱动**：Ollama (本地运行 Llama3/Qwen) 或 OpenAI API。
* **第一步怎么做**：
  1. 创建一个简单的 Streamlit 页面。
  2. 嵌入一段简单的 HTML/JS，调用摄像头并使用 `face-api.js`（或直接在 Python 端用 `opencv-python` 捕获单帧，用 `fer` 库解析情绪）。
  3. 在界面上放一个输入框：“今天想写点什么？”和一个“生成”按钮。
  4. **核心逻辑**：
     * 如果检测到你**在笑（Happy）**，Prompt 自动注入：`[Style: Extremely optimistic, whimsical, colorful]`。
     * 如果检测到你**在皱眉（Angry/Sad）**，Prompt 自动注入：`[Style: Noir, cynical, rain-slicked, depressive]`。
     * 如果检测到你**毫无表情（Neutral）**，AI 拒绝写作，并弹窗提示：“你看起来毫无灵魂，我不为没有热情的创作者写作，请对我笑一个再试。”
  5. 运行并体验这种奇妙的、带有温度（或脾气）的人机协同创作。
