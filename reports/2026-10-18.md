## 1. Show HN: Gemini 4 Argon plays StarCraft (StarSkirmish Bench)
- **来源**：Hacker News Best
- **链接**：https://starskirmish.com/bench/v0-2/
- **一句话解释**：让主流大模型通过“编写即时执行代码”直接操控《星际争霸：母巢之战》并对战的竞技 Benchmark。
- **它为什么重要**：它跳过了传统的强化学习黑盒端到端训练，验证了**“LLM 编写微型策略代码 -> 实时游戏引擎执行 -> 闭环反馈”**这一范式在极度复杂实时游戏环境中的可行性。
- **技术趋势标签**：Game AI / Code-as-Action / 实时系统闭环
- **可复用模式**：**Code-as-Policy**（代码即策略）。LLM 不直接发出单步操作指令，而是根据环境快照生成一段高内聚的控制脚本（Micro-bot logic）交给引擎执行，降低 token 消耗并提升决策频率。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 Python 脚本，让 LLM 根据 Minecraft 玩家当前周围方块和怪物坐标，实时生成 10 行以内的 Mineflayer 控制代码以保命。
  2. **一个中型项目**：构建一个双 Agent 实时策略沙盒，两个 LLM 扮演指挥官，每 30 秒编写一次兵种生产与寻路逻辑脚本，在网页 Canvas 上实时互殴演化。
  3. **一个艺术/游戏/叙事方向**：**《代码斗兽场（Glitch Colosseum）》**。玩家不直接下场打架，而是作为巫师/机械师为角斗士撰写行为规则；NPC 拥有由 LLM 动态生成的有缺陷性格脚本（例如：狂妄型角斗士会在血量低时故意写出自杀式冲锋代码）。
- **对我项目的启发**：非常适合 Minecraft 生成世界或自研游戏系统！不要让 Agent 逐帧思考，让它“编写子程序”控制世界，是解决高频游戏循环与高延迟 LLM 矛盾的最优解。
- **今天是否值得深入研究**：是

## 2. Fission-AI / OpenSpec
- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/Fission-AI/OpenSpec
- **一句话解释**：专为 AI 辅助编程打造的“Spec 驱动开发（SDD）”结构化框架。
- **它为什么重要**：直击你关注的 **spec-driven development**。AI 编程目前最大的瓶颈是上下文漂移和需求腐化，OpenSpec 将模糊意图冻结为机器可解析、可逐步验证的 Spec 契约。
- **技术趋势标签**：Spec-Driven / AI Workflow / 确定性工程
- **可复用模式**：**Contract-First Agent Loop**。Spec（意图规范）-> Test Matrix（验证矩阵）-> Code Generation（实现）-> Evaluation（自我审查）的严格单向状态机。
- **疯狂发明家灵感**：
  1. **一个小实验**：用 Markdown + YAML 定义一个“UI 组件生成 Spec”，测试 Claude Code 是否能严格按照 Spec 约束，生成零样式漂移的 React 按钮组件。
  2. **一个中型项目**：**Spec2World**。写一个用于 Minecraft 世界生成的 Spec 规范（包含生态比例、主线地牢难度、资源曲线），由 Agent 负责将其转译成方块生成脚本并自我校验。
  3. **一个艺术/游戏/叙事方向**：**《叙事宪法发生器》**。设计一套“叙事 Spec 语法”，约束互动小说的世界观公理（例如：“任何魔法都会导致水结冰”），Agent 随后生成剧本时，一旦违背 Spec 即被自动打回重写。
- **对我项目的启发**：完全可以成为你正在构思的 Drift 工具链的核心底层设计：让 Agent 在执行前先产出精确的架构与交互协议。
- **今天是否值得深入研究**：是
- **建议行动**：试用

## 3. google / artemis
- **来源**：GitHub Trending Python
- **链接**：https://github.com/google/artemis
- **一句话解释**：99%+ 成功率的自然语言驱动 Android 自动化引擎，无缝接入 Claude Code 等助手。
- **它为什么重要**：从“桌面 Agent”跨越到“移动端物理世界交互”。它不仅是测试工具，更是让 AI 掌控移动设备 GUI 的完整中介层，具备极强的容错与环境重试能力。
- **技术趋势标签**：Mobile Agent / GUI Automation / HCI
- **可复用模式**：**Visual-Semantic Grounding**（视觉语义锚定）。将屏幕树结构（Accessibility Node）与视觉流混合，转化为 LLM 能百分之百精确定位的操作节点。
- **疯狂发明家灵感**：
  1. **一个小实验**：把手机插在电脑上，通过 Claude Code 发出指令：“打开相机，拍一张我桌面的照片，并用系统相册的黑白滤镜保存”。
  2. **一个中型项目**：**跨媒介自动化艺术家（Ghost Creator）**。Agent 在手机端利用多个原生生图/滤镜/剪辑 App 互相倒手资产，全自动生产拼贴数字艺术并分发。
  3. **一个艺术/游戏/叙事方向**：**《被困在手机里的幽灵》**。观众在电脑端向 Android 虚拟机下达叙事指令，Agent 像真人一样在仿真的手机社交软件中寻找线索、打字、窥探相册，通过投屏营造出数字幽灵操纵手机的交互装置。
- **对我项目的启发**：HCI 与自动化的大杀器，摆脱了 Web 浏览器的局限，把现实世界中最普及的计算终端（手机）变成了你的 Agent 可触达的画布。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 4. akitaonrails / ai-memory
- **来源**：GitHub Trending
- **链接**：https://github.com/akitaonrails/ai-memory
- **一句话解释**：为各类命令行 AI 编码工具提供跨会话持久记忆，并支持在不同厂商 Agent 间无缝移交工作上下文。
- **它为什么重要**：解决了当前多 Agent 协同中的核心痛点——**上下文资产孤岛**。你在 Cursor 里的探索、在 Claude Code 里的报错排查，可以通过统一的长期记忆层无损共享。
- **技术趋势标签**：Agent Memory / Handoff Protocol / Developer Tooling
- **可复用模式**：**Vendor-agnostic Context Schema**（无视厂商的上下文规范）。提取高价值决策树（Decisions made, dead ends reached, mental models）而非保存全量聊天记录。
- **疯狂发明家灵感**：
  1. **一个小实验**：让 Claude Code 完成一段功能原型，提炼它的“思考过程”写入一个纯文本记忆文件，再唤起另一个本地开源小模型（如 Ollama）读取该记忆并补全注释。
  2. **一个中型项目**：**开发者的“第二脑潜意识”**。挂在系统后台监听你的 Git 提交与终端历史，自动提取你最近的技术偏好与设计决策，随时注入到任意新开的 Agent 终端中。
  3. **一个艺术/游戏/叙事方向**：**《记忆接力体（Exquisite Corpse Mind）》**。构建一个叙事 NPC，但背后由三个不同性格/模型的 Agent 轮流驱动，仅依靠统一的 `ai-memory` 保持性格记忆一致，但每次说话风格与潜台词都在诡异微调。
- **对我项目的启发**：记忆不应该是笨重的向量数据库全量检索，而应是精简的、可结构化移交的“状态手账”。
- **今天是否值得深入研究**：是
- **建议行动**：做 demo

## 今日模式总结

1. **Code-as-Action（代码即动作）**：从 StarSkirmish 可以明确看出，高阶环境控制（游戏/物理世界）的最优解不是直接输出单一操作，而是让 LLM 编写“逻辑补丁（Patch）”让宿主环境高频执行。
2. **Spec-first Execution（规格先行）**：OpenSpec 代表的趋势意味着“Prompt 即代码”正在向“Spec 约束 Agent，Agent 生成代码”演进，确定性规范成了抑制幻觉的关键。
3. **Decoupled Agent State（解耦的 Agent 状态层）**：像 `ai-memory` 这种工具的出现，证明了 Agent 的执行模型与上下文记忆正在彻底解耦，为未来随叫随到的“群体智能接力”铺平了道路。

## 今日可做小实验

### 项目名：Minispec-Bot（微型规范生成器）
*用 2 小时验证 Spec-driven 方式生成生成艺术（Generative Art）画布的精确度。*

- **输入**：一段极简的世界观/美学设计 Spec（YAML 格式，定义色盘、拓扑规则、几何约束、交互规则）。
- **输出**：一个零依赖、完全符合 Spec 约束并可在浏览器实时运行的 p5.js / Canvas 动画网页。
- **技术栈**：Claude Code / Cursor、Node.js、p5.js、YAML
- **第一步怎么做**：
  1. 在本地创建一个空目录，新建 `art-spec.yaml`：
     ```yaml
     canvas: { width: 800, height: 600, fps: 60 }
     palette: ["#1A1A1A", "#E84855", "#F9DC5C", "#3185FC"]
     rules:
       entity_count: 50
       motion: "curl_noise_flow"
       constraints: "entities must never touch canvas borders, reflect when close"
     interaction: "mouse_click creates a localized gravitational well for 1.5s"
     ```
  2. 启动 Claude Code，输入 Prompt：
     > *"读取当前目录下的 art-spec.yaml。严格将其视作系统规格，不要自由发挥添加额外元素。编写一个单一的 index.html，引入 p5.js，用纯代码实现该 Spec。如果无法实现某条规则，先向我报错，不要跳过。"*
  3. 观察 Agent 是否能完全受限于 Spec 进行生成式编码，记录它对非确定性自然语言约束（如 `curl_noise_flow`）的转译精度。
