## 1. Learning to Reason in Real-Time: 摆脱“世界等你思考”的实时 Agent
- **来源：** arXiv cs.AI
- **链接：** https://arxiv.org/abs/2611.33513
- **一句话解释：** 论文打破了现有 LLM Agent 假设“世界处于回合制等待我输出”的温室假设，研究当物理/仿真世界持续流逝时，Agent 如何根据时间预算动态调整推理深度与行动决策。
- **它为什么重要：** 现有的 AI 游戏 NPC、实体机器人或交互装置极其僵硬，核心瓶颈就是“思考延迟与环境突变不匹配”。让 Agent 学会“边跑边想，来不及就先闪避”，是从回合制走向拟真自主生命的关键一步。
- **技术趋势标签：** Real-Time Agent / Anytime Reasoning / 游戏 AI / 动态环境交互
- **可复用模式：** **渐进式推理放弃机制（Anytime Inference with Deadline）**——给推理设置动态 Tick，在规定毫秒内若未得出最优 CoT，则降级为快思考本能输出。
- **疯狂发明家灵感：**
  1. **一个小实验：** 用 Python 写一个简单的文本“落石躲避”命令行，LLM 每秒必须给出一个动作指令，若思考超过 1 秒直接判定被砸死，测试不同提示词策略下的保命率。
  2. **一个中型项目：** **Minecraft“易怒且手忙脚乱的生存搭子”**：接入 Minecraft 实时服务器，怪物靠近时它没有时间写 500 字规划，只能惊慌乱跳；安全坐在火堆旁时它才会做深度长链规划。
  3. **一个艺术/游戏/叙事方向：** **动态倒计时的 AI 审讯室游戏**：嫌疑人（Agent）不仅看你说什么，还看你犹豫了多久；当房间开始漏水/起火时，由于算力资源（心理压力）被压缩，Agent 的谎言会暴露出破绽。
- **对我项目的启发：** 在设计自主世界或多 Agent 交互时，不要把 Agent 包装成无限制阻塞主线程的黑盒，引入“思考时间成本”可以产生极度真实的拟人张力和玩法机制。
- **今天是否值得深入研究：** 是
- **建议行动：** 做demo

## 2. codegraph: 本地免 Token 的即时代码知识图谱
- **来源：** GitHub Trending TypeScript
- **链接：** https://github.com/colbymchenry/codegraph
- **一句话解释：** 一个 100% 本地运行、随代码变更自动增量同步的代码知识图谱，专为 Claude Code、Cursor、Gemini 等 Agent 减少上下文消耗与无脑 Tool Calls。
- **它为什么重要：** Agent 搞崩工程项目或消耗数万 Token，往往是因为用“全文搜索/暴力读取”来建立心智模型。结构化的本地语义/AST 图谱是 Spec-Driven Development 和自动化工具链最需要的“即时内存”。
- **技术趋势标签：** Local Knowledge Graph / Developer Tools / Agent Toolchain / Spec-Driven
- **可复用模式：** **AST 关系增量图（Incremental AST Relationship Indexing）**——把代码实体当作拓扑节点，变更时仅局部更新，Agent 只需要查询子图而非翻阅文件树。
- **疯狂发明家灵感：**
  1. **一个小实验：** 将该 repo 克隆下来，给自己的一个前端小项目生成拓扑图，用 CLI 让 Claude 仅基于子图输出架构重构建议。
  2. **一个中型项目：** **代码库“活体交互地图”（Living Architecture Map）**：将生成的 codegraph 接入 Three.js / Canvas，将代码依赖可视化为类似《孢子》的生物网络，点击某个节点即驱动本地 Agent 重构该模块。
  3. **一个艺术/游戏/叙事方向：** **“代码即地牢”世界生成器**：把一个开源项目的 codegraph 映射为 Minecraft 的地下城——函数是房间，引用是通道，圈复杂度决定怪物强度。
- **对我项目的启发：** 做 Agent 工作流时，先为 Agent 准备“结构化的拓扑地图”，远比直接把一堆 Markdown 文档和 Prompt 塞进 Context 窗口高效、干净得多。
- **今天是否值得深入研究：** 是
- **建议行动：** 试用

## 3. FIG-MAC: 细粒度灵感图谱驱动的多智能体协同假设生成
- **来源：** arXiv cs.AI
- **链接：** https://arxiv.org/abs/2611.33563
- **一句话解释：** 利用“细粒度灵感图谱”（Inspiration Graph）打破传统 CoT 的同质化，让多个 Agent 分别扮演跨学科关联者，从概念裂隙中碰撞出可验证的颠覆性科学假设。
- **它为什么重要：** 很多多 Agent 系统就是几个 LLM 在那里打乒乓球复读废话。该论文展示了如何用显式的“灵感图谱”作为外部黑板（Blackboard），强制 Agent 寻找不同概念簇之间的弱连接。
- **技术趋势标签：** Multi-Agent Collaboration / Creative Ideation / 概念图谱 / 自动化发现
- **可复用模式：** **跨域灵感跳跃（Cross-Cluster Conceptual Jumping）**——限制 Agent 不能在同一聚类内找解，必须从两个看似无关的子图节点之间架设“假设桥梁”。
- **疯狂发明家灵感：**
  1. **一个小实验：** 提取自己的 20 篇灵感笔记生成节点，强制写一个 Python 脚本随机拉取两个距离最远的节点，调用小模型生成一个“跨界产品概念”。
  2. **一个中型项目：** **“疯狂专利孵化机”**：接入近期 arXiv 跨学科论文（如生化 + 图形学），多 Agent 分别负责“反向提问”、“物理常识校验”、“工程构型”，每天自动产出 1 个怪异的可落地硬件点子。
  3. **一个艺术/游戏/叙事方向：** **推演未来神话的 Worldbuilder**：让 Agent 分别掌管“魔法规则图谱”和“失落科技图谱”，二者强行交叉结合，生成带严格内部自洽逻辑的奇幻/科幻世界观设定集。
- **对我项目的启发：** 做创新工具时，Agent 本身不需要凭空发疯；给它们设计一套“强迫关联反直觉节点”的图拓扑规则，创造力就会自然涌现。
- **今天是否值得深入研究：** 是
- **建议行动：** 收藏

## 4. CA-RAG: 约束对齐检索，专治长文生成结构塌缩
- **来源：** arXiv cs.AI
- **链接：** https://arxiv.org/abs/2611.33497
- **一句话解释：** 传统的 RAG 只根据“语义相似度”检索，而 CA-RAG 会根据下游必须要遵守的“结构性硬约束/必填条款”，主动补齐并对齐检索内容，保证复杂长文本生成的严格合规。
- **它为什么重要：** 这是 **Spec-Driven（规格驱动）** 思想在 RAG 领域的纯正体现。你定义了一个游戏关卡 Spec 或剧情框架，普通 RAG 会漏掉关键规则，而 CA-RAG 让检索本身就受“规格契约”约束。
- **技术趋势标签：** Spec-Driven RAG / 结构化生成 / 规则系统 / 强一致性
- **可复用模式：** **契约导向检索（Contract-Obligation-Guided Retrieval）**——把输出的 Specification（规格说明书）拆成必须满足的 Slot，每一个检索 Query 都是为了填满某一条特定约束，而不是泛泛的主题搜索。
- **疯狂发明家灵感：**
  1. **一个小实验：** 设定一个 Minecraft 建筑规范（必须有承重柱、必须有通风井、材质必须抗爆），用脚本测试：纯 Prompt 生成 vs 约束槽位先对齐检索再生成，对比合格率。
  2. **一个中型项目：** **极严苛的 Game Loop 逻辑生成器**：用户输入一段模糊的游戏玩法描述，系统自动将其拆解为状态机 Spec，并定向检索游戏设计模式，生成不可自相矛盾的代码逻辑。
  3. **一个艺术/游戏/叙事方向：** **侦探推理游戏的“防穿帮生成引擎”**：生成一宗案件时，强制对齐“物理证据链、不在场证明、作案动机”三维约束槽，绝不让生成出来的案件出现“死者在死后发短信”的逻辑漏洞。
- **对我项目的启发：** 抛弃纯语义模糊 RAG，采用“规格槽位驱动检索（Slot-filling RAG）”，是解决生成式系统不可控问题的正道。
- **今天是否值得深入研究：** 是
- **建议行动：** 做demo

## 5. Certify What You Plant: 杜绝程序化逻辑题生成中的“解题后门”
- **来源：** arXiv cs.AI
- **链接：** https://arxiv.org/abs/2611.33303
- **一句话解释：** 程序化生成谜题/逻辑题时，开发者通常预埋一条解题路径（Planted Proof）；但系统往往会意外生成更短的作弊路径。该论文提出了一套形式化验证方法，确保谜题必须达到设定的深度才能解开。
- **它为什么重要：** 这是程序化内容生成（PCG）与游戏关卡设计的圣杯问题。无论是在 Minecraft 生成解谜神庙，还是在 Roguelike 中生成谜题，如果无法验证“无捷径（Shortcut-Free）”，玩家就会通过跳关让精巧机制沦为笑话。
- **技术趋势标签：** Procedural Generation (PCG) / 形式化验证 / 谜题生成 / Game Systems
- **可复用模式：** **最短证明图剪枝验证（Proof Depth Certification）**——在生成谜题逻辑图后，跑一次全状态最短路径遍历，若存在步长小于预期目标 $K$ 的解，立即重构或补齐约束。
- **疯狂发明家灵感：**
  1. **一个小实验：** 用 Z3 或简易图搜索写一个 5 步推箱子生成器，加入这套验证，强制过滤掉所有可以 3 步内逃课的布局。
  2. **一个中型项目：** **Minecraft 自适应谜题地牢生成模组**：利用该机制在游戏中实时生成红石/机关密室，保证玩家必须按既定复杂度（证明深度）解谜，杜绝破坏方块外的逻辑跳步。
  3. **一个艺术/游戏/叙事方向：** **“不可作弊的互动叙事推理剧”**：剧本节点随玩家选择动态生成，但系统确保核心线索具有不可逾越的叙事深度距离，玩家必须层层盘剥才能触碰真相。
- **对我项目的启发：** PCG 绝不仅仅是“随机拼装”，必须附带“可验证性验证器（Verifier）”。将形式化验证作为生成管线的 Gatekeeper，才能做真正硬核的生成式游戏。
- **今天是否值得深入研究：** 是
- **建议行动：** 收藏

## 今日模式总结

1. **从“静态推测”转向“拓扑约束与图（Graph & Specs）”：** 无论是 `codegraph` 把代码转为本地 AST 图，`FIG-MAC` 用灵感图做跨域跳跃，还是 `CA-RAG` 用约束控制生成，单纯靠纯文本 Context 的时代正在过去，显式图谱和规格约束是 Agent 高级推理的骨架。
2. **拒绝理想温室，回归物理法则与动态世界：** `Real-Time Reasoning` 剥夺了 LLM 无限思考的时间特权，`Certify What You Plant` 严防游戏系统出现逻辑捷径。好发明的共性在于——**开始主动给 AI 设置严苛的物理、时间与数学边界。**

## 今日可做小实验

### ⏱️ 项目名：PanicBot（惊恐时钟：时间预算感知型 Agent）
**耗时目标：** 1.5 ~ 2 小时

- **输入：**
  1. 环境状态描述（如：“你在一个下沉的船舱里，海水正漫到膝盖，头顶有管道漏电，右边门反锁，左边有通风管道，水里有一把扳手”）。
  2. 动态倒计时限制（比如分别测试：`500ms`、`2000ms`、`10000ms`）。
- **输出：**
  Agent 输出行动指令，以及一条简短的“心智压力/思考过程摘要”。对比不同时间预算下 Agent 的决策风格变化。
- **技术栈：**
  Python + 任何带流式输出或快速响应的 API（如 Claude 3.5 Haiku 或 Ollama 本地模型，配合 `asyncio.wait_for`）。
- **第一步怎么做：**
  1. 写一个异步 Python 脚本，设置一个 `timeout` 参数。
  2. 当 `timeout=0.5s` 时，系统 Prompt 切换为：“你处于极致惊恐状态，只允许激活你的脊髓反射，输出 1 个动词短语”；
  3. 当 `timeout=10s` 时，系统 Prompt 切换为：“你绝对安全，请进行结构化 SWOT 分析并制定三步最优解”。
  4. 体验“时间限制”如何直接转化为一种具有强烈游戏感和人性张力的交互机制。
