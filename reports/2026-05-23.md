## MemOS: 像操作系统一样管理 LLM 长期记忆与技能复用
- 来源：GitHub Trending
- 链接：https://github.com/MemTensor/MemOS
- 一句话解释：一个为 LLM 和 AI Agent 设计的自进化内存操作系统，提供超持久化记忆、混合检索和跨任务技能复用。
- 它为什么重要：现在的 Agent 往往是“健忘”的，每次对话都在重新发明轮子。MemOS 把它做成了 OS 级别的抽象，支持技能复用（Skill Reuse），这意味着 Agent 运行越久，积累的方法论越多，且能省下 35% 的 Token。
- 技术趋势标签：`Agent Memory` `OS-like Agent` `LLM Optimization` `Skill Library`
- 可复用模式：**“Memory-as-an-OS”**（把 Agent 的记忆、工具、技能统一抽象为类似文件系统/内存块的结构，支持动态加载和冷热交换）。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个“永生终端助手”，它会偷偷记录你每次在 Bash 报错时的解决办法并固化为“技能文件”，下次遇到相同报错自动调用，无需重新消耗 API 去思考。
  2. **一个中型项目**：打造一个“数字孪生学徒”，通过挂载你的代码库和设计笔记，自动学习你的编程风格和设计美学。当你开启新项目时，它能以你的习惯自动写出初版 Spec。
  3. **一个艺术/游戏/叙事方向**：**虚拟生态缸（Virtual Terrarium）**。里面的 NPC 具有 MemOS 记忆，它们在虚拟世界里生存、发明工具、并把“如何砍树”或“如何画画”作为“技能文件”在 NPC 之间进行交易、继承和演化。
- 对我项目的启发：直接用来强化你的 Spec-driven 流程。你可以让 Agent 记住你过去所有的设计规范（Specs），新项目启动时自动调取历史最佳实践。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 剧本特工：将电影角色转化为可交互、可调研的 LLM Agents
- 来源：arXiv cs.HC
- 链接：https://arxiv.org/abs/2605.22091
- 一句话解释：该研究通过电影剧本台词，自动构建了 734 个具有特定性格、背景和偏见的电影角色 Agent，并对他们进行社会学问卷调查。
- 它为什么重要：它展示了一种从“静态文本/剧本”到“动态可交互 Agent”的标准化管线。不仅能用来做社会学分析，更是游戏 NPC 生成、互动叙事和虚拟世界构建的终极工具。
- 技术趋势标签：`LLM Agent` `Interactive Narrative` `Character Synthesis` `Social Simulation`
- 可复用模式：**“Script-to-Agent Pipeline”**（提取结构化对话 -> 注入 Agent System Prompt -> 行为/性格对齐 -> 模拟测试）。
- 疯狂发明家灵感：
  1. **一个小实验**：输入一部你最爱的电影剧本，自动提取其中两个配角，让他们在一个局域网聊天室里无休止地争吵，观察是否会产生新的剧情。
  2. **一个中型项目**：“编剧压力测试器”。上传你的游戏或小说大纲，AI 自动将所有角色实例化，让他们在虚拟空间里自由行动 100 轮，生成一份“剧情崩坏与冲突报告”。
  3. **一个艺术/游戏/叙事方向**：一个互动戏剧装置**《AI 罗生门》**。观众给出一个谋杀案设定，三个由经典电影（如《教父》、《低俗小说》）角色性格驱动的 Agent 轮流上台接受观众质询，观众需要找出谁在撒谎。
- 对我项目的启发：完美契合你的游戏系统与叙事系统兴趣。可以用这个管线来为你的 Minecraft 世界快速填充有血有肉、有独特世界观的村民。
- 今天是否值得深入研究：是
- 建议行动：做demo

## AutoRPA: 别再让 Agent 猜了，用“用户演示”直接合成自动化代码
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2605.21082
- 一句话解释：放弃了低效的“观察-思考-行动（ReAct）”循环，AutoRPA 通过记录用户在 GUI 上的单次交互演示，直接合成出可重复执行的自动化脚本。
- 它为什么重要：ReAct 模式极度消耗 Token 且延迟高。AutoRPA 转向了 "Programming by Demonstration (PbD)"。这不仅能极大地加速自动化工作流，还能为“无代码/低代码”创意工具提供全新的交互范式。
- 技术趋势标签：`Programming by Demonstration` `GUI Automation` `Code Synthesis` `Agent Efficiency`
- 可复用模式：**“Demonstrate-then-Synthesize”**（用户操作 -> 捕获 DOM/坐标变化 -> LLM 翻译为标准 Python/Playwright 代码 -> 固化为工具）。
- 疯狂发明家灵感：
  1. **一个小实验**：做一个 Chrome 插件，你手动在网页上点选、复制、粘贴一次，它自动在后台生成一段 Puppeteer 爬虫代码，下次一键运行。
  2. **一个中型项目**：“创意软件宏生成器”。在 Blender 或 Photoshop 里，你做一遍复杂的图层操作，LLM 监听你的操作流并合成一个 Python 插件，让非程序员也能“用嘴和手”开发插件。
  3. **一个艺术/游戏/叙事方向**：**“游戏外挂艺术家”**。玩家在 Minecraft 里手动盖一栋奇形怪状的房子，Agent 捕获这个建造过程，合成一个“无限盖房脚本”，在地图上像孢子一样自我复制和蔓延。
- 对我项目的启发：启发你的 Spec-driven development 流程。你可以通过演示你期望的开发工作流，让 Agent 自动为你生成脚手架和测试脚本，而不是写繁琐的 prompt。
- 今天是否值得深入研究：是
- 建议行动：试用

## COSMO-Agent: 桥接设计与仿真的闭环 3D 建模特工
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2605.20190
- 一句话解释：这是一个将强化学习与工具调用结合的 Agent，能理解 3D 物理仿真反馈，并自动修改 CAD 几何模型以达到最优物理性能。
- 它为什么重要：它打破了“美学设计（CAD）”与“物理世界规律（CAE仿真）”之间的隔阂。对于生成式设计、HCI 以及游戏中的程序化内容生成（PCG）有极大的启发。
- 技术趋势标签：`Generative Design` `CAD/CAE` `Physical-AI` `Closed-loop Optimization`
- 可复用模式：**“Design-Simulate-Refine Loop”**（生成 3D 几何 -> 运行物理/美学评估 -> 提取差异 -> LLM 修改参数 -> 迭代）。
- 疯狂发明家灵感：
  1. **一个小实验**：用 Three.js 写一个极其简易的“造桥模拟器”，Agent 随机生成桥梁，通过简单的重力物理引擎评估，自动修改桥梁网格（Mesh）直到它不会垮塌。
  2. **一个中型项目**：“进化家具设计师”。输入“一把坐着舒服且省材料的椅子”，Agent 自动在 CAD 软件中建模，调用受力分析工具，迭代生成有机、奇特、符合人体工程学的 3D 家具模型。
  3. **一个艺术/游戏/叙事方向**：**动力学雕塑生成器（Kinetic Sculpture Generator）**。在虚拟世界中，Agent 自动设计并组装复杂的齿轮和连杆机构，通过物理引擎测试其运动轨迹，最终生成可以 3D 打印的、具有特定运动美学的动态雕塑。
- 对我项目的启发：非常适合你关注的“世界生成”与“生成式系统”。你可以将这个“闭环优化”机制引入到 Minecraft 的结构生成中，让 Agent 自动设计出既好看又符合红石电路/重力规则的建筑。
- 今天是否值得深入研究：是
- 建议行动：收藏

## Repomix: 把整个代码库打包成一个 AI 极度舒适的单文件
- 来源：GitHub Trending
- 链接：https://github.com/yamadashy/repomix
- 一句话解释：一个能将你整个 GitHub 仓库无损打包成一个带目录结构、适合 LLM（如 Claude、GPT-4）深度阅读的单文本文件的超实用工具。
- 它为什么重要：它是目前最接地气的“Spec-driven”和“LLM 协同开发”辅助工具。大上下文时代（如 Claude 3.5 200k），RAG 有时不如直接把整个 Repo 塞给模型来得精准。Repomix 极大地简化了这一步骤。
- 技术趋势标签：`LLM Developer Tooling` `Context Packaging` `Spec-driven Development`
- 可复用模式：**“Whole-Repo Context Injection”**（代码库 -> 拓扑排序与格式化打包 -> 提示词增强 -> LLM 一气呵成理解全局）。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个一行命令的 CLI，自动把你当前的项目用 repomix 打包，直接通过 API 发给 Claude 询问：“指出我这个项目里最优雅和最垃圾的三个函数，并给出重构方案”。
  2. **一个中型项目**：“逆向工程 spec 生成器”。把任何开源项目的 Repo 用 repomix 打包，让 LLM 逆向推导出一份详尽的、符合你风格的“系统设计说明书（Spec）”，用来克隆或魔改该项目。
  3. **一个艺术/游戏/叙事方向**：**“代码库自画像（Codebase Portrait）”**。将你过去所有的创意编程（Creative Coding）代码库打包，丢给 LLM 深入分析你的编程习惯、偏爱的颜色函数、数学公式，然后生成一幅代表你“编程灵魂”的生成艺术作品。
- 对我项目的启发：立即把它集成到你的日常 AI 开发工作流中。这是你进行 spec-driven development 的大杀器，让 AI 真正拥有全局视野。
- 今天是否值得深入研究：是
- 建议行动：试用

## 今日模式总结

1. **“演示即合成” (Demonstrate-to-Code)**：从 AutoRPA 中看到的趋势。Agent 正在从低效的在线推理（ReAct 边想边做）转向离线的“观察用户演示 -> 一次性合成确定性脚本/工具”模式。这极大地降低了 Token 成本，提升了创意工具的响应速度。
2. **“物理/美学闭环优化” (Closed-loop Physical Simulation)**：从 COSMO-Agent 中看到的趋势。Agent 不再只是生成文字或像素，而是学会了“生成 -> 丢进仿真器/物理引擎测试 -> 根据反馈微调参数”的闭环。这是生成式系统和世界生成的未来。
3. **“代码库冷凝” (Context Condensation)**：从 Repomix 中看到的趋势。面对超大上下文模型，复杂的 RAG 检索正在被“极简、结构化的单文件代码库打包”所取代，这让 Spec-driven 开发中的“全局理解”变得极其简单。

## 今日可做小实验：黑色电影剧本沙盒 (Noir Script Sandbox)

- **项目名**：NoirScriptSandbox
- **输入**：一段经典黑色电影（如《马耳他之鹰》）的剧本片段 + 一个用户设定的冲突（例如：“花瓶被打碎了，但两个人都坚称自己没动”）。
- **输出**：一个在终端实时运行的、由两个 Agent 扮演的角色对话。它们必须严格使用剧本中角色的口吻、特定词汇（Vocabulary）和句式来围绕冲突展开争论，并在 10 轮对话内由一个“导演 Agent”给出剧情反转结局。
- **技术栈**：Python + `repomix`（用来打包你的 Prompt 模板和代码结构）+ `openai` API (或任意 local LLM) + `rich` (用于终端彩色角色对话排版)。
- **第一步怎么做**：
  1. 找一段公开的电影剧本，手动复制 20 行该角色的台词作为 Few-shot 样本。
  2. 写一个简单的 Python 脚本，定义两个 Character Agent 的 System Prompt，将 Few-shot 样本塞进去，要求它们“严格模仿此文风，不得出戏”。
  3. 用一个简单的 `while` 循环让两个 Agent 交替生成对话，并将对方的上一句作为输入。运行它，看看它们是否能维持角色设定。
