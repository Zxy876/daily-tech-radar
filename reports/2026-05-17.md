## 1. PREPING: 无任务背景下的智能体记忆构建
- 来源：arXiv cs.AI (Candidate 8)
- 链接：https://arxiv.org/abs/2605.13880
- 一句话解释：让 Agent 在正式干活前，先像个好奇的孩子一样在环境里“瞎逛”并建立记忆，解决冷启动问题。
- 它为什么重要：传统的 Agent 记忆要么是预设的，要么是干活时产生的。PREPING 提出一种“先探索、再工作”的范式，非常适合开放世界（如 Minecraft）。
- 技术趋势标签：#AgentMemory #ColdStart #ProceduralKnowledge
- 可复用模式：**“先导探索期（Pre-task Exploration）”**。在正式指令下达前，先运行一个低成本的观察循环。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个脚本，让 LLM 先读取你整个项目的目录树和 README，但不给任务，让它自己总结“这个项目的脾气”，然后再开始写代码。
  2. **一个中型项目**：Minecraft 考古学家。Agent 在服务器里自动挂机巡逻，记录地形和建筑变化，当你上线问“最近谁在我家门口放了基岩”时，它能瞬间回答。
  3. **一个艺术/游戏/叙事方向**：一个“数字幽灵”。它在你的电脑后台静默观察你的文件修改习惯，几个月后，它能以你的逻辑风格自动整理桌面。
- 对我项目的启发：在 Spec-driven 开发中，可以先让 Agent “阅读”所有 Spec 而不执行，建立一个全局状态图，再开始生成。
- 今天是否值得深入研究：是
- 建议行动：试用（在你的自动化脚本中加入一个“预观察”环节）

## 2. LOOP Skill Engine: 一次性录制与确定性重放
- 来源：arXiv cs.AI (Candidate 14)
- 链接：https://arxiv.org/abs/2605.14237
- 一句话解释：通过“一次录制”将 LLM 复杂的工具调用流程固化为“确定性技能”，成功率提升至 99% 且 Token 消耗骤减。
- 它为什么重要：Agent 最烦人的就是不确定性。这个技术把“灵动的 AI”变成了“可靠的宏（Macro）”。
- 技术趋势标签：#DeterministicAgent #Efficiency #SkillRegistry
- 可复用模式：**“演示即编程（Programming by Demonstration）”**。
- 疯狂发明家灵感：
  1. **一个小实验**：录制一段你处理图片、上传、发推的流程，让 Agent 提取其中的 API 调用链，生成一个固化的 Python 脚本。
  2. **一个中型项目**：一个“设计工具宏生成器”。在 Figma 里做一遍复杂操作，Agent 自动将其转化为一个可重复利用的插件代码。
  3. **一个艺术/游戏/叙事方向**：AI 编舞师。录制一段动作捕捉数据，Agent 学习其风格并固化为一种“舞步技能”，可以在不同的 3D 角色上完美重放。
- 对我项目的启发：解决自动化系统中的“幻觉”问题。一旦 Agent 探索出一条正确路径，立即将其“硬化”为代码，而不是每次都让 LLM 重新推理。
- 今天是否值得深入研究：是
- 建议行动：做 demo（尝试写一个能将 LLM 思考过程转化为固定函数的 Wrapper）

## 3. Steering Vectors: LLM 转向控制变得有趣了
- 来源：Hacker News / Sean Goedecke (Candidate 18)
- 链接：https://www.seangoedecke.com/steering-vectors/
- 一句话解释：不再通过 Prompt 苦口婆心地劝 AI，而是通过“转向向量”直接修改模型内部的激活状态，强制它变得更诚实、更幽灵或更具艺术感。
- 它为什么重要：这是 HCI 的新前沿。我们不再是跟 AI 对话，而是像调色一样调节它的“灵魂参数”。
- 技术趋势标签：#ModelSteering #HCI #Interpretability
- 可复用模式：**“特征注入（Feature Injection）”**。
- 疯狂发明家灵感：
  1. **一个小实验**：使用 DeepSeek-V4-Flash 配合转向向量，做一个“性格滑块”。滑动条左边是“严谨程序员”，右边是“疯狂诗人”。
  2. **一个中型项目**：一个基于情感向量的实时写作环境。当你写悲剧时，编辑器的 AI 建议会自动变得忧郁，因为你注入了“悲伤向量”。
  3. **一个艺术/游戏/叙事方向**：动态性格的 NPC。NPC 的性格不再是 Prompt 里的几句话，而是根据游戏剧情实时波动的向量权重。
- 对我项目的启发：对于 Creative Coding 极其有用。你可以直接操控生成风格的“浓度”，而不是反复修改 Prompt。
- 今天是否值得深入研究：是
- 建议行动：收藏（这代表了下一代 AI 交互的范式转变）

## 4. SimPersona: 从点击流学习离散用户画像
- 来源：arXiv cs.AI (Candidate 7)
- 链接：https://arxiv.org/abs/2605.14205
- 一句话解释：通过原始行为数据（如点击流）自动学习并生成真实的、具有差异性的 Agent 画像，而不是靠人工写 Prompt。
- 它为什么重要：解决了 Agent 行为“平均化”的问题。它能让 Agent 模拟出“真实的人类多样性”。
- 技术趋势标签：#PersonaGeneration #BehavioralModeling #GenerativeSystems
- 可复用模式：**“行为到画像的逆向工程”**。
- 疯狂发明家灵感：
  1. **一个小实验**：把你最近一周的浏览器历史记录（脱敏）喂给 LLM，让它生成一个“镜像自我”的 Agent。
  2. **一个中型项目**：一个“多重人格隔离墙”。为你的不同社交账号（如 GitHub, X, 小红书）生成完全基于你过去行为的自动回复 Agent。
  3. **一个艺术/游戏/叙事方向**：数字孪生小镇。提取一个社区所有用户的发帖行为，生成一个由这些画像组成的虚拟小镇，观察他们如何交互。
- 对我项目的启发：在构建游戏系统或叙事系统时，可以用真实数据来驱动 NPC 的独特性，而不是手动设定。
- 今天是否值得深入研究：否（原理重要，但实现较重）
- 建议行动：忽略（先记住这个模式即可）

## 5. Grounded Continuation: 对话的运行时验证器
- 来源：arXiv cs.AI (Candidate 12)
- 链接：https://arxiv.org/abs/2605.14175
- 一句话解释：通过维护一个显式的依赖图，防止 LLM 在长对话中由于忘记前提而产生“逻辑断层”。
- 它为什么重要：长文本 Agent 的致命伤是“逻辑漂移”。这个项目给对话装了一个“逻辑警察”。
- 技术趋势标签：#Verification #DependencyGraph #LongContext
- 可复用模式：**“逻辑依赖图（Logic Dependency Graph）”**。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个简单的修饰器，每当 Agent 做出决定，都要求它引用之前的某条 Spec 编号。如果引用不上，则报错。
  2. **一个中型项目**：一个“永不吃书”的协作小说工具。它会自动提取已有的设定（如：主角对花生过敏），并在新章节出现矛盾时（如：主角在吃花生）自动拦截。
  3. **一个艺术/游戏/叙事方向**：一个基于逻辑的解谜游戏。Agent 是嫌疑人，玩家必须通过长对话诱导它产生逻辑矛盾，验证器会自动高亮这些矛盾。
- 对我项目的启发：非常适合你的 Spec-driven development。Spec 就是依赖图的根节点，所有生成的代码必须能溯源到 Spec。
- 今天是否值得深入研究：是
- 建议行动：做 demo（尝试为你的 Agent 增加一个“逻辑溯源”层）

## 今日模式总结
1. **硬化（Hardening）**：将模糊的 AI 推理流程转化为确定性的录制脚本（LOOP）。
2. **预热（Pre-warming）**：在任务开始前通过无目的探索构建环境记忆（PREPING）。
3. **注入（Injecting）**：跳过语言层，直接通过向量改变模型内在行为倾向（Steering Vectors）。

## 今日可做小实验：【The Ghost Recorder / 幽灵录音机】
- **项目名**：Ghost-CLI-Recorder
- **输入**：你在终端执行的一串复杂命令（如：配置环境、处理图片、部署网页）。
- **输出**：一个经过 LLM 优化、带错误处理、且可重复执行的 `.sh` 脚本或 Python 脚本。
- **技术栈**：Python, OpenAI/DeepSeek API, `history` 命令。
- **第一步怎么做**：
  1. 运行 `history | tail -n 20 > history.txt`。
  2. 写一个 Prompt：“你是一个高级运维专家。以下是我最近的操作记录，请识别我的意图，剔除掉错误的尝试，并将其转化为一个确定性的、可重用的 Bash 脚本，要求包含基本的成功检查。”
  3. 运行这个 Prompt 并保存输出。
