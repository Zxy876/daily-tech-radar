## 1. Show HN: Lathe – 拒绝“一键生成”，用 LLM 重塑“肌肉记忆”的学习型 HCI 工具
- **来源**：Hacker News Best
- **链接**：https://github.com/devenjarvis/lathe
- **一句话解释**：一个让你通过“手打代码”来学习新领域的 CLI 工具，LLM 生成步骤，你必须亲自敲入代码来通过本地 UI 的校验。
- **它为什么重要**：它逆向了当前“AI 帮我写完一切”的懒惰趋势。在 HCI 设计中，我们常常忽略了“身体知觉”和“肌肉记忆”对学习的重要性。Lathe 探索了 AI 时代人类如何保留理解力。
- **技术趋势标签**：HCI, AI Co-learning, Developer Experience, Creative Tool
- **可复用模式**：**逆向生成模式**（AI 充当考官与物理校验器，人类充当物理执行者，通过强制输入形成反馈闭环）。
- **疯狂发明家灵感**：
  1. **一个小实验**：一个 3D 建模/Blender 快捷键“肌肉记忆”训练器。LLM 描述一个复杂的几何变换，你必须在网页端按下正确的快捷键组合，按错会触发屏幕抖动和声音惩罚。
  2. **一个中型项目**：一款关卡生成式“代码格斗”游戏。LLM 生成算法谜题，玩家必须手写代码，系统会实时渲染出两个角色的对决画面，手写代码的效率决定了角色的攻击力。
  3. **一个艺术/游戏/叙事方向**：一个互动叙事装置：玩家必须“手抄”LLM 实时生成的、由奇怪 Unicode 符号组成的“禁忌魔法咒语”（有倒计时和错别字惩罚），以此来阻止虚拟世界在屏幕上坍塌。
- **对我项目的启发**：在设计 Creative Coding 工具时，不要总想着“一键生成”，设计“人机合奏/强迫人类参与”的机制反而能创造极佳的体验。
- **今天是否值得深入研究**：是
- **建议行动**：试用并阅读其 Go 源码中的 CLI 交互逻辑。

## 2. Adversarial Co-Thinking: 逆向对抗共思：让三大主流 LLM 在你写论文/剧本时实时互撕
- **来源**：arXiv cs.HC
- **链接**：https://arxiv.org/abs/2606.06702
- **一句话解释**：作者通过将 Claude、ChatGPT 和 Gemini 深度嵌入起草学术论文的全过程，让它们并行对抗、冲突、对齐，从而完成了一次高强度的多工具 HCI 写作实验。
- **它为什么重要**：打破了“单一 Chat 窗口”或“单向 Agent 链”的局限。它证明了：**最好的灵感产生于冲突，而非顺从**。多模型博弈能极大地榨取 LLM 的隐性知识。
- **技术趋势标签**：HCI, Multi-LLM Workflow, Creative Writing, Agent Interaction
- **可复用模式**：**异构模型对抗三角测量（Triangulation）模式**。
- **疯狂发明家灵感**：
  1. **一个小实验**：一个 Obsidian 插件（或 Python 脚本）。你输入一行灵感，Claude 负责冷酷挑刺，GPT 负责乐观扩写，Gemini 负责寻找事实漏洞，三者在你的侧边栏实时“吵架”，逼你产出更完善的想法。
  2. **一个中型项目**：多角色剧本协同创作画布。玩家在画布上设定故事大纲，三个性格迥异的模型（莎士比亚风、赛博朋克风、学术风）各自控制一个角色，在画布上争夺叙事主导权，玩家则作为“造物主”随时插手干预。
  3. **一个艺术/游戏/叙事方向**：艺术装置《巴别塔辩论赛》：三个大屏幕代表三个不同立场的 AI，就观众实时输入的社会议题进行永无止境的辩论。它们会互相引用对方的漏洞，并在后台不断更新自己的“世界观底牌”。
- **对我项目的启发**：非常适合启发你的 Agent workflow。在你的系统里，不要只用一个 Agent 顺从地执行命令，引入一个“杠精 Agent”或“红队 Agent”来对抗，能让生成结果的质量呈指数级上升。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 3. Lean4Agent: 给 AI Agent 的工作流和轨迹装上“形式化数学证明”
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.06523
- **一句话解释**：引入数学定理证明器 Lean 4，对 LLM Agent 的多步工作流和执行轨迹进行严格的形式化建模与验证。
- **它为什么重要**：这是 **Spec-driven development 的终极硬核形态**。Agent 不再是靠玄学 Prompt 运行，而是其每一步状态转移都有数学层面的安全和正确性证明。
- **技术趋势标签**：Spec-driven, Formal Verification, Agent Workflow, Lean 4
- **可复用模式**：**形式化契约守卫（Formal Contract Guard）模式**。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 Python 装饰器。Agent 每次调用外部 Tool 前后，必须通过一个轻量级的 Z3 求解器（或 Pydantic 状态验证），如果不满足前置/后置条件，强制回滚并让 Agent 自我修正。
  2. **一个中型项目**：“绝对不穿模”的 Minecraft 建造 Agent。用形式化逻辑定义建筑规则（如重力、连通性、红石电路逻辑），Agent 规划的每一步蓝图都必须通过 Lean 4 验证，确保在游戏里 100% 可运行且不产生逻辑死锁。
  3. **一个艺术/游戏/叙事方向**：一个“规则类怪谈”解谜游戏。游戏世界的物理法则由形式化逻辑定义，玩家扮演程序员，必须编写出绝对没有逻辑漏洞的指令（Spec）来命令 Agent 逃出密室。任何逻辑漏洞都会被“怪物”（验证器发现的 Bug）实体化并杀掉 Agent。
- **对我项目的启发**：将形式化方法与 Agent 结合。在设计自动化系统时，用 Spec（如 JSON Schema 或契约逻辑）作为 Agent 的硬性边界，能做出极其鲁棒的工具。
- **今天是否值得深入研究**：是
- **建议行动**：试用并了解 Lean 4 的基本概念。

## 4. Workflow-to-Skill: 从混乱的 Agent 运行日志中自动提炼并固化“技能”
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.06893
- **一句话解释**：通过将 Agent 混乱的交互轨迹、工具链日志、执行 Trace 分解，自动重构并固化出高质量、可复用的“技能（Skills）”。
- **它为什么重要**：解决了 Agent 系统的“冷启动”和“经验积累”问题。Agent 在环境里探索久了，能自动把成功经验写成“代码库/工具箱”，实现自我进化。
- **技术趋势标签**：Agent Workflow, Skill Discovery, Self-Improvement, RAG
- **可复用模式**：**轨迹到技能固化（Trace-to-Skill Distillation）模式**。
- **疯狂发明家灵感**：
  1. **一个小实验**：一个 Minecraft 挖矿 Agent 的日志分析器。分析它 100 次动作日志，自动提取出它在“遇到岩浆时的成功避险操作”，并将其固化为一个名为 `avoid_lava` 的 Python 函数。
  2. **一个中型项目**：自动化 UI 测试 Agent 的“进化引擎”。Agent 在多次乱点网页后，系统自动提取其成功的交互流，提炼成“登录”、“加购物车”的标准化可复用工作流（Workflow DAG）。
  3. **一个艺术/游戏/叙事方向**：虚拟生态系统《算法达尔文》。在这个世界里，虚拟生物（LLM 驱动）的行动轨迹会被系统记录。生存时间最长的生物，其行为轨迹会被固化为“基因（Skill API）”，传递给下一代生物直接调用。
- **对我项目的启发**：在游戏系统和世界生成中，不要硬编码 NPC 的能力。让 NPC 在生存中“写出自己的技能书”，世界会变得无比生动。
- **今天是否值得深入研究**：否（先收藏思想）
- **建议行动**：收藏

## 5. Declarative Skills: 用自然语言“声明式 Skill 文件”优雅编排 Agent
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.06923
- **一句话解释**：提出一种声明式 Agent 编排范式，只需在 System Prompt 中动态追加“自然语言技能文件（Skill Files）”，就能实现高效的工具调用和工作流管理。
- **它为什么重要**：告别繁琐的硬编码 Tool Calling。让 Agent 的能力像装插件一样，通过读取 Markdown 格式的声明文件动态挂载，实现真正的 Spec-driven。
- **技术趋势标签**：Spec-driven, Declarative Programming, Agent Orchestration
- **可复用模式**：**声明式 Prompt 挂载（Declarative Prompt Attachment）**。
- **疯狂发明家灵感**：
  1. **一个小实验**：编写一个动态 Skill 挂载器。根据用户输入的意图，从技能库（一堆 Markdown 文件）中检索对应的技能说明，实时热插拔到 System Prompt 中，让 Agent 瞬间获得新能力。
  2. **一个中型项目**：模块化卡牌游戏引擎。每张卡牌都是一个“声明式技能文件”（Markdown），Agent 读到什么卡牌，就能瞬间学会该卡牌的复杂效果和博弈策略，无需重写底层代码。
  3. **一个艺术/游戏/叙事方向**：互动戏剧《人格面具》。舞台上的 AI 演员通过实时读取、替换“性格声明文件”（如野心、恐惧、嫉妒），瞬间切换其台词风格和行为动机，观众可以通过修改这些 Markdown 文件来操纵剧情。
- **对我项目的启发**：这为你的 Spec-driven 框架提供了一条极简路径。把一切 Tool 描述和限制写成声明式的 Spec Markdown，动态喂给 Agent，比复杂的 Tool Calling 更优雅。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 今日模式总结

1. **对抗性多模型共思 (Adversarial Triangulation)**：不再信任单一模型的输出，通过异构模型（如 Claude 偏向逻辑、GPT 偏向发散、Gemini 偏向事实）的实时冲突和博弈，逼出高保真、有深度的新内容。
2. **形式化契约约束 (Formal & Declarative Specification)**：给 Agent 的行为边界套上硬性枷锁。要么用数学逻辑（Lean 4/Z3）验证其轨迹，要么用声明式文件（Markdown Spec）动态约束其能力。
3. **轨迹到技能的演化 (Trace-to-Skill Evolution)**：Agent 系统的闭环自进化。Agent 的无序探索（Trace）不应被丢弃，而应被重构为可复用的结构化“技能包（Skills）”。

## 今日可做小实验：DebateWriter (杠精写作室)

这是一个 2 小时内可以跑通的小实验，融合了“多模型对抗”与“声明式规范”，用来帮你打磨任何项目灵感。

- **项目名**：DebateWriter
- **输入**：你的一句话粗糙灵感（例如：“我想做一个用红石电路模拟生态演化的 Minecraft 地图”）。
- **输出**：一个经过三方辩论、挑刺、修正后，最终生成的**高质量项目 Spec Markdown 文档**。
- **技术栈**：Python, `litellm` (用于轻松调用不同大模型), `rich` (用于终端炫酷的彩色辩论实时展示)。
- **第一步怎么做**：
  1. 安装依赖：`pip install litellm rich` 并配置好你的 Claude 和 GPT-4 的 API Key。
  2. 编写脚本，初始化三个角色：
     - **角色 A (Claude - 极端严谨的架构师)**：负责把你的灵感扩写成详细技术 Spec，并列出潜在技术难点。
     - **角色 B (GPT-4 - 杠精评审员)**：专门寻找 A 的方案中的逻辑漏洞、实现难度过高的地方，进行无情批判。
     - **角色 C (Gemini/或另一个 GPT 实例 - 调解员兼文档师)**：观察 A 和 B 的争吵，提炼出最可行的折中方案，并输出最终的 Markdown。
  3. 让 A 和 B 轮流迭代 2 个回合，最后由 C 统一收尾，将终端里的辩论过程用 `rich` 渲染成彩色对话框，爽感拉满！
