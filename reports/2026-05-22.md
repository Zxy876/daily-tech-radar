## 1. [Formal Skill: Programmable Runtime Skills for LLM Agents]
- **来源**：arXiv cs.AI (2026.05)
- **链接**：https://arxiv.org/abs/2605.19604
- **一句话解释**：把 AI Agent 的“技能”从模糊的自然语言 Prompt，编译成可执行、有状态、强约束的程序运行时代码（如 MCP 服务或结构化 API）。
- **它为什么重要**：现在的 Agent 动不动就因为 Prompt 太长而“迷失”，或者调用 Tool 时幻觉。这项研究表明，未来的 Agent 技能不应该是“写在 Prompt 里的说明书”，而应该是“动态编译的代码微服务”。这与 Spec-driven development（规约驱动开发）完美契合。
- **技术趋势标签**：#AgenticWorkflow #SpecDriven #LLMToolchain #MCP
- **可复用模式**：**“Prompt-to-Runtime-Skill”编译模式**。不直接让 LLM 跑长 Prompt，而是让它先将意图编译成一个带有输入输出 Schema 校验的独立 JS/Python 运行块。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 CLI 工具，输入一句“帮我爬取并总结这个网页”，它不直接去爬，而是实时生成一个包含 `Playwright` 节点和 `Zod` 模式校验的临时可执行 JS 脚本，运行并返回结果。
  2. **一个中型项目**：**Minecraft 技能编译器**。玩家用自然语言说“去帮我砍树，如果天黑了就躲进地洞里”，Agent 会把这个策略编译成一个状态机代码（基于 Mineflayer），然后挂载到 Agent 运行时中，实现 100% 稳定执行。
  3. **一个艺术/游戏/叙事方向**：**“代码木偶”互动剧场**。观众通过自然语言命令演员（Agent），系统将命令编译成严格的行为树和情感状态机，演员在舞台上既有 LLM 的即兴台词，又绝对不会做出越过舞台边界的穿模行为。
- **对我项目的启发**：在设计 Agent 流程时，不要试图用长 Prompt 塞满 Context，而要设计一套“技能卡牌”（Code-based Skills），让 Agent 动态组合并执行它们。
- **今天是否值得深入研究**：是
- **建议行动**：试用（尝试用 MCP 协议手写一个可动态加载的 Skill Server）

## 2. [PRISM: A Benchmark for Programmatic Spatial-Temporal Reasoning]
- **来源**：arXiv cs.AI (2026.05)
- **链接**：https://arxiv.org/abs/2605.19382
- **一句话解释**：证明了“通过代码（如 SVG, Canvas, P5.js）生成动画和视频”比“用扩散模型直接生成像素”在几何精度和时间连贯性上强得多，并为此建立了一个庞大的代码生成基准。
- **它为什么重要**：对于创意编程（Creative Coding）和设计背景的你，这是巨大的福音！像素生成是不可控的黑盒，而**代码生成（Programmatic Video）**是可交互、可无限放大、100% 可编辑的。
- **技术趋势标签**：#CreativeCoding #GenerativeSystems #SpecDriven #HCI
- **可复用模式**：**“语义-几何代码”映射**。将时间、空间和物理约束，翻译成确定性的数学公式和 Canvas 渲染循环。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一个“文字生成 P5.js 物理动画”的沙盒。输入“一个红球从高处落下，砸中蓝色斜板，最后弹进绿色垃圾桶”，LLM 必须生成纯 P5.js 物理模拟代码并在网页中即时渲染。
  2. **一个中型项目**：**Spec-to-UI-Motion 编译器**。UI 设计师用自然语言描述微交互（例如：“卡片点击后像果冻一样Q弹展开，3D 翻转，背景变暗”），系统直接生成无 Bug 的 React Spring 或 Framer Motion 代码，并提供可视化调节滑块。
  3. **一个艺术/游戏/叙事方向**：**代码驱动的无限生成漫画**。故事脚本动态产生，但分镜（Layout）、角色剪影动作、速度线全部由 SVG 代码实时计算生成，保证每一帧都具有完美的几何美感且绝对不穿模。
- **对我项目的启发**：多模态不等于“像素”。在做游戏和视觉生成时，尝试让 LLM 充当“创意程序员”，生成 P5.js/Three.js 代码，而不是去调 Stable Diffusion 的 API。
- **今天是否值得深入研究**：是（非常适合你的跨学科背景）
- **建议行动**：做 demo

## 3. [Art Card Game (ACG): Embedding Illustration in Gameplay to Mitigate Artist Self-Criticism]
- **来源**：arXiv cs.HC (2026.05)
- **链接**：https://arxiv.org/abs/2605.20465
- **一句话解释**：设计了一款嵌入到数字绘画工作流中的卡牌游戏，通过游戏化的“荒谬约束”来帮助插画师克服严苛的自我审判（Self-Criticism）和创作瓶颈。
- **它为什么重要**：它展示了**如何用游戏系统（Game Systems）去干预人类的心理和工作流**。它不是一个枯燥的“心理健康 App”，而是直接寄生在你的创作工具（如 Photoshop/Figma）里，用“限制”来解放“创造力”。
- **技术趋势标签**：#CreativeTool #GameSystems #HCI #ArtTech
- **可复用模式**：**“约束即解药”（Constraint-based Gamification）**。通过引入随机的、无厘头的规则，降低创作者的期望值，从而消除完美主义带来的焦虑。
- **疯狂发明家灵感**：
  1. **一个小实验**：**“代码草稿轮盘” (Code-Draft-Roulette)**。一个 VS Code 插件，当你写代码卡住或焦虑时启动。它会给你抽一张卡：“接下来的 5 分钟，不能写任何 `if` 语句”或“用写诗的格式写注释”。逼迫你跳出思维定势。
  2. **一个中型项目**：**Rogue-lite 画板**。一个 Web 绘画应用，每当你画了 50 笔，系统就会像《杀戮尖塔》一样弹出一组随机卡牌（例如：“接下来的 3 分钟只能用互补色”、“用非惯用手画”），完成这些挑战可以获得“精力值”来解锁新的 AI 辅助工具。
  3. **一个艺术/游戏/叙事方向**：**“故障美学协同创作”游戏**。双人联机，一人负责画，一人负责用卡牌给对方制造“善意的麻烦”（比如“把画布旋转 90 度画 1 分钟”），AI 在后台根据两人的互动实时生成一个荒诞的叙事背景。
- **对我项目的启发**：好工具不一定要“让一切变得更容易”。有时候，设计精妙的“阻碍”和“游戏化约束”反而能带给用户极大的心流体验。
- **今天是否值得深入研究**：是
- **建议行动**：收藏（作为你 HCI 或游戏设计项目的灵感库）

## 4. [Progressive Autonomy as Preference Learning: A Formalization of Trust Calibration for Agentic Tool Use]
- **来源**：arXiv cs.AI (2026.05)
- **链接**：https://arxiv.org/abs/2605.19151
- **一句话解释**：利用高斯过程（Gaussian Process）算法，让 AI 学习用户在不同场景下的“信任边界”，从而动态决定：这个操作是直接自动执行，还是停下来弹窗让用户手动确认。
- **它为什么重要**：现在的 AI 自动化非常极端：要么傻傻地每一步都问你（烦死人），要么完全黑盒运行（吓死人）。**渐进式自主（Progressive Autonomy）**是人机交互（HCI）中极其高级且必须解决的课题。
- **技术趋势标签**：#HCI #AgenticWorkflow #Automation #TrustCalibration
- **可复用模式**：**“信任度动态门控”（Dynamic HITL Gatekeeper）**。根据用户历史的“批准/拒绝”行为，计算一个置信区间，只有当 AI 动作的风险超出这个区间时才触发 Human-in-the-loop。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“智能文件整理 Agent”。前 10 次移动文件时，它会弹窗问你“确定要移动这个吗？”。如果你都同意了，它会逐渐减少弹窗频率，但如果遇到一个命名奇怪的文件（高不确定性），它会再次弹窗。
  2. **一个中型项目**：**“Drift-Pilot” 规约导航员**。一个 spec-driven 编程助手。它在重构无害的辅助函数时完全自主运行并静默 Commit，但在修改核心 API 或涉及数据库迁移时，会自动暂停，并拉起一个精美的交互式 Diff 界面请求你签字。
  3. **一个艺术/游戏/叙事方向**：**“默契度”爵士乐即兴 Agent**。一个虚拟键盘手 Agent 陪你弹琴。刚开始它弹得非常保守，每走一步和弦都会“看着你”（UI 视觉暗示提示等待）；随着你弹奏的合流，它通过 Preference Learning 发现你接受它的离调尝试，于是它开始变得越来越狂野和自主。
- **对我项目的启发**：在设计自动化工具或 Drift 流程时，加入一个“信任度仪表盘”，让用户能肉眼看到 Agent 的自主度是如何随着每一次交互而增长的。
- **今天是否值得深入研究**：是
- **建议行动**：做 demo

## 今日模式总结

1. **规约代替像素（Spec-over-Pixel）**：创意生成领域正在从“生成不可控的图片/视频”转向“生成可精确控制、可编程的几何与物理代码（P5.js, SVG）”。
2. **信任弹性化（Elastic Trust）**：人机协同（HCI）正在告别死板的“每步确认”，通过 Preference Learning 动态滑动信任边界，实现“渐进式自动化”。
3. **工作流内疗愈（In-Workflow Therapy）**：工具设计的新范式——不再把“效率”作为唯一指标，而是将游戏化约束嵌入流程，对抗创作者的焦虑与自我怀疑。

## 今日可做小实验：PhysiCode 🎨

我们将结合 **PRISM（代码生成物理动画）** 和 **Spec-driven** 的理念，在 2 小时内做一个超酷的可视化小实验！

- **项目名**：PhysiCode (物理规约动画生成器)
- **输入**：一段简短的物理场景描述（例如：“一个重力球掉下来，砸在一个跷跷板上，把另一端的方块弹飞”）
- **输出**：一个拆分左右半屏的网页。左边是生成的 P5.js 代码，右边是实时运行、可交互的 P5.js Canvas 物理动画，并且带有一个“重新微调”的输入框。
- **技术栈**：
  - 前端：单文件 HTML + Tailwind CSS + CDN 引入 P5.js
  - API：Claude-3.5-Sonnet / GPT-4o (用 SDK 或 Edge Function 呼叫)
  - 核心机制：用 HTML `<iframe>` 动态装载并运行生成的 P5.js 代码，实现沙盒隔离。

### 第一步怎么做：
1. **创建基础 HTML**：写一个简单的双栏布局，左边放一个 `<textarea>` 显示代码，右边放一个 `<iframe>` 用于渲染。
2. **设计 System Prompt**：
   ```text
   你是一个精通 P5.js 和物理模拟的创意编程大师。
   请根据用户的描述，生成一段完整的、无 Bug 的 P5.js 代码。
   约束：
   - 必须包含 setup() 和 draw()。
   - 必须使用简单的物理公式（重力、碰撞、反弹）。
   - 必须支持交互（例如：点击画布可以重新生成小球）。
   - 只输出代码，不要输出任何 Markdown 标记（如 ```javascript ）。
   ```
3. **编写 JS 胶水代码**：
   - 写一个函数 `updateSandbox(code)`，将 LLM 返回的代码组装进一个包含 `<script src="https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.4.0/p5.js"></script>` 的 HTML 字符串中。
   - 将该字符串转换为 Blob URL，并赋值给 `iframe.src`。
4. **测试**：输入“一个带引力的星球，吸引周围漂浮的尘埃”，看看你的物理宇宙是否在一秒内运转起来！
