## 1. MathVis: Can AI Reason through Drawing?
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2610.12954
- **一句话解释**：让模型在解题时“自己画草图（TikZ/SVG）来辅助逻辑推理”，把视觉生成变成了思维链（Chain-of-Thought）的一部分。
- **它为什么重要**：传统的 LLM 推理只停留在 Token 文本。这个项目将可执行代码（SVG/TikZ）作为模型“思考”的中间表示（Intermediate Representation），实现了真正的**“视觉-符号双向推理”**。对 Creative Coding 极其友好。
- **技术趋势标签**：#CreativeCoding #VisualReasoning #SVG #LLM-IR
- **可复用模式**：`Prompt -> 生成可渲染矢量代码(SVG) -> 渲染/解析度量 -> 基于图形反馈做下一步决策`。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一个“自我纠偏的几何生成器”——让 LLM 写 p5.js/SVG 代码生成复杂图形，同时让视觉模型（如 GPT-4o）给坐标与构图打分，LLM 根据视觉反馈修正代码。
  2. **一个中型项目**：**Spec-to-Diagram 游戏关卡原型机**：输入游戏规则文本，Agent 自动输出带拓扑结构和路线标注的 SVG 地图，并验证路径连通性。
  3. **一个艺术/游戏/叙事方向**：**“画出心智的解谜游戏”**：玩家用自然语言提出难题，NPC 必须在游戏内的黑板上实时绘制几何符号图谱来推演答案，玩家可以通过擦改黑板上的图形来干扰 NPC 的决策。
- **对我项目的启发**：在做 procedural generation 或世界生成时，不要直接生成最终资产，先让 Agent 生成轻量级的矢量骨架（SVG/Graph），作为 spec-driven 的中间视觉蓝图。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 2. SpireBench: Evaluating Long-Horizon Strategic Play of Agentic Models with Slay the Spire
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2610.12596
- **一句话解释**：用商业卡牌肉鸽《杀戮尖塔》作为基准，测试 Agent 在随机性、长程规划与组合爆炸环境下的策略决策能力。
- **它为什么重要**：大多数 Agent 只能处理 3-5 步的即时交互。《杀戮尖塔》融合了“宏观路线规划（Metagame）”、“状态管理（HP/金币/遗物）”与“微观战斗计算”。它是研究**游戏系统自动化、动态 NPC 与平衡性模拟**的绝佳框架。
- **技术趋势标签**：#GameAI #Roguelike #LongHorizon #AgentStrategy
- **可复用模式**：`状态外置结构化 -> 层次化决策（宏观构筑 vs 微观行动）-> 价值函数剪枝`。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个极简的命令行回合制卡牌 demo（3张牌、一个敌人），用小型本地 LLM 做策略 Agent，记录其在状态转移时的长远推理链条。
  2. **一个中型项目**：**自运行游戏数值平衡分析器**：把你的卡牌或 RPG 游戏规则写成 Spec，跑 100 个轻量 Agent 进行 Monte-Carlo 式的多局对战，自动找出“破坏平衡的超模套路”并输出平衡性报告。
  3. **一个艺术/游戏/叙事方向**：**“自言自语的流放者”**：一个《杀戮尖塔》式的地牢游戏，NPC Agent 的卡组代表其潜意识与创伤。Agent 边打牌边根据局势生成叙事独白，随着血量降低，其独白和决策会呈现出精神崩溃状态。
- **对我项目的启发**：Minecraft 或大型开放世界系统的 Agent 必须分层：长程决策（建造大城堡、探索深渊）不能和即时决策（砍这棵树、躲这只僵尸）混在同一个 Prompt 上下文里。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 3. EvoBelief: Falsifiable World Models for Self-Improving LLM Agents
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2610.12789
- **一句话解释**：让 Agent 为环境维护一套“可证伪的信念世界模型”，并在交互中根据现实反馈不断动态修改这些物理/逻辑假设。
- **它为什么重要**：过去的 Agent 失败通常只会“反思自己的 prompt”，而这个框架让 Agent **“反思它对环境规律的理解”**（如：“我原本以为水能灭掉所有的火，但蓝色的火不行”）。这是打造真正适应性游戏 NPC 和自主物理环境探索者的核心飞跃。
- **技术趋势标签**：#WorldModel #EpistemicAgent #SelfEvolution #ProceduralSimulation
- **可复用模式**：`信念列表(Hypotheses) -> 采取行动(Experiment) -> 收集反馈(Observation) -> 修正/证伪信念(Update World Model)`。
- **疯狂发明家灵感**：
  1. **一个小实验**：给 Agent 一套“错误的物理规则”（如：在这个房间里重力是向上的），让它通过调用 Python 物理模拟环境自行纠正出真实规则并打印演化日志。
  2. **一个中型项目**：**Minecraft 盲盒环境探索者**：在一个装满未知 Mod 机制的 MC 房间里（比如特定方块踩了会中毒、某些方块必须合成），Agent 自动提出科学假说并进行对照实验，最终生成一份完整的“生存指南手册”。
  3. **一个艺术/游戏/叙事方向**：**“认知失调的侦探”叙事交互**：玩家扮演犯人，通过伪造案发现场的物理痕迹，误导侦探 Agent 的“世界信念模型”，观察 Agent 在坚信错误规则下推理出的荒诞真相。
- **对我项目的启发**：Spec-driven 不应只是静态约束，它可以作为 Agent 脑中的“动态假说系统”。当环境变更时，Agent 应该有能力重写自己的局部 spec。
- **今天是否值得深入研究**：是
- **建议行动**：试用（阅读并拆解其信念更新逻辑）

## 4. mksglu / context-mode
- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/mksglu/context-mode
- **一句话解释**：为 AI Coding Agent 设计的上下文压缩沙箱，通过拦截、沙盒化工具输出减少 98% 上下文消耗，并跨平台持久化会话记忆。
- **它为什么重要**：构建复杂创意工具或自动化工作流时，最大的敌人是“Context Window 膨胀导致失忆与高额费用”。它通过 MCP（Model Context Protocol）和 Hooks 拦截原始 CLI/Terminal 输出，仅将语义精简摘要反馈给上下文。
- **技术趋势标签**：#MCP #AgentWorkflow #ContextEngineering #DeveloperTools
- **可复用模式**：`执行环境与状态隔离 -> 拦截器过滤原始输出(Log Stripping) -> 结构化状态更新`。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个极简的 MCP Server，拦截本地终端执行测试的超长堆栈错误，提取出只有 3 行的错误核心，再喂回给 Cursor 或 Claude Code。
  2. **一个中型项目**：**Minecraft 日志过滤器与 Agent 控制中枢**：拦截 Mineflayer 的全部高频原始世界事件流（坐标变化、声音包），通过状态摘要器每 5 秒只向决策 Agent 汇报一次环境突变摘要。
  3. **一个艺术/游戏/叙事方向**：**“失忆机器人的记忆黑匣子”**：一个只能维持 2048 token 记忆的艺术装置 Agent。你对它说长篇大论，它必须依靠本地 context-mode 机制主动丢弃“无意义修饰”，只保留它认为刻骨铭心的关键词。
- **对我项目的启发**：不要让任何 Agent 直接看未经处理的系统原始输出（无论是 git diff、终端 log 还是游戏引擎世界数据），中间必须有一层“降噪沙箱”。
- **今天是否值得深入研究**：是
- **建议行动**：做demo / 接入已有工作流

## 今日模式总结

1. **视觉即可执行思维（Visual Code as CoT）**：
   图形不仅仅是最终展示结果，SVG/TikZ 等代码正在成为 Agent 推理过程中的中间思考载体（MathVis）。在创意生成中，多利用矢量中间态。
2. **假设-证伪闭环（Hypothesis-Falsification Loop）**：
   Agent 正从简单的“执行器”向“假说科学家”转变（EvoBelief）。赋予 Agent 一套随时准备被推翻的“世界观字典”，能极大提升系统自愈与动态适应能力。
3. **输出沙盒化与上下文节流（Output Sandboxing）**：
   Agent 与环境交互的瓶颈已不是模型能力，而是环境冗余信息的污染。利用 MCP 和 Hooks 对环境信息进行沙盒降噪（context-mode）已成为构建复杂工作流的标配。

## 今日可做小实验（< 2 小时）

### 项目名：SVG-Reasoning Sketchpad（自纠偏矢量草图器）

- **输入**：一句自然语言几何艺术需求（例如：“绘制一个由三个同心但旋转角度错开的等边三角形构成的莫比乌斯感图腾”）。
- **输出**：一个经过 Agent 自我检查、零重叠、带代码注释的完整可渲染 `.svg` 文件。
- **技术栈**：Python / Node.js + Claude 3.5 Sonnet (或 GPT-4o) API + 本地任意无头渲染器/或简单基于 xml 的视口边界检查脚本。
- **第一步怎么做**：
  1. 写一个 20 行脚本，调用 LLM 要求它分两阶段输出：先输出 `[GEOMETRIC_LOGIC]`（计算顶点坐标、旋转矩阵公式），再输出 `[SVG_CODE]`。
  2. 提取出 SVG 代码，用 Python 的 `xml.etree.ElementTree` 检查 viewBox 边界与图形坐标是否越界。
  3. 如果坐标越界或计算矛盾，自动将错误坐标和渲染尺寸作为 feedback 回传给 LLM：“你的第 2 个三角形超出了 500x500 的 viewBox，请根据公式重新调整尺度”，观察它是否具备根据几何规则自修正的能力。
