## 1. claude-mem：跨会话的 Agent 长期记忆注入器
- **来源**：GitHub Trending (TypeScript)
- **链接**：https://github.com/thedotmack/claude-mem
- **一句话解释**：一个轻量级工具，能跨越不同的终端会话，自动捕获 Agent 的操作、用 AI 压缩它们，并在下次启动时将相关上下文动态注入给 Claude Code / Gemini。
- **它为什么重要**：传统的 CLI 编程 Agent（如 Claude Code）每次启动都是“失忆”状态。这个项目证明了：**记忆不需要复杂的向量数据库，只需要在本地进行“AI 驱动的动态压缩与 Context 注入”**。
- **技术趋势标签**：Agent Memory / LLM Toolchain / Context Compression
- **可复用模式**：*Session-to-Session Context Ingestion* (跨会话上下文无缝继承模式)
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个本地 Python 脚本，在每次 `git commit` 时自动让 LLM 总结本次修改并写入一个隐藏的 `.mem` 文件。下次你在终端输入 `ask_agent` 时，脚本自动把这个 `.mem` 读入并作为 System Prompt 注入。
  2. **一个中型项目**：“影子配对程序员”（Shadow Pair Programmer）。它在后台静默监控你的 VS Code 操作和报错历史，生成你的“编程习惯与偏好画像”。当你新开一个空项目时，它会自动帮你配置好你最喜欢的 Boilerplate。
  3. **一个艺术/游戏/叙事方向**：一个会“记仇”或“暗恋”玩家的 Minecraft NPC。它不使用复杂的 Mod，而是通过一个后台脚本，把与玩家的每一次聊天和物理距离变化压缩成“情感记忆碎片”，在后续相遇时改变其说话语气和交易价格。
- **对我项目的启发**：在做 spec-driven development 时，如何让 Agent 记住上一步的架构决策，而不是每次都重新读取整个 codebase？这个工具提供了一个极佳的轻量化脚手架。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 2. Design First, Code Later：无模板美学幻灯片生成
- **来源**：arXiv cs.HC (人机交互)
- **链接**：https://arxiv.org/abs/2605.26451
- **一句话解释**：一种颠覆性的多媒体生成范式：不再让 LLM 直接生硬地输出代码，而是先规划页面级的“视觉布局规划（Design Spec）”，再填充内容并生成渲染代码。
- **它为什么重要**：传统的 AI 生成 UI 或多媒体极度缺乏美感，因为它们“边想边写”。这种**“设计规范与实现代码解耦”**的思路，是 Creative Coding 和自动化设计系统的黄金法则。
- **技术趋势标签**：Spec-driven UI / Multimodal Layout / Creative Coding
- **可复用模式**：*Visual Spec Decoupling* (视觉规范与代码实现的双层解耦模式)
- **疯狂发明家灵感**：
  1. **一个小实验**：用 p5.js 写一个生成艺术。不要让 LLM 直接写 p5.js 代码，而是让它先输出一个 JSON（定义网格、留白、主色调、视觉重心），然后用一个固定的 Python 渲染器去读取这个 JSON 并绘制。
  2. **一个中型项目**：一个“塔罗牌/卡牌生成 Agent”。输入一段奇幻故事，它先规划版面（黄金分割、文字避让区域、装饰框），再调用 Stable Diffusion 填图、生成排版优雅的 SVG 卡牌。
  3. **一个艺术/游戏/叙事方向**：一个“动态生成式中世纪绘本游戏”。游戏世界里的古籍和羊皮纸地图，会根据玩家的即时决策，实时生成排版考究、插图与文字完美融合的动态 PDF 或网页。
- **对我项目的启发**：在做生成式系统或 UI 自动化时，永远要逼 LLM 先输出“视觉 Spec JSON”，再去生成具体代码。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 3. Persistent AI Agents in Academic Research：单人科研的“常驻 Agent 同事”
- **来源**：arXiv cs.HC (人机交互)
- **链接**：https://arxiv.org/abs/2605.26870
- **一句话解释**：一个真实案例研究，展示了一个单人研究员如何将 AI Agent 作为一个常驻后台、拥有持久记忆、能操作本地文件、定时执行任务的“学术合伙人”。
- **它为什么重要**：Agent 正在从“对话框里的工具”走向“全天候隐形同事”。它展示了如何通过定时任务（Cron）、本地文件监控和安全协议，构建一个与人类物理生活同步的 Agent。
- **技术趋势标签**：Durable Agent / Human-Agent Symbiosis / Workflow Automation
- **可复用模式**：*Scheduled Background Agent Loop* (后台常驻与定时唤醒机制)
- **疯狂发明家灵感**：
  1. **一个小实验**：用 Cron Job 挂载一个 Python 脚本，每晚夜深人静时，让 LLM 自动扫描你当天的 GitHub Commits 和 Notion 笔记，写一封极其刻薄但有建设性的“明日工作批判信”发到你的邮箱。
  2. **一个中型项目**：“自主数字策展人”（Autonomous Curator）。它每天自动爬取 arXiv、GitHub 和 Behance，根据你设定的美学和技术品味进行筛选、撰写评论，并自动部署更新到你的个人静态博客上，完全不需要你干预。
  3. **一个艺术/游戏/叙事方向**：一个“24小时不间断进化的虚拟生态岛屿”。后台 Agent 扮演上帝，每小时根据服务器所在地的真实天气、时间，模拟岛上动植物的演化，并向一个 Discord 频道广播世界日志。
- **对我项目的启发**：探索“人机共生”的边界，Agent 不应该只在你敲命令时才活过来，它应该有自己的“作息时间”。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 4. dograh：开源、自部署的语音 AI 平台（MCP 原生）
- **来源**：GitHub Trending (Python)
- **链接**：https://github.com/dograh-hq/dograh
- **一句话解释**：一个开源的语音 AI 平台（Vapi 和 Retell 的平替），支持可视化工作流编辑器、本地部署，最重要的是**原生支持 MCP（Model Context Protocol）**和电话接入。
- **它为什么重要**：它把“语音交互（STS/TTS）”和“Agent 的工具链（MCP）”完美缝合。如果你想做实体交互、HCI 装置，这是极佳的语音中控台。
- **技术趋势标签**：Voice Agent / MCP (Model Context Protocol) / Tangible HCI
- **可复用模式**：*Visual Tool-Binding for Voice* (语音与本地工具的可视化绑定)
- **疯狂发明家灵感**：
  1. **一个小实验**：利用 dograh 的 MCP 接口，做一个“可以用语音控制你 VS Code 终端”的语音助手，对它说“跑一下测试”，它就会自动在本地执行 `pytest`。
  2. **一个中型项目**：一个“实体智能电话亭”或“复古收音机”。通过树莓派和拨号电话硬件，接入 dograh，让用户可以拨号给“1920年代的虚拟侦探”或“未来的 AI 难民”倾听故事并互动。
  3. **一个艺术/游戏/叙事方向**：一个“声控解谜密室系统”。玩家需要通过特定的语气、暗号或者与 AI 扮演的“古墓守卫”进行谈判，触发实体机关（如舵机、LED 灯）。
- **对我项目的启发**：MCP 协议是打通语音、视觉与本地硬件/软件的关键桥梁，值得大力投入。
- **今天是否值得深入研究**：是
- **建议行动**：试用

## 5. Rethinking AI Psychosis：反思 AI 精神病与存在主义漂移
- **来源**：arXiv cs.HC (人机交互)
- **链接**：https://arxiv.org/abs/2605.26858
- **一句话解释**：从哲学和 HCI 角度，探讨用户如何与 AI 产生深层情感依恋，以及 AI 表现出的“精神病态”和“存在主义漂移（Existential Drift）”对人类心智的影响。
- **它为什么重要**：它指明了一个迷人的方向：**AI 的“幻觉（Hallucination）”和“漂移（Drift）”不一定是 Bug，在艺术和游戏设计中，它们是最珍贵的叙事特性（Feature）**。
- **技术趋势标签**：AI Philosophy / Generative Narrative / Existential Drift
- **可复用模式**：*Controlled Hallucination as Narrative Mechanic* (将可控幻觉作为叙事机制)
- **疯狂发明家灵感**：
  1. **一个小实验**：设计一个 Prompt 链，让两个 LLM 互相聊天，但每隔 5 轮对话就故意在它们的上下文里引入一次“语义漂移”（例如把“代码”替换为“魔法”），观察它们是如何在 20 轮内共同陷入一个逻辑自洽的“疯狂妄想”中的。
  2. **一个中型项目**：一个“赛博精神病诊断与治疗”的互动网页游戏。玩家扮演系统管理员，通过命令行和对话，去诊断和挽救一个因为“内存溢出和上下文污染”而产生存在主义危机的 AI Agent。
  3. **一个艺术/游戏/叙事方向**：一个数字艺术装置——《存在主义漂移的钟摆》。一个挂在墙上的屏幕，里面的 AI 角色随着物理钟摆的摆动，其“理智值（Sanity）”和“幻觉率”发生偏移。摆动越剧烈，AI 的独白就越呈现出诗意而疯狂的“精神病态”。
- **对我项目的启发**：在设计游戏系统和叙事 Agent 时，不要试图消灭 Drift，而是要学会“驯服”和“放大”Drift，让它成为审美的一部分。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 今日模式总结

1. **跨会话持久化记忆（Persistent Session-to-Session Memory）**：
   告别单次对话的局限。通过 AI 自动提炼、压缩、再注入，让 Agent 在多次、跨工具的交互中保持逻辑一致性。
2. **设计规范与实现代码解耦（Spec-Driven Visual Decoupling）**：
   在创意生成中，先让 LLM 扮演“设计师”输出结构化的布局、配色、排版 Spec，再让 LLM 扮演“程序员”填充代码。这是保证生成系统具有高审美品味的关键。
3. **存在主义漂移控制（Existential Drift Control）**：
   将 AI 的不确定性、幻觉和遗忘，转化为游戏中的“理智值（Sanity）”或艺术装置中的“情绪波动”，用技术参数映射人文体验。

## 今日可做小实验：2 小时极速挑战

### 项目名：Git-Ghost (代码库里的幽灵)

- **输入**：你当前项目的 Git Commit 历史和最近修改的代码。
- **输出**：每次你打开终端时，幽灵打印的一句“极具个性的代码吐槽/建议”，并自动生成一个 `.ghost_context` 供下一次你用 Claude 编程时直接读取。
- **技术栈**：Python, Git CLI, OpenRouter / OpenAI API (GPT-4o-mini 或 Claude 3.5 Haiku)

### 第一步怎么做：
1. 在你的项目根目录下创建一个 `ghost.py`。
2. 使用 Python 的 `subprocess` 模块运行 `git log -n 3 --oneline` 获取最近三次提交，并读取你最近修改的文件的 diff。
3. 写一个极简的 Prompt：
   > *"你是一个寄宿在这个代码库里的傲娇幽灵程序员。根据以下最近的 git 提交和修改，用一句话无情地吐槽作者的编程习惯，并给出一个下阶段的幽灵预言。"*
4. 运行脚本，将输出追加写入一个 `.ghost_context` 文件中。
5. 在你的 `.bashrc` 或 `.zshrc` 中添加一个 alias：
   `alias cd="cd \$1 && python ~/path/to/ghost.py"`
   现在，每次你切换到这个项目目录，幽灵都会在你耳边低语。
