## 1. Studying Without a Syllabus: Task-Agnostic Environment Preprocessing
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2609.10824
- **一句话解释**：让 Agent 在没有接任何具体任务前，先像拓荒者一样自主探索陌生环境，自动编译工具库、建立索引和写出“生存指南”。
- **它为什么重要**：以往的 Agent 都是“给需求才动”（Task-driven），而这篇论文探讨的是“无纲领自适应”（Task-agnostic）。Agent 会主动摸索环境里的 API、文件、交互机制，生成预处理资产。这是构建具有自主意识 NPC 和自动化开荒工作流的关键跳板。
- **技术趋势标签**：#AgenticEnvironment #自主探索 #ProceduralWorkflow #SpecGeneration
- **可复用模式**：`Env-Inspection -> Asset-Synthesis -> Skill-Registry`（环境盲测 -> 资产提取 -> 注册为自制技能库）。
- **疯狂发明家灵感**：
  1. **一个小实验**：给 Claude 扔一个没有任何 README 的冷门开源仓库，限制它不准运行任何测试用例，仅通过阅读目录和 AST 自动生成一份《新手黑客游玩指南.md》以及 3 个封装好的 CLI 便捷脚本。
  2. **一个中型项目**：**Minecraft 拓荒先遣队**。新生成一个随机种子地图后，无任务 Agent 先自主在世界跑图 10 分钟，建立一份包含“附近矿脉热图、危险生物群系分布、当前资源最优科技树”的本地 Spec 文档，随后生成待执行任务列表给玩家或下游工作 Agent。
  3. **一个艺术/游戏/叙事方向**：**《盲盒遗迹》文字冒险游戏**。玩家每进入一个程序生成的失落文明遗迹，AI 伴侣都在后台“无先验逆向工程”这个遗迹的神庙机关，根据它探测到的环境规律，实时生成带有仪式感但功能合乎逻辑的解谜机制。
- **对我项目的启发**：在 Spec-driven 开发中，不要总由人类先写 Spec。可以让 Agent 先对目标沙盒做 Task-agnostic Preprocessing，反向提炼出环境规范（Environment Spec），开发者只需在上面做 Diff 修正。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 2. system_prompts_leaks: 顶级工业 Agent 的系统级 Spec 解剖库
- **来源**：GitHub Trending
- **链接**：https://github.com/asgeirtj/system_prompts_leaks
- **一句话解释**：全面逆向收集 Anthropic（Claude Code、Claude Design）、OpenAI、Cursor 等第一梯队产品的最新完整 System Prompt 泄露库。
- **它为什么重要**：这不是猎奇八卦，这是**全球最顶尖团队的“Prompt 架构工程 Spec”实物切片**。你可以直接观察 Anthropic 和 OpenAI 是如何定义 Agent 的工具调用边界、文件读写协议、思维链约束以及失败自愈机制的，比读任何论文都更贴近工业级落地。
- **技术趋势标签**：#PromptArchitecture #SpecDriven #AgentWorkflow #逆向工程
- **可复用模式**：`Meta-Role + Negative Constraints + Tool Invocation Grammar`（角色元定义 + 严格负向约束 + 工具调用语法树）。
- **疯狂发明家灵感**：
  1. **一个小实验**：对比 Claude Code 与 Cursor 的 System Prompt 结构，提取出它们用于“防止误删文件”与“长上下文记忆修剪”的特定 Prompt Block，合入你自己的日常开发 Agent。
  2. **一个中型项目**：**System-Prompt-Linter**。一个基于 AST 和规则引擎的 VSCode 插件，根据泄露的顶级 Prompt 提炼出的防御性规则，对你自己编写的 Agent System Prompt 进行静态检查（如：检测是否有歧义指令、是否缺少边界终止条件）。
  3. **一个艺术/游戏/叙事方向**：**AI 仿生人格冲突剧场**。把 Claude Code 的“极端严谨与任务至上”人格注入 NPC-A，把 Claude Design 的“审美发散与视觉权衡”注入 NPC-B，给它们同一套生成代码并围观它们在终端里吵架和博弈。
- **对我项目的启发**：做 Agent 工具时，Spec 的编写风格可以直接套用顶级产品的模板（比如结构化 XML 标签、极端清晰的 Step-by-step 工具交互守则）。
- **今天是否值得深入研究**：是
- **建议行动**：收藏（必须把 Claude Code 和 Claude Design 的文件拉下来细读）

## 3. Grounding Agent Memory: Environment-Probing Curation
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2609.11060
- **一句话解释**：Agent 不再盲信历史对话记录，而是在存入长期记忆前，主动向真实环境发探针“戳一下”验证事实，防止错误经验病毒式蔓延。
- **它为什么重要**：Agent 长时间运行最怕“记忆污染”（幻觉被当作常识存进向量库）。本研究提出了一种主动探测机制（Active Probing），在维护持久记忆时不仅做文本归纳，还要主动跑测试、发探针，确保记忆是与环境强绑定的。
- **技术趋势标签**：#AgentMemory #ActiveProbing #自愈系统 #可靠性工程
- **可复用模式**：`Candidate Memory -> Probing Action -> Environment Feedback -> Validated Storage`（生成记忆候选 -> 发出验证探针 -> 获得物理真实反馈 -> 固化进记忆）。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个只有 30 行代码的记忆校验器：当 Agent 总结出一条规则（如：“端口 8080 已被占满”）准备写入 memory.json 前，强制派发一个探测器执行 `nc -zv 127.0.0.1 8080`，验证失败则直接将该条记忆打上 `[HALLUCINATION]` 标签并丢弃。
  2. **一个中型项目**：**Minecraft 动态经验簿**。NPC 学习生存技能时，记录下“用木镐可以挖钻石”，入库前触发一次行为探针（去试挖一次），探针捕获破坏失败后，NPC 记忆自动修正为“木镐无法破坏钻石，需要铁镐以上”。
  3. **一个艺术/游戏/叙事方向**：**不可靠叙事解谜游戏**。玩家扮演一个机器人的“记忆审查官”，AI 机器人经常因为各种创伤生成虚假记忆，玩家需要根据世界环境的探针数据（物理痕迹、终端日志），剔除它的妄想，拼凑出飞船失事的真实始末。
- **对我项目的启发**：在你的自动化流水线或世界生成管线中，不要让 LLM 纯靠上下文推理生成规则，每个记忆/规则的持久化必须绑定一个“可执行断言（Executable Assertion）”。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 4. Finishing the Task Is Not Enough: Agent Resilience and Considerate Participation
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2609.10724
- **一句话解释**：重新定义 Agent 的好坏——不仅看它能不能跑通任务，更看它在环境崩坏时的“韧性”以及与人类协作时的“体贴度”。
- **它为什么重要**：终于有学术界开始从 HCI（人机交互）和系统韧性视角审视 Agent 了！过去的基准测试只看单一任务成功率，但现实是环境会有扰动、人类会临时插嘴改需求。这篇论文提出了“累积混乱下的抗打击能力”和“协同体贴度”，是做生成式协作系统（Co-creative tools）的理论金矿。
- **技术趋势标签**：#HCI #Agent协作 #Resilience #情商与交互体验
- **可复用模式**：`Disruption Ingestion -> Graceful Degradation -> Considerate Check-in`（摄入扰动 -> 优雅降级/兜底 -> 主动寻求人类最小成本确认）。
- **疯狂发明家灵感**：
  1. **一个小实验**：设计一个“防暴怒代码助手”：模拟开发中断（比如你突然强行 Ctrl+C 或修改了正在生成的文件），观察 Agent 是否能保留已完成的暂存区，并体贴地发一条：“你刚才中断了我，我保留了前 15 行逻辑，接下来你打算自己写还是让我从第 16 行继续？”
  2. **一个中型项目**：**体贴型 Game Master (AI-DM)**。在跑团或开放游戏世界中，当检测到玩家长时间处于挫败状态（频繁死亡/卡关/输入带情绪词汇），Agent 不破坏世界规则强行通关，而是动态引入环境微扰（如偶遇一个受伤的流浪商人遗落了补给），做到“无痕体贴”。
  3. **一个艺术/游戏/叙事方向**：**双人默契实验游戏**。玩家必须和一个具有自主脾气的 AI 共同操作一台复杂的星际采矿机械，AI 会根据你的操作稳定度来调整它对你的“信任值”；你犯错时它不仅要补救，还会产生符合性格的微表情和对话反馈。
- **对我项目的启发**：在设计 Creative Coding / 自动化设计工具时，不要追求“一次性黑盒跑完”，要把重点放在“当参数冲突时，Agent 如何体贴地向创作者提供可视化分支选择”。
- **今天是否值得深入研究**：否（理念极佳，可作为系统设计的指导哲学，无需通读全文公式）
- **建议行动**：收藏

## 今日模式总结

1. **从“等待 Prompt”转向“环境主动嗅探”（Environment Probing & Preprocessing）**
   顶尖 Agent 不再是一个被动的聊天框，而是一个被扔进未知生态系统后，能自己探索、自己下探针做单元测试、自己生成地图的“数字有机体”。
2. **Spec 从静态代码扩展为双向协议（Bidirectional Contract）**
   系统 Prompt 泄露库和韧性评估表明，工业级的 Spec 正在变成一个强约束、高防御、具备错误降级和情境感知的完整运行时配置。

## 今日可做小实验：主动式环境自检探针（Probe-Grounded Agent Memory）

- **项目名**：`Probe-Memory-Mini`（带探针验证的极简 Agent 记忆缓存）
- **输入**：一段 Agent 试图记录的“经验断言”（例如：`{"belief": "当前目录包含未提交的 git 更改", "probe_command": "git status --porcelain"}`）
- **输出**：经由物理环境执行并裁决后的记忆对象（若 probe 返回空，则判定为伪经验，拒绝写入并在控制台亮红灯；若非空，写入 `active_memory.json`）。
- **技术栈**：Node.js 或 Python（几行 `child_process.execSync` 或 `subprocess` 即可）、任意一个小 LLM（甚至直接写死 Mock 测试 logic）。
- **第一步怎么做**：
  1. 打开终端，新建一个目录 `probe-test` 并初始化 git。
  2. 写一个 20 行的脚本：接受一个 `{ 事实描述, 检验命令, 期望条件 }` 对象。
  3. 执行检验命令，捕获实际 stdout/stderr，断言失败则抛出 `MemoryPollutionError`。
  4. 感受一下“不靠 LLM 自圆其说，而是靠环境反馈作为真实性锚点”的感觉。这将是你未来写游戏 Agent 世界感知闭环的核心基石。
