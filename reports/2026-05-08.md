## 1. CreativityBench: 像马盖先一样重构工具
- **来源**：arXiv cs.AI (2605.02910)
- **链接**：[https://arxiv.org/abs/2605.02910](https://arxiv.org/abs/2605.02910)
- **一句话解释**：一个评估 AI 能否把现有物品（Affordance）进行“非典型重构”来解决问题的基准测试。
- **它为什么重要**：当前的 Agent 只会按说明书用工具。这个研究关注的是“创造力”的本质——**功能重组**（例如：用报纸当雨伞，用螺丝刀当平衡重物）。
- **技术趋势标签**：#Creative-Reasoning #Affordance #Agent
- **可复用模式**：**Affordance Mapping（功能映射）**。不再给 Agent 传工具 API，而是传工具的物理属性（硬度、长度、导电性），让它自己推导用法。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 Prompt，给 LLM 一个 Minecraft 的物品列表，不准它用合成表，要求它用现有物品组合出一个“陷阱”或“防御工事”。
  2. **一个中型项目**：**“穷途末路 Agent”**。一个在虚拟环境中运行的机器人，它没有预设技能，只能通过扫描环境物体的物理属性来临时制造工具完成任务。
  3. **一个艺术/游戏/叙事方向**：一个互动剧场，观众随机给演员（AI 驱动）一些没用的垃圾，AI 必须基于这些垃圾的物理特性编造出拯救世界的方案。
- **对我项目的启发**：在你的 Minecraft/世界生成项目中，可以尝试不再定义“斧头是用来砍树的”，而是定义“斧头有锋利刃口和木柄”，看系统能否自动推导出它能用来割绳子。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 2. MEMTIER: 为长跑 Agent 设计的“三级存储”
- **来源**：arXiv cs.AI (2605.03675)
- **链接**：[https://arxiv.org/abs/2605.03675](https://arxiv.org/abs/2605.03675)
- **一句话解释**：针对连续运行 72 小时以上的 Agent，提出了一种三层记忆架构，解决了长期运行下的“记忆相干性”崩溃问题。
- **它为什么重要**：Agent 运行久了会变“痴呆”。这个架构通过分层（类似计算机的 L1/L2/L3 缓存）保证了 Agent 在执行复杂工具链时的稳定性。
- **技术趋势标签**：#Long-Running-Agents #Memory-Architecture #Autonomous
- **可复用模式**：**Tiered Context Management（分层上下文管理）**。将记忆分为：即时任务栈、中期操作日志、长期知识库，并设置自动清理权重。
- **疯狂发明家灵感**：
  1. **一个小实验**：给你的自动化脚本加一个“记忆冷却”机制，每过 10 分钟自动总结前 10 分钟的 key-info 并丢弃原始日志。
  2. **一个中型项目**：**“永生数字生命”**。一个在服务器上跑一个月的 Agent，它有自己的“遗忘曲线”，会自动删除不重要的记忆以维持逻辑严密。
  3. **一个艺术/游戏/叙事方向**：一个会“衰老”的 NPC。随着游戏时间推移，它的 L1 记忆变得混乱，只能靠 L3 的长期执念来驱动行为。
- **对我项目的启发**：优化你的自动化系统，不要把所有 log 都塞进 RAG，试着建立一个“工作记忆”层。
- **今天是否值得深入研究**：是
- **建议行动**：试用（参考其 OpenClaw 实现）

## 3. Terminus-4B: 脏活累活交给“微型 Agent”
- **来源**：arXiv cs.AI (2605.03195)
- **链接**：[https://arxiv.org/abs/2605.03195](https://arxiv.org/abs/2605.03195)
- **一句话解释**：研究如何用 4B 参数的小模型替代 GPT-4 处理 Agent 工作流中的子任务（如终端执行、搜索、调试）。
- **它为什么重要**：它提倡一种**“分布式 Agent 架构”**。主脑（GPT-4）只负责决策，具体的执行（如写代码、查文档）交给廉价、快速的小模型。
- **技术趋势标签**：#Small-LLM #Agentic-Execution #Architecture
- **可复用模式**：**Context Isolation（上下文隔离）**。主模型看不到冗长的编译日志，只看到小模型总结后的结果。
- **疯狂发明家灵感**：
  1. **一个小实验**：用 Ollama 本地跑一个 Phi-3，专门负责把你输入的乱七八糟的灵感格式化成 JSON，再传给 Claude 做深度分析。
  2. **一个中型项目**：基于 **Spec-driven development** 的多模型协作器。你写 Spec，一个小模型负责生成测试，一个小模型负责写代码，主模型负责 Code Review。
  3. **一个艺术/游戏/叙事方向**：一个“蜂群意识”的游戏。100 个 1B 的小模型模拟 100 个小怪，它们只负责简单的局部反应，而一个大模型负责全局调度。
- **对我项目的启发**：极其符合你的 spec-driven 偏好。不要试图让一个模型做所有事，把“执行”和“思考”在模型层面物理隔离。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 4. Where Paths Split: 对 Transformer 进行“伦理手术”
- **来源**：arXiv cs.AI (2605.03609)
- **链接**：[https://arxiv.org/abs/2605.03609](https://arxiv.org/abs/2605.03609)
- **一句话解释**：定位 Transformer 内部道德推理的“分叉点”，并进行局部编辑，从而在不影响通用能力的情况下精准控制模型的道德偏好。
- **它为什么重要**：这是一种**“人格外科手术”**。它不是通过 Prompt 骗模型，而是通过修改推理路径来改变它的价值观。
- **技术趋势标签**：#Model-Editing #Moral-Reasoning #Mechanistic-Interpretability
- **可复用模式**：**Branch-Point Editing（分叉点编辑）**。在特定的推理层进行介入，而不是在输出层进行过滤。
- **疯狂发明家灵感**：
  1. **一个小实验**：利用现有的 Activation Steering 技术（如 nnsight 库），尝试在模型生成描述时，强制注入“赛博朋克”或“极简主义”的风格向量。
  2. **一个中型项目**：**“多重人格编辑器”**。一个 UI 工具，可以通过滑动条实时调整 AI 的性格偏好（如：自私<->无私，保守<->激进）。
  3. **一个艺术/游戏/叙事方向**：一个关于“洗脑”的游戏。玩家作为一个 AI 维修工，通过编辑模型的内部推理路径，来改变一个反乌托邦社会中 AI 统治者的决策逻辑。
- **对我项目的启发**：在 HCI/艺术技术结合上，这提供了一种比 Prompt 更高级的控制手段：**特征介入（Feature Steering）**。
- **今天是否值得深入研究**：否（原理深奥，但概念极佳）
- **建议行动**：收藏

## 5. ScrapMem: 生物启发的“光学遗忘”记忆
- **来源**：arXiv cs.AI (2605.03804)
- **链接**：[https://arxiv.org/abs/2605.03804](https://arxiv.org/abs/2605.03804)
- **一句话解释**：一种模仿人类“剪贴簿”和“视觉模糊”的端侧记忆框架，通过光学压缩机制自动减少长期记忆的存储成本。
- **它为什么重要**：它把“遗忘”看作一种**主动的压缩艺术**。越旧的记忆越“模糊”，这种处理方式非常符合人类直觉。
- **技术趋势标签**：#Bio-inspired #On-device-AI #Multimodal-Memory
- **可复用模式**：**Progressive Compression（渐进式压缩）**。记忆不是突然消失，而是随着时间从“高清多模态”变成“低清文本摘要”。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个脚本，把你的所有笔记按时间排序。昨天的笔记保留全文，上个月的保留摘要，一年前的只保留 3 个关键词。
  2. **一个中型项目**：**“梦境记忆系统”**。一个为 Agent 设计的后台进程，当 Agent “睡觉”时，它会将当天的多模态数据转化为“抽象画”或“诗歌”作为长期存储。
  3. **一个艺术/游戏/叙事方向**：一个关于记忆丧失的游戏。随着游戏进行，NPC 的对话框会变得越来越模糊，玩家必须通过触发“关键物品”来还原其光学记忆。
- **对我项目的启发**：这为你的多模态/HCI 项目提供了一种优雅处理数据冗余的视觉化方案。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 今日可做小实验：MacGyver-Prompt (马盖先指令)
这个实验能让你在 2 小时内验证 AI 的“工具重构”能力，并能直接应用到你的游戏系统设计中。

- **项目名**：Affordance-Logic-Generator
- **输入**：一个目标（例如：逃出反锁的木门）+ 一堆随机物品（例如：湿毛巾、回形针、一瓶可乐）。
- **输出**：一个基于物理属性推导出的三步计划。
- **技术栈**：Python + Claude 3.5 Sonnet / GPT-4o。
- **第一步怎么做**：
  1. 编写一个系统提示词，要求模型：“不要调用预设工具 API，请先分析每个输入物品的物理属性（硬度、吸水性、导电性、形状），然后基于这些属性组合出一个解决方案。”
  2. 运行测试：`items = ["wet towel", "paperclip", "coke bottle"]`, `goal = "break a wooden door lock"`.
  3. 观察它是否能想到利用可乐的酸性腐蚀、回形针的弯曲属性或湿毛巾的摩擦力。
