## 1. HandMade: Spatial Prompting for Generative 3D Creation with Part-Labeled VR Sketches
- **来源**：arXiv cs.HC (2026-06)
- **链接**：https://arxiv.org/abs/2606.27738
- **一句话解释**：一种将 VR 3D 涂鸦与自然语言结合的生成流，通过给粗糙的 3D 草图打上“部件标签”（如“翅膀”、“车轮”）来对 3D 生成模型进行精确的空间约束。
- **它为什么重要**：单纯用文字（Text-to-3D）生成 3D 资产就像开盲盒，缺乏空间控制。这项研究提出了“空间提示词（Spatial Prompting）”，用低精度的粗糙 3D 几何体+语义标签作为脚手架，让 AI 填充细节。这是 HCI 与生成式 3D 的完美结合。
- **技术趋势标签**：`HCI`, `Spatial Prompting`, `VR Sketching`, `Generative 3D`, `Creative Tool`
- **可复用模式**：**语义几何脚手架（Semantic-Geometric Scaffolding）**——用粗糙的、带标签的 3D 占位符（Whitebox）来引导复杂的生成式 AI 填充具体细节。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一个 Web 端的 2D 涂鸦板。你在画布上画几个彩色色块，并分别打上标签（如“红球=火球”、“蓝条=冰霜激光”），然后用 Stable Diffusion + ControlNet 瞬间将你的简笔画转化为像素风的游戏法术特效。
  2. **一个中型项目**：写一个 Blender 插件。允许你用最简单的立方体拼出怪兽的粗糙大形，给每个立方体打上标签（如 `[head: dragon]`, `[wing: mechanical]`），点击生成，插件自动调用 3D 生成 API，将这个粗糙模型缝合成一个高精度的、拓扑合理的 3D 角色模型。
  3. **一个艺术/游戏/叙事方向**：一个 VR 创造沙盒游戏。玩家在空间中用手势“画”出怪物的骨架并贴上器官标签（如“复眼”、“喷火口”），游戏实时生成这个 3D 怪物，并根据你画的器官赋予它物理行为（例如：因为你画了翅膀，它真的在 VR 空间里飞了起来）。
- **对我项目的启发**：在世界生成或 Minecraft 项目中，不要让 LLM 从零生成建筑代码。可以让 LLM 先生成一个极简的“体素脚手架”（如：这里是承重墙，这里是窗户），再由局部生成算法去填充细节。
- **今天是否值得深入研究**：是
- **建议行动**：做 demo

## 2. When Does Personality Composition Matter for Multi-Agent LLM Teams?
- **来源**：arXiv cs.AI (2026-06)
- **链接**：https://arxiv.org/abs/2606.27443
- **一句话解释**：研究了如何通过改变 LLM 智能体的“性格特质”（如大五人格中的宜人性），来显著改变多智能体团队的协作动态、对抗性语言输出以及最终的任务结果。
- **它为什么重要**：智能体不应该只是冷冰冰的工具。通过给智能体注入“性格”，不仅能改变它们的对话语气，还能改变它们解决问题的策略。例如，低宜人性的智能体更具批判性，适合纠错；高宜人性的智能体适合达成共识。
- **技术趋势标签**：`Multi-Agent System`, `Personality Prompting`, `Social Simulation`, `Emergent Behavior`
- **可复用模式**：**性格光谱对齐（Personality Spectrum Alignment）**——通过大五人格（Big Five）Prompting 调配 Agent 团队的认知多样性，以优化特定任务（如头脑风暴需要高开放度，代码审计需要低宜人性/高严谨性）。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个命令行“毒舌代码评审局”。实例化三个 Agent：一个极度自负且低宜人性的“技术杠精”，一个极度悲观的“安全偏执狂”，和一个和稀泥的“老好人组长”。扔给它们一段你的代码，看它们吵架并给出最终的修改方案。
  2. **一个中型项目**：打造一个“智能体编剧室（Agent Writer's Room）”。输入一个故事大纲，由性格各异的 Agent（焦虑的主编、浪漫主义的编剧、注重逻辑的剪辑）通过激烈的辩论和妥协，合作撰写出充满冲突的剧本。
  3. **一个艺术/游戏/叙事方向**：一个《模拟人生》式的虚拟社交生态。每个 NPC 的人格特质（如外向度、神经质）会随着游戏内事件（如被玩家欺负、连续晴天）发生动态漂移，从而自发形成帮派、暗恋、排挤等复杂的涌现叙事。
- **对我项目的启发**：在 spec-driven development 或 agent workflow 中，不要用千篇一律的“你是一个资深专家”来 Prompt 智能体。引入“性格冲突”能极大地暴露出系统设计中的隐蔽 bug。
- **今天是否值得深入研究**：是
- **建议行动**：试用（在现有 Agent 框架中加入人格 Prompt 观察效果差异）

## 3. Agent-Native Immune System: Architecture, Taxonomy, and Engineering
- **来源**：arXiv cs.AI (2026-06)
- **链接**：https://arxiv.org/abs/2606.28270
- **一句话解释**：提出了“智能体原生免疫系统”架构，将安全防御机制融入智能体的实时推理循环中，像生物免疫系统一样，主动识别并阻断针对 Agent 的恶意攻击和幻觉污染。
- **它为什么重要**：现在的 Agent 很容易被 Prompt 注入（Prompt Injection）或工具滥用带偏。把安全防御比作“免疫系统”，意味着我们需要在 Agent 内部部署不间断运行的、监控“自我/非我”状态的微型监控循环，而不是只做外围过滤。
- **技术趋势标签**：`Agent Security`, `Autonomous Loop`, `Self-Monitoring`, `Immune Metaphor`
- **可复用模式**：**双轨免疫监控（Dual-Track Immune Monitoring）**——在主推理 Agent 旁边，并联一个轻量级的“T细胞 Agent”，专门审查主 Agent 的短期记忆、工具调用参数和即将输出的行为是否偏离了“系统基线（Spec）”。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个带有“痛觉/免疫”的 CLI 助手。当你在对话中试图诱导它删除系统文件，或者它自己产生幻觉要执行危险命令时，它的“免疫模块”会报警，并像生物一样产生“发热反应”（暂时限制其 API 额度，强制其进入自我反思模式）。
  2. **一个中型项目**：构建一个“智能体生态培养皿（Agent Sandbox Sandbox）”。在里面放几个自主运行的 Agent，并不断向环境中注入“病毒”（如恶意 Prompt、虚假的 API 响应、带毒的 RAG 文档），观察并可视化它们的免疫 Agent 是如何识别、隔离并“杀死”受感染 Agent 的。
  3. **一个艺术/游戏/叙事方向**：一个赛博朋克风格的文字冒险游戏。玩家扮演一个黑客，试图侵入一个 AI 智能体的大脑。AI 的防御系统被具象化为一个有生命的“免疫迷宫”，玩家的每一次 Prompt 攻击都会引发迷宫内的免疫反应（视觉化为细胞吞噬和防火墙重构）。
- **对我项目的启发**：在做自动化系统和 LLM 工具链时，必须设计一个独立的、高权限的“监督 spec 检查器”（即免疫系统），防止 Agent 在连续执行任务时彻底跑偏。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 4. SidConArena: An Environment Evaluating Agents in Open-Ended, Positive-Sum Bargaining Game
- **来源**：arXiv cs.AI (2026-06)
- **链接**：https://arxiv.org/abs/2606.27397
- **一句话解释**：一个全新的评估环境，专门测试 LLM 智能体在开放式、非零和（双赢）博弈中的谈判、资产交换、长期规划和应对延迟回报的能力。
- **它为什么重要**：大多数 AI 游戏都是零和博弈（你死我活），但现实世界和好玩的游戏系统往往是“非零和”的（通过交易创造剩余价值）。让 Agent 学会“通过妥协换取长远利益”，是智能体走向社会化、生态化的关键一步。
- **技术趋势标签**：`Game Theory`, `Positive-Sum Negotiation`, `Agent Arena`, `Economic Simulation`
- **可复用模式**：**非零和资源互换协议（Non-Zero-Sum Barter Protocol）**——智能体之间不仅比较眼前利益，还维护一个“信任度/债务”账本，允许进行跨越时间维度的资源拆借和承诺。
- **疯狂发明家灵感**：
  1. **一个小实验**：在本地跑两个 Agent（商人 A 和商人 B）。给 A 分配“木材”，给 B 分配“皮革”，目标是合成“皮甲”。设定不同的贪婪指数，让它们在本地终端里通过多轮讨价还价达成一笔双赢的交易。
  2. **一个中型项目**：搭建一个“自治跳蚤市场（Autonomous Bazaar）”。20 个 Agent 在一个局域网内运行，每个 Agent 都有自己的“合成配方”和初始原材料，它们必须通过 WebSockets 自行寻找交易对象、谈判、甚至结盟来完成各自的合成任务。
  3. **一个艺术/游戏/叙事方向**：一个极简的策略生存游戏。玩家漂流到一个由 LLM 酋长统治的群岛。在这里，暴力无法通关，你必须利用真实的经济学原理、长期信用累积、甚至是“画大饼（延迟回报）”来游说各部落首领，达成贸易同盟共同对抗自然灾害。
- **对我项目的启发**：这非常适合 Minecraft 世界生成或多 Agent 社会模拟。可以给 NPC 引入“经济动机”和“正和博弈”逻辑，让它们自发建立村庄、开辟商路。
- **今天是否值得深入研究**：否（先收藏，作为博弈机制设计的参考）
- **建议行动**：收藏

## 5. Internalizing the Future: A Unified Agentic Training Paradigm for World Model Planning
- **来源**：arXiv cs.AI (2026-06)
- **链接**：https://arxiv.org/abs/2606.27483
- **一句话解释**：提出了一种统一的智能体训练范式，让 LLM 智能体拥有“内部世界模型”，在正式行动前，能像人类一样在脑海里进行“What-if（如果……会怎样）”的虚拟演练和多路径规划。
- **它为什么重要**：现在的 Agent 大多是“走一步看一步”的反应式系统。而“世界模型（World Model）”赋予了 Agent “神游”和“推演未来”的能力。它在虚拟脑海中模拟执行，评估后果，然后再在现实中踏出第一步。
- **技术趋势标签**：`World Model`, `What-If Reasoning`, `Sequential Decision Making`, `Agent Planning`
- **可复用模式**：**双环心理沙盒（Dual-Loop Mental Sandbox）**——外环负责接收现实感知并执行决策，内环（世界模型）负责对备选动作进行多步前向模拟（Rollout）并打分。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一个“先知命令行”。当你想执行一个复杂的 Bash 命令组合时，Agent 并不直接运行，而是在后台启动一个轻量级的 Docker 容器（或者让 LLM 模拟终端输出），预测命令执行后的文件树变化。如果预测到会报错或删错文件，自动拦截并修正。
  2. **一个中型项目**：开发一个“剧本杀先知助手”。玩家输入当前想对 NPC 撒的谎，AI 助手在后台的“心理沙盒”中模拟该 NPC 听完谎言后的 3 种心理反应路径，并可视化为概率树，提示玩家“如果说这个谎，NPC 有 70% 的概率在 3 轮后识破你”。
  3. **一个艺术/游戏/叙事方向**：一个解谜游戏。你扮演一个拥有“预知未来”能力的超能力者。游戏里的 NPC 每一个动作前，都会在后台运行世界模型推演你的下一步行动。你必须利用这种“心理推演的重叠”来制造悖论，欺骗 NPC 的内部世界模型，从而通关。
- **对我项目的启发**：对于 spec-driven development（规范驱动开发），在生成代码前，可以用一个专门的“模拟器 Agent”去“推演”这段代码在复杂边缘情况下的运行状态，从而在代码真正写出来之前就完成消错。
- **今天是否值得深入研究**：是
- **建议行动**：试用（尝试用双 LLM 角色构建一个“设计-模拟反馈环”）

## 今日模式总结

1. **空间与语义的脚手架化（Spatial-Semantic Scaffolding）**：不再仅仅依赖文本 Prompt，而是将粗糙的几何、物理形状与语义标签结合，作为生成式 AI 的“空间约束骨架”。
2. **双环推理与心理沙盒（Mental Sandbox Rollout）**：Agent 的架构正在从“单向反应链”演变为“双环结构”——一个负责行动，一个负责在虚拟世界模型中进行“What-if”前向演练。
3. **生态化安全与性格动力学（Ecology & Personality Dynamics）**：将 Agent 团队视为一个活的生态系统，引入类似“生物免疫系统”的自我监控机制，并利用“性格光谱”来调控团队的创造力与对抗性。

## 今日可做小实验

### 项目名：The Mental Sandbox (心智沙盒：零运行代码消错器)

- **输入**：一个复杂的、可能包含陷阱的 Python 编程任务（例如：“写一个读取 CSV、解析日期并计算差值的脚本，注意处理缺失值和异常格式”）。
- **输出**：一个在**不实际运行代码**的情况下，经过多次“心理演练”和自纠错后生成的完美 Python 脚本，以及一份详尽的“脑内模拟失败日志”。
- **技术栈**：Python, `LiteLLM` 或 `OpenAI API` (推荐使用 GPT-4o 或 Claude 3.5 Sonnet，因为需要极强的逻辑推理能力)。
- **第一步怎么做**：
  1. 创建两个不同的 System Prompt：
     - **Architect (架构师)**：负责根据任务写出初始代码。
     - **MentalSimulator (心智模拟器)**：负责在脑海中虚拟执行代码，模拟各种边缘输入（如空 CSV、错误的日期格式 `YYYY/DD/MM`），并生成虚构的 Python Traceback（报错堆栈）和 `print` 输出。
  2. 编写一个 Python 脚本，让 `Architect` 给出第一版代码。
  3. 将该代码传给 `MentalSimulator`，命令它：“请不要运行此代码，在脑海中用 3 种极端的输入数据模拟运行它，如果发现报错，请伪造一份逼真的 Python Traceback，并指出是哪一行代码引起的。”
  4. 将模拟器的报错反馈给 `Architect` 进行修正。
  5. 循环 2 轮，最后将“完美版代码”保存到本地，并打印出“脑内模拟失败日志”，对比最终真实运行的结果。你会惊叹于 AI 居然能在“纯脑补”的情况下找出那么多逻辑漏洞！
