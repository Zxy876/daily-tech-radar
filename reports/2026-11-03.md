## 1. Claude-Code-Game-Studios：用 49 个分工 Agent 模拟游戏工作室
- **来源**：GitHub Trending
- **链接**：https://github.com/Donchitos/Claude-Code-Game-Studios
- **一句话解释**：把 Claude Code 包装成一个包含策划、主程、美术管线、数值与 QA 的 49 节点虚拟游戏开发工作室。
- **它为什么重要**：它把“Prompt 单兵作战”演进成了“层级化的生产力群岛”。它不是单纯堆砌角色，而是定义了 72 个具体的流水线 Skill（技能），展示了 spec-driven（规范驱动）开发如何应用在游戏制作这种重资产、重依赖的领域。
- **技术趋势标签**：#AgentSwarm #GameDev #SpecDriven #WorkflowHierarchy
- **可复用模式**：**组织架构即代码（Org-as-Code）**。将复杂项目的生成流程拆解为“提出需求 -> 架构评审 -> 切片交付 -> 交叉验证”的职能树，而非单 agent 线性循环。
- **疯狂发明家灵感**：
  1. *一个小实验*：抽离出“关卡策划 Agent + 语法校验 Agent”，用它全自动批量生成可运行的 P5.js / Pico-8 极简关卡。
  2. *一个中型项目*：做一套**Minecraft 自动化筑城工坊**：一个 Agent 负责世界观与空间叙事，一个负责结构切片，一个负责将结构编译为 WorldEdit / Litematica 原理图指令。
  3. *一个艺术/游戏/叙事方向*：**自治 NPC 制作组**——让一组 Agent 不负责写代码，而是作为一个活体“戏剧导演组”，在游戏后台根据玩家行为动态编写支线任务与世界传闻。
- **对我项目的启发**：给个人项目（如 Drift）建立轻量级“虚拟委员会”spec：一个人开发时，通过配置虚拟的“架构师 vs 顽固测试员”，强迫自己先定 schema 再落代码。
- **今天是否值得深入研究**：是
- **建议行动**：做demo（克隆仓库，只偷师它的 `skills/` 和 agent 提示词分工编排逻辑）

## 2. context-mode：把工具输出隔离在上下文之外的极简补丁
- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/mksglu/context-mode
- **一句话解释**：通过沙箱与本地 SQLite FTS5 全文搜索，把庞大的工具运行输出（日志、报错、万行数据）隔离在 Agent 上下文之外，只允许按需检索，节约 99% 的 token。
- **它为什么重要**：上下文窗口（Context Window）不是垃圾场。当前大多数 Agent 变笨、漂移（drift）的核心原因是 terminal/tool 返回了过多无用信息。这个项目提出了一种极其优雅的 HCI 架构：**执行归执行，上下文只留检索引用**。
- **技术趋势标签**：#ContextMinimalism #AgentTooling #SQLiteFTS5 #TokenEfficiency
- **可复用模式**：**Tool 隔离区与虚空指针（Virtual Pointer via Search）**。Agent 执行命令后只拿到一个哈希引用或状态码，仅当需要排查时才用自然语言/SQL 关键词检索局部碎片。
- **疯狂发明家灵感**：
  1. *一个小实验*：写一个 Python 包装器，让 LLM 跑 Bash 时默认把输出写入临时 SQLite，只向 LLM 返回 `[Output 2.4KB stored. Use query_log("keyword") to inspect]`。
  2. *一个中型项目*：**超长连续生成的生成式艺术 Debugger**。在 Processing / TouchDesigner 自动化生成中，隔离海量控制台报错，只在视觉产出异常时反查报错。
  3. *一个艺术/游戏/叙事方向*：**无限记忆侦探游戏**。游戏生成数万字的案卷档案并存入 FTS5，侦探 NPC 并不具备全知全能的上下文，必须像真人一样通过查阅特定线索词来推导结论，完全规避幻觉与长文本失忆。
- **对我项目的启发**：做 Agent 工作流时，永远不要把原始 raw output 喂回 prompt，强制引入一个“过滤/中间存储”层。
- **今天是否值得深入研究**：是
- **建议行动**：试用并精读其 SQLite FTS5 与 Agent 的通信实现。

## 3. claude-mem：跨会话的自主情境压缩记忆层
- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/thedotmack/claude-mem
- **一句话解释**：在后台无感监听 Agent 的每一个动作，由后台 AI 定期浓缩为长期记忆向量与摘要，并在开启新 Session 时自动注回相关上下文。
- **它为什么重要**：解决开发中最痛苦的“冷启动”问题（每个新 session 都要重讲一遍项目规范和约定）。它把人类工作中的“自传式记忆（Autobiographical Memory）”变成了 Agent 工具链的标准中间件。
- **技术趋势标签**：#LongTermMemory #ContextInjection #DevWorkflow #LocalFirst
- **可复用模式**：**旁路观察者模式（Sidecar Observer）**。主 Agent 专注写代码，后台独立轻量 Agent 负责做“工作笔记”，把显式 context 维护转移到隐式自监督流程中。
- **疯狂发明家灵感**：
  1. *一个小实验*：利用 Claude 钩子，每次 `git commit` 时自动调用轻量模型更新一份本地 `PROJECT_MINDMAP.md`。
  2. *一个中型项目*：**个人设计语言持久化引擎**。不管你在哪个 IDE 或设计工具里，Agent 都能记住你偏好的调色盘、间距规范、代码坏品味并实时提醒。
  3. *一个艺术/游戏/叙事方向*：**能记住上周玩家情绪的 RPG 伙伴**。离线压缩玩家每一次对话的潜台词，再次登录时，NPC 带着“隔周沉淀后的感慨”开场，增强情感羁绊。
- **对我项目的启发**：在 spec-driven 流程中，spec 不仅是自顶向下的指令，也应该是 Agent 经历迭代后自底向上“反向写回”的资产。
- **今天是否值得深入研究**：是
- **建议行动**：收藏并安装到本地 CLI 工具流中进行日常体验。

## 4. 复杂与创意统一的 Agentic 视频剪辑系统 (Unified Agentic Video Editing)
- **来源**：arXiv cs.HC
- **链接**：https://arxiv.org/abs/2609.12769
- **一句话解释**：提出了一个支持场景预览、摘要提取到电影级预告片制作的分层 Agent 剪辑系统，用结构化规划解耦创意约束与底层操作。
- **它为什么重要**：论文探讨了 HCI 领域的核心命题——**如何让 AI 在有严格美学约束（节奏、情绪弧线、蒙太奇）的任务中工作**。它放弃了 end-to-end 视频生成，而是采用“高层叙事计划 -> 时间线约束调度 -> 底层剪辑”的三层架构。
- **技术趋势标签**：#CreativeAgent #ComputationalNarrative #VideoEditing #AgentPlanning
- **可复用模式**：**时间线约束编排（Timeline Constraint Planning）**。把感性的“节奏感/戏剧性”形式化为时间线上的约束条件（如：高潮点位置、镜头长度方差、音画同步锚点）。
- **疯狂发明家灵感**：
  1. *一个小实验*：做一个由 Markdown 剧本驱动的自动化剪辑工具，输入一段长视频和带情绪标记的对白，自动生成节奏卡点的粗剪 EDL（剪辑决策表）。
  2. *一个中型项目*：**生成式 Minecraft 电影导演系统**。通过录制 ReplayMod 的摄像机轨迹，Agent 依据叙事脚本自动计算运镜角度、景深与时间轴剪辑。
  3. *一个艺术/游戏/叙事方向*：**自适应动态微电影装置**。采集展厅观众的声音与动作，系统 Agent 实时抓取监控流切片，按经典三幕式戏剧节奏拼贴成一部每 5 分钟放映一次的“展厅惊悚片”。
- **对我项目的启发**：在做创意工具或游戏系统时，不要让 LLM 直接输出终极产物，让它输出“时间轴/空间约束规则”，把渲染与排布交给确定性代码。
- **今天是否值得深入研究**：否（先取其思路，无需死磕其数学评估指标）
- **建议行动**：收藏，借鉴其叙事规划到时间轴的架构流程图。

## 今日模式总结

1. **上下文瘦身（Context Sanitization）**：从 `context-mode` 到 `claude-mem`，大家终于意识到**Context Window 不是越大越好，而是越纯越好**。将冗余信息（Tool 原始日志、过往长历史）通过 FTS5 搜索或后台总结抽离为“外部存储”，正成为最先进 Agent 的共同解法。
2. **创意工作流的分层分权（Hierarchical Agency）**：无论是游戏开发的 49 个岗位，还是电影剪辑的三层规划，端到端的大模型神话正在破灭，**Spec（规范定义）+ 分层职能编排（High-level Planner + Low-level Executors）** 是构建复杂创造性系统的唯一稳健路径。

## 今日可做小实验：上下文幽灵（Context Ghost）
一个 2 小时内能跑通的原型，体验“将工具噪音完全隔离在 Agent 上下文之外”的快感。

- **项目名**：`Context Ghost`（上下文幽灵）
- **输入**：用户要求 Agent 执行一个会产生上千行输出的命令（例如：`npm test`、扫描一个大型目录或拉取大体积 JSON 数据）。
- **输出**：Agent 无法看到原始输出，它只能拿到包含 `output_id` 和“输出统计”的 1 行摘要，并调用你提供的专用检索工具按需提问并解决问题。
- **技术栈**：Python + SQLite（开启 FTS5）+ 任意 OpenAI 兼容 API / Claude CLI。
- **第一步怎么做**：
  1. 本地建一个 `ghost.db`，写一段 30 行的 Python 代码建表：`CREATE VIRTUAL TABLE logs USING fts5(command, content);`。
  2. 封装一个自定义 Tool `run_command_ghost(cmd)`：在后台用 `subprocess` 跑命令，将标准输出存入 SQLite，仅向模型返回：`"Command executed. 2480 lines hidden. Stored in id=1. Use search_ghost(id, query) to inspect."`。
  3. 封装第二个 Tool `search_ghost(id, query)`：执行 SQL `SELECT snippet(logs) FROM logs WHERE logs MATCH query AND rowid = id`，只把匹配的 3 行输出还给 LLM。
  4. 体验一次让模型在不知道完整输出的情况下，定位一个隐藏在第 1500 行的特定错误。感受 token 消耗骤降 95% 的震撼。
