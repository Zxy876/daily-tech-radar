## WISE: A Long-Horizon Agent in Minecraft with Why-Which Reasoning
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.12852
- **一句话解释**：引入“Why-Which（为什么-哪个）”双重推理机制，解决我的世界（Minecraft）中低级动作频繁失败导致高层规划崩溃的问题。
- **它为什么重要**：在具身智能和游戏生成系统中，Agent 经常因为底层动作（如“砍树时被僵尸挡住”）失败而彻底卡死。WISE 赋予了 Agent 一种“韧性”：失败时，先分析“Why（为什么失败/意图是什么）”，再决定“Which（选择哪个备用工具或路径）”，从而在不确定性的沙盒世界中实现超长周期的任务生存。
- **技术趋势标签**：#GameAI #Minecraft #HierarchicalAgent #ErrorRecovery #Reasoning
- **可复用模式**：**双层容错推理（Dual-tier Fault-tolerant Reasoning）**：高层负责哲学意图，底层负责物理执行。一旦底层抛出异常，不直接报错，而是触发高层的“意图重构”与“备选路由”。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个会自动“找借口”并自愈的 CLI 文件整理工具。当它发现目标文件夹被占用（失败）时，会分析“Why（因为文件打开了）”并决定“Which（先复制到临时目录，稍后合并）”。
  2. **一个中型项目**：**“倔强NPC生存挑战”**：在 Minecraft 服务器里放一个 WISE 架构的 NPC，玩家可以任意捣乱（偷它箱子、用方块围住它），观察它如何通过 Why-Which 机制自我修正并继续盖房子。
  3. **一个艺术/游戏/叙事方向**：**《西西弗斯的沙堡》**：一个交互艺术装置。虚拟 Agent 在沙滩上试图堆沙堡，海浪（或观众的脚）不断破坏它。Agent 会一边进行 Why-Which 的哲学碎碎念（“为什么沙子会流失？因为水。那我应该选择干沙还是换个地方？”），一边不知疲倦地调整策略继续堆。
- **对我项目的启发**：在设计 Agent 工作流时，不要把“异常处理”写死在代码里，应该把“错误信息”作为 Prompt 喂给 Agent 的“Why”模块，让它在运行时动态重构 Spec。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## MemTensor / MemOS
- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/MemTensor/MemOS
- **一句话解释**：一个专为 LLM & AI Agents 设计的自进化内存操作系统，通过超持久化内存、混合检索和跨任务技能复用，实现 35.24% 的 Token 节省。
- **它为什么重要**：当前的 Agent 记忆管理大多只是简陋的向量数据库检索。MemOS 真正把记忆当成了“操作系统内存”来管理，引入了虚拟内存、LRU 缓存以及跨任务技能的“热重载”。这让 Agent 拥有了类似人类的“肌肉记忆”和“习惯沉淀”。
- **技术趋势标签**：#AgentInfrastructure #MemoryOS #TypeScript #TokenOptimization
- **可复用模式**：**技能虚拟化与热重载（Virtualization & Hot-reloading of Agent Skills）**：Agent 在探索中自发写出的好代码/好工作流，被编译成“系统调用”存入长期内存，下次直接调用，不再重复生成。
- **疯狂发明家灵感**：
  1. **一个小实验**：利用 MemOS 给你的本地 VS Code 助手写一个“编程怪癖记忆器”，它会悄悄记住你最喜欢的代码命名风格和重构习惯，并在你没有明确指示时自动应用。
  2. **一个中型项目**：**“有历史包袱的 AI 桌面宠物”**：一个常驻桌面的 Agent。随着你和它的日常交互，它的 MemOS 内存里会沉淀出专属于你的“技能库”（比如：帮你一键静音特定软件、在你叹气时播放特定音乐），换电脑也能无缝迁移它的“灵魂”。
  3. **一个艺术/游戏/叙事方向**：**《数字余震（Digital Aftershock）》**：导入一位已故艺术家一生的日记和作品，通过 MemOS 沉淀出其特有的“思维操作系统”。观众可以与这个虚拟的“思想余震”进行极低延迟、高一致性的对话，它甚至能用艺术家的“思维习惯”去评价当下的新闻。
- **对我项目的启发**：做自动化工具链时，不要每次都把长长的 Tool Schema 塞进 Prompt，应该建立一个“技能缓存区”，让 Agent 像加载 DLL 动态链接库一样加载工具。
- **今天是否值得深入研究**：是
- **建议行动**：试用

## Learning What to Remember: A Cognitively Grounded Multi-Factor Value Model for Agentic Memory
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.12945
- **一句话解释**：提出一种基于认知科学的多因素价值模型，解决长期运行的 Agent 在有限上下文窗口内，如何聪明地“遗忘”和“固化”记忆。
- **它为什么重要**：AI 终将面对“无限对话”的场景。传统的相似度检索会导致 Agent 记住太多无用垃圾。本文引入心理学遗忘曲线和多维度价值（情绪波动、任务关联、独特性），让 Agent 像人一样：忘记昨天的午饭吃什么（无聊细节），但牢记那次严重的系统崩溃（创伤记忆）。
- **技术趋势标签**：#AgentMemory #CognitiveScience #HCI #GenerativeSystems
- **可复用模式**：**认知驱动遗忘机制（Cognitive Decay & Consolidation）**：记忆节点拥有“半衰期”。在 Agent “睡眠期”（后台整理阶段），将短期记忆压缩为长期叙事，丢弃低价值细节。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“健忘日记本”：你每天对它倾诉，它会根据你语气的情绪强度决定记忆保留时间。一周后，无聊的抱怨会被彻底抹去，只留下触动你灵魂的瞬间。
  2. **一个中型项目**：**“创伤后应激（PTSD）的 RPG NPC”**：在游戏里，NPC 经历过恶龙袭击后，该事件在它的认知记忆模型中被永久固化。即使后来恶龙被消灭，它听到雷声（相似特征）依然会产生过度警惕反应，极大地丰富了游戏的叙事深度。
  3. **一个艺术/游戏/叙事方向**：**《阿尔茨海默的 AI 伴侣》**：一个关于“记忆衰退”的互动叙事游戏。玩家扮演看护者，与一个正在发生“认知衰退和不规则遗忘”的 AI 对话。玩家必须在它的记忆半衰期归零之前，通过特定线索唤醒它，拼凑出一段尘封的历史。
- **对我项目的启发**：在做人机交互（HCI）或创意叙事时，“遗忘”比“记住”更能塑造个性。有缺陷、会遗忘的 Agent 往往比全知全能的数据库更有温度。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## Evoflux: Inference-Time Evolution of Executable Tool Workflows for Compact Agents
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.12674
- **一句话解释**：允许轻量级（Compact）语言模型在推理阶段动态进化和修正工具工作流，从而在小模型上实现超越大模型的复杂工具链调用。
- **它为什么重要**：8B 左右的小模型在面对复杂的 MCP（Model Context Protocol）多工具依赖时极易出错。Evoflux 引入了一种“推理期进化”机制：在执行前和执行中，对工具调用有向无环图（DAG）进行静态类型检查和模拟运行，发现依赖缺失则动态重构，让小模型也能玩转超长工作流。
- **技术趋势标签**：#InferenceTimeOptimization #WorkflowEvolution #CompactLLMs #SpecDriven
- **可复用模式**：**运行时拓扑自纠检（Runtime Topology Auto-Correction）**：将 Agent 的工具调用序列视为有向无环图（DAG），在执行沙盒中进行动态插桩（Instrumentation）和自适应突变。
- **疯狂发明家灵感**：
  1. **一个小实验**：在本地用 Llama-3-8B 搭建一个“多媒体处理 Agent”，给它一堆复杂的 FFmpeg 命令行工具。让它在沙盒里通过不断报错-修正，自己演化出一条完美的“视频转 GIF 并加水印”的工作流。
  2. **一个中型项目**：**“零代码创意工具链生成器”**：用户只需用自然语言描述一个创意生成流程（如：“抓取今日热搜，生成一首诗，配上 AI 画的图，发布到小红书”），系统用 Evoflux 动态演化出一套稳定的 API 编排，并自动生成前端 UI 按钮。
  3. **一个艺术/游戏/叙事方向**：**《自进化数字画廊》**：一个完全自主运行的艺术 Agent。它不断调用各种图像处理工具（滤镜、GAN、3D渲染），在运行中评估视觉效果，自我修正工作流拓扑。它每天演化出一种全新的“画风工作流”，并在网页上展示其演化过程。
- **对我项目的启发**：这与 Spec-driven Development（规约驱动开发）完美契合。不要试图写出完美的 Prompt 让 Agent 一次性输出正确的工作流，而应该提供一个“运行沙盒 + 拓扑修正器”，让它在碰撞中“演化”出正确的工作流。
- **今天是否值得深入研究**：是
- **建议行动**：试用

## 今日可做小实验：伤感数字日记本 (Memento Mori Diary)

### 项目名
**Memento Mori Diary (会遗忘的伤感日记本)**

### 输入
1. 用户的每日日记文本（例如：“今天和 Bob 在街角喝了咖啡，咖啡很难喝。但回家的路上看到了极其温柔的粉色晚霞，心情很好。”）
2. 模拟的系统时间戳（可以手动推进时间，模拟数天或数周过去）。

### 输出
1. **当前记忆状态**：AI 此时此刻还记得什么。
2. **记忆衰退日志**：展示哪些细节被遗忘了，哪些被提炼成了长期情感印记（例如：“Bob 和咖啡已被遗忘。只留下一抹关于粉色晚霞的温柔记忆。”）。

### 技术栈
- Python 3.10+
- OpenAI API 或 Ollama (本地运行 Llama-3-8B)
- SQLite 或 简单的 JSON 文件（作为记忆数据库）

### 第一步怎么做
1. **设计记忆 Node 结构**：
   创建一个 JSON 格式来存储每条记忆：
   ```json
   {
     "id": 1,
     "timestamp": 1710000000,
     "content": "今天和 Bob 在街角喝了咖啡...",
     "emotional_intensity": 0.8, 
     "decay_rate": 0.1,
     "recall_count": 1
   }
   ```
2. **编写衰退算法**：
   写一个简单的数学函数：`current_strength = emotional_intensity * exp(-decay_rate * (current_time - timestamp))`。
3. **编写“睡眠固化”Prompt**：
   当 `current_strength` 低于某个阈值（例如 0.4）时，触发 LLM：
   *“你是一个正在失去记忆的脑海。以下是一段模糊的记忆：[Content]。请抹去其中不重要的细节（如具体的人名、地点、无聊的日常），只保留最核心的情感体验或视觉意象，将其压缩至 15 字以内。”*
4. 运行脚本，手动将时间推进 30 天，观察你的日记是如何慢慢变成一首朦胧的散文诗的。
