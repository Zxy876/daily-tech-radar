## 1. Kanbots - 跑在看板卡片上的并行 Agent 空间
- **来源**：Hacker News Best
- **链接**：https://www.kanbots.dev/
- **一句话解释**：一个开源的桌面看板（Kanban）应用，最硬核的是：**它的每一个卡片都是一个可以并行运行的 AI Agent**。
- **它为什么重要**：它彻底颠覆了“对话框式”的 Agent 交互（HCI）。它把任务管理（Kanban）和 Agent 编排（Orchestration）完美融合。你不再是通过打字命令 Agent，而是通过拖拽卡片、配置卡片属性来编排一个“流水线工厂”。
- **技术趋势标签**：HCI, Agent UI, Task Orchestration, Desktop App
- **可复用模式**：**卡片即 Agent (Card-as-an-Agent)**。将任务的生命周期（To Do -> Doing -> Done）直接映射为 Agent 的状态机和执行逻辑。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个本地 Markdown 文件夹，用 Python 监听文件变化。你只要新建一个 `translate.md` 拖进 `Doing` 文件夹，后台 Agent 自动翻译并把结果写回文件，然后自动把文件移动到 `Done` 文件夹。
  2. **一个中型项目**：*“Game Loop Kanban”*。一个游戏策划画布，卡片代表游戏里的 NPC 决策。把“寻找水源”卡片拖到“NPC_01”卡片下方，NPC 就会在后台模拟执行，并实时在看板上输出它的生存日志。
  3. **一个艺术/游戏/叙事方向**：*“多线叙事碰撞机”*。看板的每一列代表一个平行宇宙，卡片是角色。Agent 在卡片里自行演化。当你把“罗密欧”卡片从 A 宇宙拖到 B 宇宙（朱丽叶所在的列）时，触发跨时空剧情碰撞，自动生成新的剧本。
- **对我项目的启发**：极度启发你的 **spec-driven development**。你可以用看板卡片作为 Spec 的容器，卡片在不同状态间流转，就是 Spec 被逐步细化、生成、测试并最终交付的过程。
- **今天是否值得深入研究**：是
- **建议行动**：做demo（去他们的官网或 GitHub 看看他们是如何处理卡片之间的数据流和上下文继承的）。

## 2. andrej-karpathy-skills (CLAUDE.md) - 开启 Agent 编程的“物理外挂”
- **来源**：GitHub Trending
- **链接**：https://github.com/multica-ai/andrej-karpathy-skills
- **一句话解释**：基于大神 Andrej Karpathy 对 LLM 编程痛点的观察，提炼出的单文件 `CLAUDE.md`，用于规范和提升 Claude Code 的编码行为。
- **它为什么重要**：这是最极致的“上下文工程”（Context Engineering）。你不需要写任何复杂的 Python/TS 代码，只需要在项目根目录下放一个 `.md` 规范，就能让强力 Agent 瞬间“听话”，避免它陷入死循环、写出冗余代码或破坏已有系统。
- **技术趋势标签**：LLM Toolchain, Spec-driven, Context Engineering
- **可复用模式**：**规则锚定文件 (Anchor Spec File)**。在项目根目录下放置特定命名协议，让进入该目录的 AI 协同工具自动读取并严格遵守。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 `CREATIVE_CODING.md` 扔进你的 p5.js 项目，强制 Claude 在帮你写交互代码时，必须遵循特定的“包豪斯”色彩美学和数学曲线公式。
  2. **一个中型项目**：*“Agent 角色格斗场”*。在一个代码库里放入不同的 `CLAUDE_PROFILES`。通过脚本动态切换 `CLAUDE.md`，让同一个 Claude 扮演“极客黑客”和“保守架构师”，对同一段代码进行极限拉扯和重构。
  3. **一个艺术/游戏/叙事方向**：*“物理世界规则书”*。在你的世界生成系统（如 Minecraft 插件目录）中放入一个 `WORLD_RULES.md`。任何进入该目录生成地形或 NPC 行为的 AI 必须先读取此规则，从而决定这个世界的物理常数（比如“重力是反的”）。
- **对我项目的启发**：你的 spec-driven 流程可以直接通过这种“声明式文件”来实现。让 Spec 不仅是文档，更是直接规训 AI 的“法律”。
- **今天是否值得深入研究**：是
- **建议行动**：试用（直接把这个 `CLAUDE.md` 复制到你当前最头疼的代码库里，用 Cursor/Claude 提问，体验它的行为变化）。

## 3. GitNexus - 浏览器里的无服务器代码知识图谱
- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/abhigyanpatwari/GitNexus
- **一句话解释**：一个纯客户端运行、零服务器配置的代码知识图谱生成器，拖入 GitHub 仓库或 ZIP，就能在浏览器里生成交互式 3D 图谱，并用内置的 Graph RAG Agent 进行探索。
- **它为什么重要**：它把复杂的 Graph RAG 和重度可视化完全搬到了浏览器前端。对于设计/艺术背景的你来说，这种“所见即所得”的视觉化代码理解工具，是极佳的 HCI 范例。它证明了：**复杂的 AI 检索不需要笨重的后端，纯前端就能给用户极佳的探索体验。**
- **技术趋势标签**：HCI, Graph RAG, Creative Coding, Serverless AI
- **可复用模式**：**纯前端图谱检索 (Serverless Client-side Graph RAG)**。利用 Web Workers 或 WebAssembly 在浏览器内完成索引、向量化和 3D 可视化。
- **疯狂发明家灵感**：
  1. **一个小实验**：把一个复杂的 p5.js 或 Three.js 创意代码库拖入 GitNexus，看看它是如何把函数调用关系变成视觉星系的，尝试找出视觉上最孤立的那个“无用函数”。
  2. **一个中型项目**：*“Narrative Graph Explorer (故事图谱探索器)”*。拖入一部小说的章节 Markdown（或游戏剧本），自动生成角色关系和事件流的交互图谱，并用内置 Agent 问答：“如果 A 在第三章没有去酒馆，图谱会怎么变？”
  3. **一个艺术/游戏/叙事方向**：*“代码生态繁衍”*。将你的代码库变成一个“数字花园”。代码中的每个类和函数是一个植物，调用关系是藤蔓，GitNexus 的图谱就是你的代码生态系统，玩家可以在这个 3D 花园里漫步，通过浇水（调用）来让特定的代码节点生长。
- **对我项目的启发**：可视化是降低 AI 焦虑、增强人类掌控感（Agency）的关键。在设计 Agent 工具链时，不要只给用户一个 Loading 动画，给他们一个动态生长的知识图谱。
- **今天是否值得深入研究**：是
- **建议行动**：做demo（把自己的一个跨学科项目拖进去，看看它生成的图谱长什么样，体验一下它的 Graph RAG 问答）。

## 4. Midscene - 视觉驱动的 UI 自动化黑客工具
- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/web-infra-dev/midscene
- **一句话解释**：基于 AI 视觉的跨平台 UI 自动化工具，用自然语言和视觉理解（而不是脆弱的 DOM 选择器）来操控和测试任何界面。
- **它为什么重要**：传统的网页自动化（如 Puppeteer/Playwright）依赖于复杂的 HTML 标签定位，一旦网页改版就崩溃。Midscene 走的是“人类路线”：**它用眼睛看，用脑子想，然后动手点**。这为“Agent 操控人类软件”提供了一条极其宽广的非侵入式道路。
- **技术趋势标签**：AI Automation, Vision-driven UI, HCI, Creative Tool
- **可复用模式**：**视觉锚定定位 (Vision-anchored Interaction)**。不看代码结构，只看界面长相来执行交互。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 50 行的脚本，让 Agent 每天自动登录一个艺术灵感网站（如 Are.na 或 Pinterest），不用任何 API，仅靠视觉识别找到最亮眼的图片并自动下载保存。
  2. **一个中型项目**：*“AI 网页寻宝游戏”*。一个游戏，AI Agent 必须在未知的网页中，通过视觉寻找特定的视觉隐喻（比如“一个看起来像悲伤的按钮”或“一只隐藏的猫”），最快找到并点击的 Agent 获胜。
  3. **一个艺术/游戏/叙事方向**：*“The Glitched Automator (故障自动化装置)”*。一个艺术装置：Agent 试图自动化操作一个复杂的网页（比如填写无尽的表单），但由于屏幕上不断产生随机的视觉干扰（Glitch），Agent 必须不断调整其视觉理解来应对这些混乱，展现 AI 在混沌中的挣扎。
- **对我项目的启发**：这启发了“非侵入式”的创作工具。你可以让 Agent 去操控那些没有 API 的老旧设计软件或网页（比如一些古老的在线合成器），通过视觉识别界面并自动调音。
- **今天是否值得深入研究**：是
- **建议行动**：试用（安装并写一个简单的脚本，让它帮你想办法自动抢一张 Livehouse 的票或者自动化完成一项日常的网页重复工作）。

## 今日模式总结

今天我们看到了两个极具生命力的技术模式：
1. **规约锚定 (Context/Spec Anchoring)**：如 `CLAUDE.md`，通过极度精简的本地规约文件直接规训 Agent，避免了复杂的 Prompt 链和后端开发，让“规范”成为第一生产力。
2. **具象化空间编排 (Spatial Agent Orchestration)**：如 Kanbots 和 GitNexus，不再让 Agent 隐藏在黑盒或聊天框里，而是将其生命周期、关系和执行过程具象化为看板卡片、知识图谱等空间实体。

## 今日可做小实验：CLAUDE.md 驱动的“包豪斯”赛博画家

我们用今天学到的 **规约锚定模式**，在 2 小时内做一个好玩的小实验。

- **项目名**：CLAUDE.md-driven Cyber Painter
- **输入**：一个极其简陋的 HTML 页面，和一个包含审美规约的 `CLAUDE.md` 文件。
- **输出**：Claude Code (或 Cursor) 自动为你生成并快速迭代一个符合特定先锋艺术风格的 p5.js 动态交互画布。
- **技术栈**：Cursor 或 Claude Code, p5.js, Node.js (本地 server)
- **第一步怎么做**：
  1. 在一个空文件夹里创建 `CLAUDE.md`，写入以下“硬核美学规约”：
     ```markdown
     # Creative Coding Rules
     - Framework: p5.js (loaded via CDN in index.html)
     - Aesthetic: Bauhaus (Strictly use only: #E63946 (Red), #F1FAEE (White), #A8DADC (Light Blue), #457B9D (Dark Blue), #1D3557 (Navy). Strong geometric shapes only.)
     - Interaction: Must respond to mouse movement with organic easing.
     - Code structure: Keep setup() and draw() clean. Use modular functions. Never delete the canvas container.
     ```
  2. 在同目录下创建一个空的 `index.html`。
  3. 打开 Cursor 或 Claude Code，在聊天框中输入一句极其模糊且不负责任的指令：“*帮我在 index.html 里写一个好看的交互画布。*”
  4. **见证奇迹**：观察 AI 是如何瞬间读取并严格遵守你的 `CLAUDE.md` 规约，写出极其符合包豪斯风格、且结构优雅的代码，而不是给你一段烂大街的彩色小球特效。
