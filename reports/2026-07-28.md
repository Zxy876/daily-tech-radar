## [1] LeAct：用游戏引擎和规则规划器训练 LLM 逻辑推理
- 来源：arXiv cs.LG
- 链接：https://arxiv.org/abs/2607.21856
- 一句话解释：不靠人类标注或强模型蒸馏，而是让大模型直接从游戏引擎、经典规划器（Planner）等确定性“专家系统”生成的最佳动作轨迹中学习推理。
- 它为什么重要：过去的 CoT（思维链）依赖文本推演，容易产生“幻觉”。但现实世界和游戏世界中的物理引擎、A*算法、图论规划器是 100% 准确的。用确定性规则生成的轨迹来“教”LLM，打通了“世界模型/游戏规则”与“LLM 推理”的闭环。
- 技术趋势标签：#GameSystems #LLM推理 #确定性引擎 #世界模型
- 可复用模式：**确定性系统生成动作轨迹 -> 转换为自然语言思考过程 -> 训练/引导 LLM 的逻辑推演能力**。
- 疯狂发明家灵感：
  1. *一个小实验*：写一个 Sokoban（推箱子）算法解算器，自动把求解出的路径转化为“解题思路 Prompt”，测试这能否显著提升小模型求解逻辑 puzzle 的能力。
  2. *一个中型项目*：Minecraft 红石电路/建筑解算 Agent：用算法求解红石逻辑门，导出为思维步骤，训练出一个能直接口述“如何搭建红石自动化农场”的红石工程师 AI。
  3. *一个艺术/游戏/叙事方向*：基于逻辑规划的“戏剧冲突生成器”——利用传统叙事规划器（如 STRIPS）生成绝对合理的剧情冲突路径，再让 LLM 赋予其充满文学色彩的对话与氛围。
- 对我项目的启发：解决在游戏生成或 Agent 决策中 LLM 容易“瞎编”的问题——永远用一个底层的数学/游戏规则系统做 Validation 和轨迹输入。
- 今天是否值得深入研究：是
- 建议行动：做demo

## [2] ruflo：多智能体蜂群的元调度与自适应记忆框架
- 来源：GitHub Trending TypeScript
- 链接：https://github.com/ruvnet/ruflo
- 一句话解释：一个支持多智能体蜂群（Swarm）协作的调度框架，支持自适应记忆、动态 RAG，并原生适配 Claude Code 和 Codex 等 CLI 工具链。
- 它为什么重要：Agent 开发正在从“单 Agent 调工具”演进为“多 Agent 团队（Swarm）”。此项目极其贴合 Spec-Driven 开发逻辑，把任务拆解、记忆管理和终端执行高度整合。
- 技术趋势标签：#AgentWorkflow #MultiAgent #ClaudeCode #SpecDriven #Swarm
- 可复用模式：**蜂群任务分发 + 共享自适应上下文/记忆 + CLI 原生工具链执行**。
- 疯狂发明家灵感：
  1. *一个小实验*：配置两个 Claude Agent，一个负责根据自然语言需求实时更新 `spec.md`，另一个监控 Spec 变更并自动用 CLI 运行测试与修正。
  2. *一个中型项目*：自治游戏关卡生成工厂：策划 Agent 提出世界观，逻辑 Agent 写机制，结构 Agent 生成 Minecraft/Unity 场景文件，测试 Agent 在模拟器跑通并提交报告。
  3. *一个艺术/游戏/叙事方向*：生成式“虚拟剧组”工作流：导演、编剧、美术指导三个 Agent 在后台自动展开剧本围读，实时把碰撞出的变奏剧本与场景 Prompt 渲染到前端页面。
- 对我项目的启发：可以作为自身 Spec-driven 自动化开发工作流的底层调度工具，省去重造多 Agent 协作和 CLI 通信轮子的时间。
- 今天是否值得深入研究：是
- 建议行动：试用

## [3] LLM 算命/玄学行为分析：当生成式 AI 成为文化与不确定性介质
- 来源：arXiv cs.HC
- 链接：https://arxiv.org/abs/2607.15626
- 一句话解释：深入研究人类如何利用 LLM 进行算命、塔罗和玄学占卜，分析 LLM 作为“不确定性消除工具”对人类心理和决策的深远影响。
- 它为什么重要：从 HCI 与新媒体艺术的角度看，算命本质上是一种**“基于不确定性的叙事交互系统”**。LLM 的核心优势不仅是回答事实，而是“心理投射与冷读（Cold Reading）”，这对设计游戏叙事和交互艺术极具启发。
- 技术趋势标签：#HCI #GenerativeNarrative #CreativeCoding #CulturalAI #ArtTech
- 可复用模式：**模糊性输入 -> 心理投射引导 -> 结构化剧情/隐喻输出（Cold Reading AI）**。
- 疯狂发明家灵感：
  1. *一个小实验*：结合系统时钟与鼠标轨迹熵生成“赛博易经”，将物理随机数转化为带有生成式代码视觉的冷读（Cold Reading）叙事。
  2. *一个中型项目*：交互式心理游戏《命运编译器》：玩家输入代码或文字，AI 根据隐喻生成一个“规则与命运图景”，玩家需要通过重构逻辑来反抗 AI 预设的结局。
  3. *一个艺术/游戏/叙事方向*：新媒体艺术装置《AI 预言社》：利用 LLM 模拟不同历史时期的占卜师，在空间中与观众语音对谈，探讨AI时代人类对“确定性”的病态依赖。
- 对我项目的启发：生成式系统的魅力往往不在于“绝对正确”，而在于“隐喻性”和“戏剧性”。可以把这种心理投射机制引入游戏 NPC 的对话系统中。
- 今天是否值得深入研究：是
- 建议行动：收藏

## [4] open-code-review：确定性 Pipeline + LLM Agent 的混合代码审查架构
- 来源：GitHub Trending
- 链接：https://github.com/alibaba/open-code-review
- 一句话解释：阿里开源的混合架构代码审查工具，将“确定性静态分析管道（Pipeline）”与“LLM Agent”相结合，提供精准的行级审查。
- 它为什么重要：“纯 LLM”缺乏严谨性且有幻觉，而“纯规则”缺乏语义理解。这种**“确定性规则守底线 + LLM Agent 处理语义”**的混合架构（Hybrid Architecture），是目前构建可靠自动化工具链的最佳范式。
- 技术趋势标签：#SpecDriven #Automation #HybridArchitecture #AgentWorkflow #CodeToolchain
- 可复用模式：**确定性静态规则过滤 -> LLM 语义分析与意图对齐（双层防护网）**。
- 疯狂发明家灵感：
  1. *一个小实验*：写一个 Markdown 规范（Spec）检查器，先用正则检测结构语法是否缺失，再将通过的内容传给 LLM 检查语义逻辑是否有矛盾。
  2. *一个中型项目*：游戏关卡配置文件自动修正器：用 AST 语法树解析 Unity/Minecraft 配置文件，触发异常时让 LLM Agent 尝试修改并自动提交 PR。
  3. *一个艺术/游戏/叙事方向*：创意编程（Creative Coding）代码审美评估器：用 P5.js/Shader 解析器先过滤掉语法死循环，再让 LLM 评估其视觉隐喻，并自动微调艺术参数。
- 对我项目的启发：构建 Spec-Driven 自动开发系统时，切忌把所有事情打包抛给 LLM，必须建立“确定性程序过滤 + LLM 语义生成”的架构。
- 今天是否值得深入研究：是
- 建议行动：试用

## 今日模式总结

1. **确定性与生成式的共生（Hybrid Deterministic-LLM Architecture）**：
   无论是用游戏引擎/规划算法来训练 LLM 推理（LeAct），还是用静态代码分析管道为 LLM 打底（open-code-review），**“用传统规则做硬约束，用 LLM 做软理解”**已经成为当前 AI 工具与系统设计的核心模式。
2. **终端原生与多 Agent 蜂群化（Swarm Agents in CLI）**：
   Agent 正在脱离浏览器对话框，通过终端 CLI 工具（如 Claude Code）深度嵌入系统，并从“单兵作战”向“自适应记忆的多 Agent 蜂群（ruflo）”演进。

## 今日可做小实验

**项目名称**：《赛博求签器：物理随机数与 LLM 冷读卡牌生成》 (Cyber Divination Terminal)

* **输入**：用户当前的一句困惑 + 鼠标移动轨迹算出的物理随机 Seed。
* **输出**：一个在终端（或网页 Canvas）渲染的 ASCII/极简图形卡牌，附带一段由 LLM 生成的带有玄学隐喻的冷读文本。
* **技术栈**：Node.js / Python + OpenAI/Claude API + 简单的 ASCII 渲染库。
* **第一步怎么做**：
  1. 写一段 15 行的脚本，监听鼠标移动坐标或键盘打字时间间隔，计算出一个熵值并映射为一个随机符号（例如：“0x04-溢出之塔”）。
  2. 编写 Prompt：“你是一个运行在废土系统中的 AI 占卜师。请结合随机符号 [Seed_Name] 与用户的困惑 [Input]，用冷读（Cold Reading）技巧生成一段不超过 100 字的赛博占卜预言，并附带 3 行代表该卡牌的 ASCII Art。”
  3. 在终端运行它，体会物理随机性与 LLM 文本隐喻结合带来的有趣体验。
