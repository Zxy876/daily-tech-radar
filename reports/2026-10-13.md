## 1. MathVis: Can AI Reason through Drawing? (以图推演的中间表征系统)
- **来源：** arXiv cs.AI
- **链接：** https://arxiv.org/abs/2610.12954
- **一句话解释：** 验证 LLM 能否不靠纯文字、而是通过生成可执行的 TikZ/SVG 代码与中间表征（IR）边画图边完成复杂推理。
- **它为什么重要：** 传统的思维链（Chain of Thought）是纯自然语言的，但人类艺术家和架构师依靠“草图（Sketching）”来降低认知负荷。将绘图代码（SVG/TikZ）作为一种*可执行的推理步骤*，打开了多模态生成式推理的新接口。
- **技术趋势标签：** `Visual-Reasoning`, `Code-as-Thought`, `SVG/TikZ`, `Creative Tool`
- **可复用模式：** **草图即状态机（Sketch-as-State）**。在让 LLM 做出决策前，强制它先输出一个参数化的矢量图（SVG/Canvas）作为工作记忆区，再基于该图形的状态做出逻辑裁决。
- **疯狂发明家灵感：**
  1. **一个小实验：** 一个自动生成 ASCII/SVG 架构图的 CLI：写需求时，LLM 先画架构拓扑图，再根据拓扑图生成规范文档（Spec）。
  2. **一个中型项目：** **Diagram-First Spec Generator**：设计一个给艺术程序员用的 IDE 插件，输入自然语言交互逻辑，AI 先画出状态机图表与连线，用户在画布上手工连线调整，再一键反编译出运行代码。
  3. **一个艺术/游戏/叙事方向：** **“盲人地牢生成器”**：Agent 玩文字 MUD 游戏时，必须实时在后台输出自身认知的地牢 SVG 地图。玩家看到的不是文本，而是 Agent 脑中“逐步扭曲或清晰”的地图绘制过程。
- **对我项目的启发：** 非常适合融入 Spec-driven 流程——未来的 Spec 不必是纯 Markdown，可以是 LLM 边画边改的动态图纸系统。
- **今天是否值得深入研究：** 是
- **建议行动：** 做demo

## 2. EvoBelief: Falsifiable World Models for Self-Improving LLM Agents (可证伪的 Agent 动态世界观)
- **来源：** arXiv cs.AI
- **链接：** https://arxiv.org/abs/2610.12789
- **一句话解释：** Agent 不仅积累经验，还会在运行中构建并实时“证伪/推翻”自己关于物理或环境规则的信念（World Model）。
- **它为什么重要：** 现有的 Minecraft 或游戏 Agent 大多依赖硬编码的环境物理规则。EvoBelief 允许 Agent 在被“烫到”或“摔死”后，动态修改其核心信念表（可证伪的假设体系），这是具有真正涌现式生命感 NPC 的核心。
- **技术趋势标签：** `World-Model`, `Agent-Belief`, `Emergent-Behavior`, `Minecraft/Game`
- **可复用模式：** **假设-验证世界观字典（Hypothesis-Falsification Registry）**。将 Agent 的决策驱动力解耦为独立的“当前世界规则假设”，每次行动失败不是重试，而是触发对该假设的降级与篡改。
- **疯狂发明家灵感：**
  1. **一个小实验：** 在一个简易 2D Grid 迷宫中，给 Agent 一个错误的物理常识（比如“水可以穿透，火不会死”），记录它尝试多少步后自己改写出正确的物理 Spec。
  2. **一个中型项目：** **Minecraft“外星探险家”NPC**：把 NPC 扔进装满未知 Mod 的 Minecraft 世界，它不带 Wiki 知识库，完全靠尝试、死亡、更新规则字典来画出自己的《生存百科指南》。
  3. **一个艺术/游戏/叙事方向：** **妄想症叙事生成器**：一个侦探推理游戏，侦探 Agent 会形成荒谬但内部自洽的规则假设（“红衣服的人说话必定是谎言”），玩家的目标不是破案，而是通过设计事件去“证伪”Agent 的偏见与妄想。
- **对我项目的启发：** 对自动化系统的容错机制很有帮助：让系统不再报 `500 Retry`，而是让 Agent 主动推翻对当前 API 接口特性的“幻觉认知”。
- **今天是否值得深入研究：** 是
- **建议行动：** 试用

## 3. Work2Skill: Capturing Human GUI Experience for Reusable Agent Skill Induction (人类操作提炼为通用操作原语)
- **来源：** arXiv cs.AI
- **链接：** https://arxiv.org/abs/2610.12984
- **一句话解释：** 录制人类在 GUI 软件上的操作演示，自动剔除偶然数据，将其解构提炼为可复用、跨场景的 Agent 技能动作流（Procedural Skill）。
- **它为什么重要：** 传统的 Computer-use 成本高且随机性大。Work2Skill 提供了一种机制：将人类在 Blender/Photoshop/TouchDesigner 等复杂界面的行为，提炼成确定性的、状态驱动的“技能树”。
- **技术趋势标签：** `GUI-Agent`, `Procedural-Knowledge`, `Macro-Induction`, `HCI`
- **可复用模式：** **操作行为抽象化（Trace-to-DSL Pipeline）**。从 UI 坐标/点击事件流中，抽象出带有前后置断言（Pre/Post-conditions）的代码化工作流。
- **疯狂发明家灵感：**
  1. **一个小实验：** 录屏自己做一段 Figma 排版，用多模态模型把录屏拆解为标准操作步骤（Step-by-step UI 规范）。
  2. **一个中型项目：** **Creative-Tool Macro Synthesizer**：一个本地守护进程，观察你在 Blender/MaxMSP 里的重复性鼠标动作，自动用 Python/节点生成一个定制的“一键宏插件”。
  3. **一个艺术/游戏/叙事方向：** **“人类习惯标本馆”**：抓取不同数字艺术家使用画布的手势流数据，提取出他们的“数字作画直觉”，让不同的 AI 画家 Agent 继承这些习惯并在画布上互动打架。
- **对我项目的启发：** 对于设计开发工作流（Drift/Agent Workflow）而言，将人的经验变成标准 Spec 的过程不再需要手写，可以直接从“屏幕演示”反推生成。
- **今天是否值得深入研究：** 是
- **建议行动：** 收藏

## 4. SpireBench: Evaluating Long-Horizon Strategic Play of Agentic Models with Slay the Spire (杀戮尖塔长程战略基准)
- **来源：** arXiv cs.AI
- **链接：** https://arxiv.org/abs/2610.12596
- **一句话解释：** 用商业卡牌构建 Roguelike 游戏《杀戮尖塔》（Slay the Spire）作为环境，专门压测和评估 Agent 处理长程决策、组合构建和运气波动的能力。
- **它为什么重要：** 这是游戏系统（Game Systems）与 Agentic 架构交汇的绝佳标本。游戏包含巨大的组合状态空间（遗物、卡组、路线规划），迫使系统在战术执行（单卡使用）与长期战略（流派构筑）之间保持一致。
- **技术趋势标签：** `Game-AI`, `Long-Horizon`, `Deckbuilder`, `Emergent-Strategy`
- **可复用模式：** **双层规划架构（宏观战略 Spec + 微观战术 Agent）**。上层维护构筑意图（Build Intent），下层维护状态转移，防止长文本推理过程中的“战略漂移”。
- **疯狂发明家灵感：**
  1. **一个小实验：** 接入《杀戮尖塔》开源模拟器，写一个最简 Agent，让它仅基于卡组语义解释输出“当前成型流派”的自述卡片。
  2. **一个中型项目：** **Roguelike 规则自动平衡器（AI Playtester）**：给自研的桌面卡牌或策略小游戏接入此 Agent 框架，让数个不同性格的 Agent 自动对战 1000 局，自动汇报哪个卡牌组合破坏了游戏生态。
  3. **一个艺术/游戏/叙事方向：** **“命运赌徒”生成式戏剧**：把一个完整的卡牌游戏跑测过程实时翻译成文字史诗：一张普通牌的获得被渲染成命运转折点，Agent 的生命值起伏直接驱动生成古典悲剧剧本。
- **对我项目的启发：** 如果要做复杂游戏系统或世界生成，这个论文里的环境抽象层（游戏状态序列化为结构化 prompt）是极佳的代码脚手架。
- **今天是否值得深入研究：** 是
- **建议行动：** 收藏

## 今日模式总结

1. **图元/草图作为高维推理中间件（Code/Visual Intermediate Representation）：**
   纯文本不是 Agent 的终极边界。通过可渲染代码（SVG、TikZ、Graphviz）将结构化关系画出来，反倒大幅降低了模型的推理错误率。
2. **假设驱动的动态世界观（Dynamic Belief Maintenance）：**
   环境不再是静态 Prompt 注入的背景板，而是可被实验、可被失败推翻的假设网络（Hypothesis Engine），这正是自主 NPC 和长程自动化的核心驱动机制。

## 今日可做小实验：SVG 思维链涂鸦板 (SVG-Chain-of-Thought)

**目标：验证 LLM 在输出代码前“先画图”是否能带来完全不同的设计逻辑。**

- **项目名：** `SVG-Pencil-Thinker`
- **输入：** 一段带有拓扑结构的设计需求（例如：“一个拥有 3 个独立岛屿、中央有一个发光灯塔，且岛屿间通过隐形传送带连接的低多边形游戏场景生成 Spec”）。
- **输出：**
  1. 一个原生的 `output.svg` 文件（展示该场景的顶视图草图架构）；
  2. 基于这张 SVG 中各个图形的 `<circle>` / `<rect>` 坐标生成的最终场景 Spec（JSON）。
- **技术栈：** Node.js 或 Python + Anthropic/OpenAI API + 本地浏览器（直接预览 SVG）。
- **第一步怎么做：**
  1. 新建 `sketch_prompt.py`。
  2. 设定 System Prompt：“你是一个视觉逻辑推理引擎。解决空间布局问题时，你**严禁直接回答**。你必须先在 `<sketch>` 标签中输出一段干净的 500x500 像素 SVG 代码绘制布局构想，然后再基于该 SVG 元素属性提取 JSON 配置”。
  3. 运行代码，将返回的 SVG 写入本地 `view.html` 查看 AI 的“草图推理过程”。用时不超过 40 分钟。
