## Spatial Memory Agent: 空间程序记忆系统
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2608.12743
- 一句话解释：让 Agent 不仅记住“这里有什么”，而是建立一套基于经验沉淀的“空间操作程序记忆（Procedure Memory）”。
- 它为什么重要：过去做 Minecraft 或 3D 游戏 Agent，通常要么靠纯视觉 VLM 硬看，要么靠固定的符号路网。这项研究将空间记忆 procedural 化——Agent 记下的是空间拓扑与行动序列的复合经验，大幅提升空间推理与规划效率。
- 技术趋势标签：`Spatial Intelligence` `Embodied AI` `Procedural Memory` `Game AI`
- 可复用模式：**拓扑图 + 动作宏（Action Macro）缓存**。不仅记录空间坐标，还记录从 A 到 B、如何在特定地形下搭建结构的动作配方。
- 疯狂发明家灵感：
  1. **一个小实验**：在 Minecraft (Mineflayer) 中，让 Agent 探索一个未知洞穴，自动将“如何搭跳板跨过岩浆”沉淀为一个可复用的空间动作 Macro。
  2. **一个中型项目**：3D 生成式关卡自适应探险家：输入任意生成的 3D 地牢 mesh，Agent 自动探索并在盲区留下“空间指引路标”与解谜脚手架。
  3. **一个艺术/游戏/叙事方向**：“记忆遗迹”互动装置——NPC 的记忆体随着玩家破坏/重建环境而产生认知失调与即兴应变，玩家通过改造空间来篡改 NPC 的生存程序。
- 对我项目的启发：为 Minecraft/3D 世界生成系统引入“空间经验缓存”，使生成器或 Agent 无需每次从零用 LLM 计算路径与建造语法。
- 今天是否值得深入研究：是
- 建议行动：做demo

## Beyond Retrieval: 轨迹记忆的动态重用 (Query-Conditioned Reuse)
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2608.12847
- 摘要：Agent 检索到历史轨迹不等于能直接用，论文提出了在实体、约束和环境状态变化后，如何“条件化重组与重用”长周期轨迹的方法。
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2608.12847
- 一句话解释：解决了 Agent “记住了以前怎么做，但环境稍微一变就抓瞎”的泛化重用难题。
- 它为什么重要：传统 RAG 和 Agent Memory 只管检索（Retrieve），不管突变适应（Adapt）。本研究将重点放在**检索后的轨迹参数化重构**上，这是长周期 Agent 可靠性的核心拼图。
- 技术趋势标签：`Agent Trajectory` `Memory Adaptation` `Spec-Driven Workflow`
- 可复用模式：**轨迹 AST 变量解耦与重绑定**。将历史执行链路抽象成带有插槽的流程模板，新任务输入时只替换变量与局部分支，而非重新规划。
- 疯狂发明家灵感：
  1. **一个小实验**：把一次成功的 Figma 导出或 Blender 建模操作记录提取为 JSON 轨迹，换一个全新的资产需求，让 LLM 只做“差分修补”重放操作。
  2. **一个中型项目**：Spec-Driven 代码重构 Agent——记录一次复杂的跨文件重构轨迹，迁移并在另一个架构相似但业务不同的仓库上重演。
  3. **一个艺术/游戏/叙事方向**：分支叙事“命运重演”引擎——将一个角色的悲剧一生记录为 Trajectory，玩家通过在关键节点修改一个环境变量，观察整个轨迹的自愈与级联偏转。
- 对我项目的启发：在设计自动化流程中，不要每次都让 LLM end-to-end 重新生成，提取成功 Run 的 AST 轨迹进行 Conditioned Reuse 成本更低且极稳。
- 今天是否值得深入研究：是
- 建议行动：做demo

## @skills: 突破 System Prompt 技能插槽危机的动态分发机制
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2608.12610
- 一句话解释：指出将成百上千个 Agent 技能硬塞进 System Prompt 必然导致注意力衰减，提出了一种按需寻址的技能动态激活协议。
- 它为什么重要：社区工具狂欢导致大家写了上万个 Agent Skill，但模型的 Context Attention 是有限的。当技能超过几十个，Trigger 准确率暴跌。这个研究直接切中了当今 Agent 基础设施的瓶颈。
- 技术趋势标签：`Agent Tooling` `Dynamic Routing` `Prompt Optimization` `HCI`
- 可复用模式：**两级分发器模式（Two-Stage Dispatcher）**：主 Agent 仅挂载轻量级的技能路由器（Router Specs），真正执行时才向上下文即时 JIT 注入完整 Skill Spec。
- 疯狂发明家灵感：
  1. **一个小实验**：用 Bash/Python 写一个本地路由代理，把本地 50 个 CLI 工具的文档做语义索引，只有当 LLM 提及相关意图时才把工具 schema 贴入 prompt。
  2. **一个中型项目**：模块化创意工具链 OS：允许艺术家用自然语言编写无限个微脚本（如“把选中音频反相”、“生成噪波着色器”），系统自动管理注意力分配与动态插拔。
  3. **一个艺术/游戏/叙事方向**：一个拥有几千种人格碎片的虚拟神明，随玩家对话情绪仅动态“降临”特定子人格与词汇表，产生不可预测的通灵体验。
- 对我项目的启发：构建 Spec-driven Agent 时，彻底抛弃“巨石型（Monolithic）System Prompt”，改用类似 MCP (Model Context Protocol) 的 JIT 按需装载机制。
- 今天是否值得深入研究：是
- 建议行动：试用

## citrolabs / ego-lite: 零配置无缝接管已登录状态的 Agent 浏览器
- 来源：GitHub Trending
- 链接：https://github.com/citrolabs/ego-lite
- 一句话解释：专门为 Claude Code、Codex 等本地命令行 Agent 设计的超轻量浏览器，能直接复用你日常已登录的 Cookie 与会话，完全不打扰正常使用。
- 它为什么重要：做 Agent 自动化最大的痛点是验证码、双重认证和登录态隔离。ego-lite 抹平了开发者工作流与 Agent 执行环境之间的壁垒，让 Agent 能够真正无摩擦地调取你授权的 Web 生态。
- 技术趋势标签：`Browser Automation` `Agent HCI` `Developer Tools` `Local Agent`
- 可复用模式：**Session Shadowing（会话影子复用）**。Agent 在后台以无头/轻量方式共享主浏览器上下文，无需频繁配置环境变量中的 API Token。
- 疯狂发明家灵感：
  1. **一个小实验**：让 Claude Code 通过 ego-lite 自动抓取你私人 Arena/Pinboard 收藏夹中的艺术灵感图，自动喂给 ComfyUI 批量生成。
  2. **一个中型项目**：一键式跨平台创作工作流 Agent——直接在命令行里让 Agent 读取你的 Notion 灵感库、写成 Twitter/Are.na 草稿并自动完成排版。
  3. **一个艺术/游戏/叙事方向**：“幽灵创作者”实验——Agent 观察你的日常浏览痕迹（已授权范围），每天半夜根据你白天看过的视觉碎片，自动合成并发布一本排版前卫的纯数字“潜意识杂志”。
- 对我项目的启发：将本地 Agent 的工具链打通到已登录的 Web 生态中，极大降低做真实自动化工作流的摩擦力。
- 今天是否值得深入研究：是

## 多重约束下的相变失效：LLM 的组合规则崩溃临界点
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2608.12426
- 一句话解释：研究揭示了当多条格式、推理结构、安全限制等约束同时施加给 LLM 时，其性能会发生断崖式下跌的“相变（Phase Transition）”现象。
- 它为什么重要：在做生成式系统、游戏规则判定和 Spec-driven 架构时，我们习惯在 Prompt 里写“规则 1、规则 2……规则 10”。该论文从理论和实验上证明了这种做法的危险性：约束数量一旦超过阈值，模型不是线性变差，而是直接雪崩。
- 技术趋势标签：`Constraint Satisfaction` `System Prompt Engineering` `Generative Rules`
- 可复用模式：**约束分层级联过滤器（Constraint Pipeline/Gating）**。将多重约束拆解为多个单任务的微步骤，或采用编译原理中的多遍扫描（Multi-pass Parsing）。
- 疯狂发明家灵感：
  1. **一个小实验**：测试自己最常用的生成 Prompt，通过逐步增加负向词与排版约束，绘制出自己常用模型的“崩溃临界点曲线”。
  2. **一个中型项目**：Spec-Linter 约束编译器：输入一个包含几十条游戏/设计规则的复杂 Spec，编译器自动将其拓扑排序，并拆分成一组无损执行的 Agent Pipeline。
  3. **一个艺术/游戏/叙事方向**：一个以“逻辑过载”为核心机制的解谜游戏——玩家通过故意给 AI 法官叠加互相冲突的繁琐律法规则，诱发其产生“幻觉相变”，从而打破原本不可动摇的叙事死局。
- 对我项目的启发：在设计复杂的规则系统（如 Minecraft 地形生成规范、严苛的 UI 生成格式）时，坚决不能把规则压在单次 Prompt 里，必须做管线化与约束外置。
- 今天是否值得深入研究：是
- 建议行动：收藏

## 今日模式总结

1. **从“静态检索”到“程序化记忆与重组”（Procedural Memory & Trajectory Reuse）**：
   记忆不再只是把向量库里的文本翻出来，而是提取“动作配方”（Macro）与“可参数化的轨迹”（Trajectory AST），在面对变化环境时做插槽替换与自适应。
2. **上下文空间的“轻量化与动态路由”（Attention Space Decongestion）**：
   无论是针对爆炸的 Agent 技能集（@skills），还是针对过载的规则约束（Phase Transitions），业界正在达成共识：**不能把所有东西塞进单次推理**，必须依赖动态按需注入与流水线过滤。

## 今日可做小实验

### 项目名：`MacroMorph` —— 基于 AST 差分修补的单动作重演器
- **输入**：一段你手动用 Node.js/Python 脚本操作某个设计工具（如用 p5.js 画一个网格，或生成一段特定规则 SVG）的成功执行 Trajectory JSON。
- **输出**：在输入全新尺寸/颜色规则时，LLM 仅输出“修补补丁 (Patch Spec)”，并成功自动运行生成新资产，而不重写整个脚本。
- **技术栈**：Node.js / Python + OpenAI/Anthropic API + 任意轻量绘图库 (Canvas / SVG)。
- **第一步怎么做**：
  1. 写一个极简的 JSON Schema，记录 3 个绘图步骤（如 `[{"action": "draw_rect", "params": {"w": 100, "h": 50}}, ...]`）。
  2. 写一个 Prompt，给它上述 JSON 作为基准轨迹，输入新约束：“把所有的矩形换成圆角，宽度等比放大 1.5 倍”。
  3. 要求模型**仅输出 JSON Patch 格式**（针对键值的替换指令），本地脚本 apply 这个 patch 并即时渲染出图，体验一次零幻觉的 Trajectory Reuse。
