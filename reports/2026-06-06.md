## 1. Beyond Prompt-Based Planning: MCP-Native Graph Planning
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.04494
- **一句话解释**：抛弃扁平的 Prompt 工具描述，利用 Anthropic 的 **MCP (Model Context Protocol)** 协议构建原生图规划代理，解决复杂工具异构与环境隔离问题。
- **它为什么重要**：MCP 正在成为 AI 统一接口的事实标准。这篇文章展示了如何把 MCP 从“单纯的工具调用”升级为“基于图的动态规划”，让 Agent 能够像搭积木一样动态组装和调度复杂的异构工具链。对于做 Spec-driven development 和自动化工具链的你来说，这是绝对的降维打击。
- **技术趋势标签**：`MCP-Native` / `Graph-Planning` / `LLM-Toolchain` / `Spec-Driven`
- **可复用模式**：**MCP-as-Graph-Node**：将每个 MCP 服务（如本地文件读写、Blender 接口、API）视为图中的一个节点，Agent 不再通过 Prompt 挑选工具，而是通过图遍历和拓扑排序来生成执行流。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个本地 MCP Server，将你本地的 Figma 文件结构或 p5.js 画布状态暴露给 Claude，让 Claude 能够直接对画布进行节点式的增删改查。
  2. **一个中型项目 [Spec-Craft]**：基于 MCP 的自动化游戏关卡生成器。用户给出一个关卡 Spec，Agent 通过调用 Blender MCP、Unity/Minecraft MCP 和物理引擎 MCP，自动在多个异构软件间传递资产并完成关卡组装与测试。
  3. **一个艺术/游戏/叙事方向 [The Orchestra Agent]**：一个多乐器协同的实时音乐生成系统。每个乐器（如 MIDI 合成器、鼓机、人声合成器）都是一个 MCP 节点，由一个“图规划指挥家 Agent”根据当下的情感曲线动态连接和断开这些节点的音频流。
- **对我项目的启发**：极大地启发了 Spec-driven development。我们可以把“需求文档”直接转化成“MCP 图结构”，让 Agent 顺着图的依赖关系自动调用不同的本地 creative coding 工具生成代码。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 2. The Saturation Trap and the Subjectivity of Intervention Timing
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.04296
- **一句话解释**：探讨了在长程自治 Agent 运行中，何时“打断”和“干预”Agent 的时机问题，并引入了 18 维情感动力学引擎 HEART 作为诊断探针。
- **它为什么重要**：随着 Agent 运行时间变长，它们会陷入“饱和陷阱”（比如死循环或情绪漂移）。传统的“LLM 裁判”或简单的硬编码触发器无法在对的时机干预它们。引入“情感动力学（Affective Dynamics）”作为干预指标，为 HCI（人机交互）和 Agent 行为控制提供了一个极其硬核、有趣且充满艺术感的新维度。
- **技术趋势标签**：`HCI` / `Agent-Intervention` / `Affective-Computing` / `HEART-Engine`
- **可复用模式**：**Affect-Based Heartbeat**：用一个连续的情感/状态动力学引擎作为 Agent 的“心率监视器”，当情感数值（如挫败感、疲劳度、兴奋度）超出特定阈值时，触发人类干预或系统重置。
- **疯狂发明家灵感**：
  1. **一个小实验**：用 Python 写一个极简的 3 维情感引擎（好奇心、挫败感、无聊度），让一个写代码的 Agent 在运行中动态更新这个数值。当“挫败感”过高时，终端会自动弹出一个“请安慰我”的交互框，否则它就拒绝继续写代码。
  2. **一个中型项目 [The Moody Autopilot]**：一个自动玩 Minecraft 的 Agent。它的动作选择受其内部“恐惧度”和“贪婪度”影响。玩家无法直接控制它，但可以通过给它“喂食”或“制造噪音”（改变其情感状态）来间接引导它的游戏路径。
  3. **一个艺术/游戏/叙事方向 [Tamagotchi of Errors]**：一个桌面的“报错电子宠物”。它读取你的 VS Code 报错日志。报错越多，它越沮丧；当你成功 Debug 时，它会跳舞。如果它太沮丧了，它会“黑入”你的终端，用 ASCII 艺术写一封充满诗意的抱怨信，强行打断你的工作，要求你带它去“散步”（静音 5 分钟）。
- **对我项目的启发**：完美的 HCI + Game 结合点。Agent 的控制不应该是冰冷的 Prompt，而可以是某种“动力学反馈”。在世界生成或游戏系统中，可以用这种多维动力学来生成更有血有肉的 NPC 行为。
- **今天是否值得深入研究**：是
- **建议行动**：试用

## 3. Thinking Through Signs: PEEL as a Semiotic Scaffolding
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.04152
- **一句话解释**：将皮尔士符号学（Peircean Semiotics）与 LLM 结合，通过确定性的文本挖掘工具构建一个“符号学支架”，让 AI 的推理过程既有诗意深度又可被知识学溯源。
- **它为什么重要**：这是一个极其罕见的、将硬核人文理论（符号学 Semiotics）直接编码进 AI 工作流的尝试。它不把 LLM 当作简单的“信息提取器”，而是当作“符号阐释者”。对于艺术技术和生成式系统方向，这提供了一种超越常规 RAG 的、更具文化和设计质感的语义分析框架。
- **技术趋势标签**：`Semiotics` / `HCI` / `Generative-Systems` / `Creative-Tool`
- **可复用模式**：**Triadic Semiotic Scaffolding**：将 AI 的输入、上下文和输出解构为符号的三元关系（媒介、对象、解释），迫使 Agent 在生成内容时，显式地声明它所使用的“隐喻”和“符号线索”。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 GPT Prompt 模板，输入一段歌词，要求它输出三个层面的解析：1) 表面字词，2) 背后指代，3) 产生的隐喻新意，并以此生成一幅对应的 ASCII 艺术画。
  2. **一个中型项目 [The Metaphor Engine]**：一个创意写作助手。输入一个枯燥的技术文档（如 RFC 协议），系统自动提取其中的“符号”，并将其转译为一段充满克苏鲁神话色彩或古典魔幻风格的叙事 Spec。
  3. **一个艺术/游戏/叙事方向 [Tarot of the Machine]**：一个由 AI 驱动的“机械塔罗牌”占卜装置。它读取你最近的 Git Commit 记录作为“符号”，通过皮尔士符号学模型，自动生成三张代表“过去的代码冲突”、“当下的重构”和“未来的 Bug”的定制塔罗牌面和解读。
- **对我项目的启发**：很多时候，艺术和游戏系统需要的是“模糊性”和“隐喻”，而不是绝对的精确。PEEL 证明了我们可以用符号学理论作为 prompt/workflow 的骨架，创造出极具人文质感的 AI 创意工具。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 4. FALSIFYBENCH: Evaluating Inductive Reasoning via Rule Discovery Games
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2606.04751
- **一句话解释**：引入基于“规则发现游戏”的评估框架，测试 LLM 代理在科学发现中的归纳推理和假说驱动推理能力。
- **它为什么重要**：游戏是测试和训练 Agent 逻辑的最好温床。这篇文章提出的“规则发现游戏”其实就是一种“黑盒测试”：Agent 必须通过与环境互动、提出假说、故意做实验去“证伪（Falsify）”自己的假说，最终摸清世界的底层规则。这与 Minecraft 的世界生成、自动化 Debug 和 Spec-driven 完美契合。
- **技术趋势标签**：`Inductive-Reasoning` / `Rule-Discovery` / `Game-Systems` / `World-Generation`
- **可复用模式**：**Hypothesis-Test-Falsify Loop**：Agent 不直接寻找正确答案，而是主动生成“反例”（Falsification）来测试环境边界，通过排除法锁定真实规则。
- **疯狂发明家灵感**：
  1. **一个小实验**：在本地写一个极简的 2D 物理世界（比如只有重力和碰撞），不告诉 Agent 物理公式。让 Agent 通过发射小球、记录轨迹，自己归纳出这个世界的“物理定律”（用代码写出公式）。
  2. **一个中型项目 [The Minecraft Alchemist]**：一个 Minecraft 自动化炼金 Agent。游戏里有 10 种未知的药水材料，它们组合会产生各种效果（有些会爆炸，有些会发光）。Agent 必须像科学家一样，通过最少次数的实验，画出完整的“化学反应图谱”，并据此合成出指定的“终极药水”。
  3. **一个艺术/游戏/叙事方向 [Deconstruct the God]**：一个解谜游戏。玩家进入一个由 AI 实时生成的奇异房间，房间的重力、光照、声音规则都是随机且反常识的（例如：走得越快，声音越小）。玩家必须与一个“科学家 Agent”合作，Agent 负责做实验归纳规则并写出“世界运行说明书”，玩家负责利用这些规则逃脱。
- **对我项目的启发**：“证伪能力”是当前 Agent 最缺失的。在 Spec-driven development 中，不要只让 Agent 写代码，还要让它扮演“疯狂测试员”，故意去写能让代码崩溃的测试用例（Falsification），这能极大地提升代码的鲁棒性。
- **今天是否值得深入研究**：否（看思路即可，无需深挖 Benchmark 细节）
- **建议行动**：做demo

## 今日模式总结

1. **协议级解耦 (Protocol-Level Decoupling / MCP-Native)**：从“Prompt 驱动工具”转向“协议/图驱动工具”。利用类似 MCP 的开放标准，将异构工具彻底解耦并节点化，使 Agent 能够动态组装工作流。
2. **情感/状态动力学干预 (Affective Dynamics Intervention)**：长程 Agent 的控制不再仅依靠静态的 RAG 或 LLM Judge，而是引入类似心率的连续多维动力学数值（如挫败感、饱和度），作为优雅的人机交互（HCI）和系统自愈的触发器。
3. **假说-证伪闭环 (Hypothesis-Falsification Loop)**：在未知环境（如游戏世界、未测试的代码库）中，Agent 通过主动制造“反例”来探知边界，而非被动等待正确反馈。

## 今日可做小实验

### 项目名：MCP-p5.js Shape Master (MCP-p5.js 创意傀儡)
- **输入**：用户的自然语言创意描述（例如：“画一个在风中摇曳的红色赛博蒲公英”）。
- **输出**：一个运行在本地浏览器中的 p5.js 画布，Claude 通过本地 MCP Server 实时、动态地在画布上添加、修改、删除图形节点和动画参数。
- **技术栈**：Node.js / Python (MCP SDK), FastMCP, p5.js, WebSocket, Claude Desktop (或一个简单的自定义前端页面)。
- **第一步怎么做**：
  1. 使用 Python 的 `mcp` 库写一个极简的 MCP Server，暴露一个 `draw_shape(shape_type, params)` 和 `clear_canvas()` 的 Tool。
  2. 在本地用 HTML/JS 启动一个简单的 WebSocket 页面，运行 p5.js，接收来自 MCP Server 的绘图指令。当 MCP Tool 被调用时，通过 WebSocket 将数据推送到前端。
  3. 启动 Claude Desktop，配置该本地 MCP Server。输入“在画布上画一个动态的星空”，看 Claude 如何通过调用工具一步步在你的浏览器里“画”出世界。
