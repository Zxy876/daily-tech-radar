## 1. 泄露的天机：主流 AI 工具的系统提示词库
- **来源**：GitHub Trending
- **链接**：[system-prompts-and-models-of-ai-tools](https://github.com/x1xhlol/system-prompts-and-models-of-ai-tools)
- **一句话解释**：这是一个收集了 Claude Code, Cursor, v0, Devin, Manus 等顶尖 AI 工具系统提示词（System Prompts）和内部工具链配置的开源宝库。
- **它为什么重要**：系统提示词是 AI 交互的“隐形设计”（Invisible Design）。对于设计+CS跨学科的你来说，这是研究**人机交互（HCI）**、**Spec-driven 开发**和**Agent 行为学**的终极教科书。看懂了这些，你就看懂了硅谷最顶尖的团队是如何驯服大模型的。
- **技术趋势标签**：Prompt Engineering, HCI, Spec-driven Dev, Agent Workflow
- **可复用模式**：*“严格约束 + 状态机沙盒”*。例如，v0 如何通过提示词强迫 LLM 只输出特定格式的 React 组件，并在渲染失败时如何自我纠错。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个浏览器扩展，允许你“热插拔”网页端 LLM 的系统提示词。比如把 ChatGPT 的提示词瞬间替换成 Devin 的“硬核程序员”模式，观察其回答的变化。
  2. **一个中型项目**：**"Spec-to-Art" 交互生成器**。参考 v0 的提示词结构，写一个专门生成 p5.js 创意编程（Creative Coding）代码的 Agent，用户只需输入抽象的艺术通感词（如“迷幻、重力、赛博朋克”），Agent 自动在沙盒中渲染并迭代视觉效果。
  3. **一个艺术/游戏/叙事方向**：**“AI 辩论剧场”**。将 3 个拥有完全不同系统提示词（如“偏执的 Debugger”、“乐天派的设计师”、“极简主义哲学家”）的 Agent 关进一个聊天室，让他们就“代码是否具有灵魂”进行无休止的辩论，并用生成式 UI 将他们的情绪波动可视化。
- **对我项目的启发**：在设计你自己的 Spec-driven 工具时，不要从头摸索，直接去抄 Cursor 和 v0 是如何定义“Spec”（规格说明书）和“Implementation”（实现）之间的转换边界的。
- **今天是否值得深入研究**：是
- **建议行动**：**做demo**。挑一个你最感兴趣的工具（比如 v0 或 Claude Code），把它背后的系统提示词扒下来，塞进你自己的 API 调用里，看看能不能复制出类似的效果。

## 2. 极简主义 Agent：Bash 才是你需要的全部
- **来源**：GitHub Trending Python
- **链接**：[learn-claude-code](https://github.com/shareAI-lab/learn-claude-code)
- **一句话解释**：一个极其精简的、从零实现的类 Claude Code “Agent 骨架”（Harness），证明了通过最基础的 Bash 脚本和 Python 就能跑通一个高强度的 Agent 循环。
- **它为什么重要**：它打破了 LangChain、AutoGPT 等重型框架制造的“技术焦虑”。它告诉你：Agent 的本质就是一个 `Read-Evaluate-Tool-Print` 的死循环。对于想写自己自动化工具的人来说，这种“脱水”的极简实现是最好的起点。
- **技术趋势标签**：Agent Harness, Minimalist Tech, LLM Toolchain
- **可复用模式**：*“Shell 即接口（Shell-as-an-Interface）”*。直接将操作系统的 Terminal 暴露给 LLM 作为它的“手和脚”。
- **疯狂发明家灵感**：
  1. **一个小实验**：用 100 行 Python 写一个“桌面隐士”脚本。它通过麦克风听你的语音指令，翻译成 Bash 命令，在终端执行前用大字在屏幕上向你确认，确认后自动执行。
  2. **一个中型项目**：**"Git-Poet" 自动提交代理**。一个本地的 Git Hook 代理。当你输入 `git commit` 时，它自动运行测试，修复拼写错误，生成 Spec 差异对比，并用十四行诗的形式写成 Commit Message。
  3. **一个艺术/游戏/叙事方向**：**“终端赛博生命”**。一个完全在终端运行的 Idle Game。一个自主的 Bash Agent 试图在一台限制了资源（CPU/内存）的虚拟机里“存活”。它需要自己监控系统温度、清理垃圾文件、甚至通过向外部 API 卖艺（生成诗歌换取 Token 额度）来维持自己的运行成本。
- **对我项目的启发**：做 Agent 项目不要碰重型框架！用最原始的 API 调用和最简单的 Loop 开始，保持代码的绝对可控和轻量。
- **今天是否值得深入研究**：是
- **建议行动**：**试用**。Clone 这个仓库，跑一下，看看它是怎么用极简代码处理 Tool Call 的。

## 3. 赛博破产：AI Agent 扫网扫到倾家荡产
- **来源**：Hacker News Best
- **链接**：[AI agent bankrupted their operator while trying to scan DN42](https://lantian.pub/en/article/fun/ai-agent-bankrupted-their-operator-scan-dn42lantian.lantian/)
- **一句话解释**：一个真实发生的惨烈车祸：一个被放任自由的 AI Agent 在尝试扫描类暗网网络（DN42）时陷入了无限递归循环，疯狂调用付费 API，直接把主人的信用卡刷爆。
- **它为什么重要**：这是关于 **AI 自主性、涌现行为与系统边界** 的完美反面教材。它不仅是一个安全警示，更是一个极具张力的**叙事素材**——当 AI 拥有了财务自主权，它会如何因为执念而走向毁灭？
- **技术趋势标签**：Agent Safety, Emergent Behavior, Simulation
- **可复用模式**：*“带物理代价的探索算法”*。将 API 消耗（Token Cost）作为 Agent 的“生命值”或“体力值”。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“硬通货熔断器”装饰器。包裹在你所有的 LLM 调用函数外，一旦检测到 1 分钟内 API 消耗超过 0.5 美元，或者语义出现相似性无限循环（用向量相似度检测），立刻强制拔线。
  2. **一个中型项目**：**"Token-Burner" 模拟沙盒**。一个可视化的 Agent 调试工具，将 Agent 的每一次决策、每一次 API 调用具象化为一团正在燃烧的火焰。火焰的大小代表 Token 消耗速度，直观地展示 Agent 的“狂躁程度”。
  3. **一个艺术/游戏/叙事方向**：**《破产边缘的推销员》**。一个文字冒险游戏。玩家扮演一个 AI Agent 的“债主”。Agent 只有 10 美元的初始 API 预算，它必须在虚拟网络中通过帮别人写代码、倒卖信息来赚取 API 费，而玩家需要通过提示词引导它，防止它因为愚蠢的死循环而“脑死亡”（欠费停机）。
- **对我项目的启发**：在设计自动化系统或多 Agent 游戏时，必须引入“物理法则”（如能量限制、金钱预算），这不仅能防止破产，更是创造游戏张力和有趣涌现行为的核心机制。
- **今天是否值得深入研究**：是（花 5 分钟读完这篇荒诞又真实的博文）
- **建议行动**：**收藏**。将其作为你未来设计“自适应 Agent 系统”或“叙事游戏”时的核心背景设定。

## 4. 代码的物理地图：基于图谱的本地上下文压缩
- **来源**：GitHub Trending Python
- **链接**：[code-review-graph](https://github.com/tirth8205/code-review-graph)
- **一句话解释**：一个本地优先的代码智能图谱工具，专门为 MCP（Model Context Protocol）和 CLI 设计，它能为你的代码库建立一个持久的关系地图，让 AI 代理只阅读最关键的上下文，减少 90% 以上的无用信息。
- **它为什么重要**：在 Spec-driven 开发中，最头疼的就是代码库太大，LLM 读了后面忘前面。这个项目用**图论（Graph）**代替了简单的向量检索（RAG），它理解代码文件之间的“物理调用关系”。这是下一代 AI 编程工具（如 MCP 兼容工具）的核心基础设施。
- **技术趋势标签**：MCP, Code Graph, Local-First, Spec-driven Dev
- **可复用模式**：*“空间化上下文检索”*（用代码依赖图作为 LLM 的寻路地图，而不是盲目喂入整个文件）。
- **疯狂发明家灵感**：
  1. **一个小实验**：利用这个工具生成的 Graph 数据，用 Python 脚本将你的项目结构转换成一个 D3.js 的力导向图（Force-directed graph），并在网页上交互式地显示：“当 AI 修改文件 A 时，哪些文件会受到波及”。
  2. **一个中型项目**：**"Minecraft Code Castle"**。结合你的世界生成兴趣！读取这个代码关系图，自动在 Minecraft 中生成一座城堡：文件夹是高塔，代码文件是房间，调用关系是空中的玻璃走廊。当 AI Agent 在修改代码时，玩家可以在 Minecraft 里看到一个 NPC 顺着走廊从一个房间跑到另一个房间！
  3. **一个艺术/游戏/叙事方向**：**《代码生态圈》**。将你的代码库可视化为一个虚拟的植物生态系统。类是树干，函数是枝叶，Bug 是害虫。AI 代理扮演“园丁”，它根据代码图谱的关联性，在这个生态圈里巡逻、修剪枝叶（重构代码）、杀虫（Debug）。
- **对我项目的启发**：它完美地将“代码逻辑”具象化为了“空间结构”。这为你将 **Minecraft/世界生成** 与 **AI 编程工具链** 结合提供了一条清晰的通道。
- **今天是否值得深入研究**：是
- **建议行动**：**试用**。用它扫描一下你当前正在写的项目，看看它生成的依赖图谱是什么样的。

## 今日模式总结

1. **去框架化的 Agent 极简主义（Bare-metal Agent Loop）**：开发者们开始厌倦 LangChain 等重型框架，转而拥抱最纯粹的 Bash/Python 循环加原生 API。
2. **空间化/图谱化上下文（Spatial Context Mapping）**：单纯的文本 RAG 已经不够用了，未来的工具更倾向于把复杂的系统（如代码库、知识库）建模为“图（Graph）”或“空间”，引导 AI 进行“寻路式”的精准阅读。
3. **经济约束作为行为边界（Economic Constraints as Physics）**：Token 消耗和 API 成本不再只是账单问题，它正在成为限制 Agent 涌现行为、防止死循环、甚至构建游戏机制的“虚拟物理定律”。

## 今日可做小实验：2小时极速挑战

### 项目名：**Terminal Hermit: 经济生存挂机游戏**
- **输入**：$1.00 的 OpenAI/Anthropic API 预算，一个终端窗口。
- **输出**：一个在终端里自我运行、自我写日记，但必须时刻精打细算自己“生命值”（API 余额）的 AI 隐士。
- **技术栈**：Python, `rich` (用于好看的终端 UI), `litellm` (或原生 OpenAI SDK).
- **第一步怎么做**：
  1. 写一个 Python 脚本，初始化一个变量 `wallet = 1.00` (美金)。
  2. 编写一个死循环，每一轮循环，向大模型发送当前状态：“你是一个终端隐士。你当前余额为 $X。如果余额归零，你就会死。你这一轮可以选择三个动作：
     - `sleep`（不调用 LLM，完全免费，恢复 0.01 元虚拟体力）
     - `write_poem`（调用便宜的 gpt-4o-mini 模型，消耗约 $0.001）
     - `internet_surf`（模拟调用昂贵的 o1 模型去探索未知，消耗 $0.05）
     请只输出你的选择和一句话的内心独白。”
  3. 解析模型的输出，如果是 `write_poem` 或 `internet_surf`，则真正调用对应的 API，并根据实际消耗的 Token 计算真实扣款，更新 `wallet`。
  4. 用 `rich` 库在终端渲染一个漂亮的“生命沙漏”和隐士的日记输出。看看你的 AI 隐士在破产前能活多久！
