## [Instruction Bleed: Cross-Module Interference in Prompt-Composed Agentic Systems]
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2606.26356
- 一句话解释：在由多个 Prompt 组成的 Agent 系统中，即使模块之间没有直接的变量或执行依赖，一个模块的修改也可能意外地影响其他模块的行为。
- 它为什么重要：这是构建复杂 Agent 系统时一个非常实际且令人头疼的“幽灵bug”问题。理解和解决它，能让我们更稳定、可控地设计和调试 Agent。
- 技术趋势标签：AI, agent, transformer, prompt, context window, spec-driven development, LLM工具链
- 可复用模式：模块化 Agent 设计中的“干扰”与“隔离”策略。
- 疯狂发明家灵感：
    1. 一个小实验：尝试构建一个简单的多 Agent 系统，其中两个 Agent 共享一个非常大的 Prompt 上下文，然后修改其中一个 Agent 的 Prompt，观察另一个 Agent 的行为是否发生非预期变化。
    2. 一个中型项目：开发一个“Prompt 隔离器”或“Prompt 监视器”，能够可视化或量化 Prompt 模块之间的相互影响，帮助调试。
    3. 一个艺术/游戏/叙事方向：设计一个“AI 叙事生成器”，其中的不同 Agent 负责不同的叙事元素（如角色对话、场景描述、情节转折），并利用“Instruction Bleed”来制造意想不到的叙事转折或角色动机的微妙变化。
- 对我项目的启发：在设计复杂的 Agent 工作流时，需要考虑 Prompt 之间的隐式耦合，并寻找解耦或显式通信的机制。
- 今天是否值得深入研究：是
- 建议行动：收藏 / 试用

## [SKILL-DISCO: Distilling and Compiling Agent Traces into Reusable Procedural Skills]
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2606.26669
- 一句话解释：该研究提出了一种方法，可以将 Agent 在执行任务时产生的“思考过程”（trace）提炼成可重用的、程序化的“技能”，避免重复从头开始推理。
- 它为什么重要：这直接解决了 Agent 系统中效率和可复用性的问题，是迈向更智能、更高效 Agent 的重要一步，也与“spec-driven development”中的模块化和复用精神契合。
- 技术趋势标签：AI, agent, workflow, reasoning, procedural, automation, LLM工具链
- 可复用模式：从动态执行到静态技能的转化，以及技能的组合与编排。
- 疯狂发明家灵感：
    1. 一个小实验：记录一个 Agent 完成某个特定任务（如数据清洗、代码生成）的完整执行过程，然后尝试手动或用简单的规则提炼出其中的关键步骤，模拟成一个简单的函数或脚本。
    2. 一个中型项目：构建一个“Agent Skill Miner”，能够自动分析 Agent 的执行日志，识别出重复出现的模式，并将其打包成可调用的“技能模块”，供其他 Agent 复用。
    3. 一个艺术/游戏/叙事方向：开发一个“AI 编舞系统”，Agent 学习不同的舞蹈动作序列（trace），并将其提炼成可组合的舞蹈“技能”，生成复杂的舞蹈表演。或者，在游戏 AI 中，让 NPC 学习并提炼出执行特定任务（如战斗、采集）的“技能”，使行为更流畅且可复用。
- 对我项目的启发：可以为我的 Agent 设计一个“技能库”，通过观察和分析，自动生成和优化这些技能，提高 Agent 的效率和通用性。
- 今天是否值得深入研究：是
- 建议行动：收藏 / 做demo

- 链接：https://arxiv.org/abs/2606.26458
- 一句话解释：这是一个用于评估多模态知识图谱增强生成（MKG-RAG）中检索（Retrieval）性能的基准测试。
- 它为什么重要：多模态 RAG 是未来 LLM 应用的重要方向，而检索是其中的关键瓶颈。这个基准有助于推动该领域的研究和发展，尤其是跨模态信息融合的检索。
- 技术趋势标签：LLM, multimodal, RAG, retrieval, AI, creative tool
- 可复用模式：多模态信息融合、知识图谱与 RAG 的结合、评估基准的设计。
- 疯狂发明家灵感：
    1. 一个小实验：尝试使用一个简单的多模态数据源（如图片+文字描述），构建一个基础的 RAG 系统，并观察当检索时需要融合文本和图像信息时，效果如何。
    2. 一个中型项目：开发一个“多模态创意内容生成器”，能够根据用户输入的文本和图像，检索相关的多模态知识，然后生成新的、融合了这些信息的创意内容（如故事、诗歌、设计概念）。

## 今日模式总结
今天出现了几个关键的技术模式：

1.  **Agent 的“智能记忆”与“技能提炼”**：Cognee 强调了 Agent 需要长期记忆来提供连贯服务，而 SKILL-DISCO 则展示了如何将 Agent 的动态执行过程转化为可重用的、程序化的“技能”。这两者共同指向了构建更强大、更自主、更高效 Agent 的方向。
2.  **多模态信息融合与检索**：MKG-RAG-Bench 突显了在处理图像、声音等多种模态信息时，有效的检索和融合是关键。这为 Agent 和生成系统提供了更丰富的输入维度和更广阔的知识边界。
3.  **复杂系统中的“隐式行为”与“可控性”**：Instruction Bleed 指出了在由多个组件（如 Prompt 模块）构成的系统中，即使没有显式依赖，也可能存在意想不到的相互影响。这提醒我们在设计复杂系统时，需要关注“spec-driven development”中的可预测性和可控性。

## 今日可做小实验
**项目名：** Prompt 干扰探测器

**输入：**
1.  一个简单的多模块 Prompt 结构（例如，一个负责生成故事开头的 Prompt A，一个负责生成角色对话的 Prompt B）。
2.  一个基础的 LLM API（如 OpenAI, Claude, 或本地模型）。

**输出：**
一个简单的可视化，显示当你修改 Prompt A 的某个部分时，Prompt B 生成内容的“变化程度”。

**技术栈：**
- Python
- OpenAI API (或其他 LLM API)
- `diff` 库 (用于比较文本差异)
- (可选) `streamlit` 或 `gradio` 用于简单的 UI

**第一步怎么做：**
1.  **设置 LLM API 调用：** 编写一个 Python 函数，接收一个 Prompt 字符串，调用 LLM API，并返回生成的文本。
2.  **定义基础 Prompt 结构：** 创建两个（或更多）Prompt 模板，例如：
    *   Prompt A 模板: "写一个故事的开头，关于 [主题]。"
    *   Prompt B 模板: "根据上面的故事开头，写一段角色 [角色名] 的对话，他/她感觉 [情感]。"
3.  **实现基础 Agent 流程：** 先用两个 Prompt 独立生成内容，或者按顺序调用。
4.  **引入“修改”和“比较”：**
    *   选择 Prompt A 的一个参数（例如，`[主题]`），并准备几个变体。
    *   对于 Prompt A 的每一个变体，调用 LLM 生成新的 Prompt A 输出。
    *   **关键步骤：** 使用 *上一次* Prompt A 的输出作为 Prompt B 的输入，生成 Prompt B 的输出。然后，使用 *当前* Prompt A 的输出作为 Prompt B 的输入，再次生成 Prompt B 的输出。
    *   使用 `difflib.SequenceMatcher` 或其他文本比较工具，计算两次 Prompt B 输出之间的差异（相似度分数）。
5.  **可视化结果：** 打印出差异分数，或者使用 `streamlit` 创建一个简单的界面，滑动 Prompt A 的参数，实时查看 Prompt B 输出的变化。

这个实验的目标是直观地感受到“Instruction Bleed”的存在，即使你只修改了 Prompt A 的内容，Prompt B 的输出也可能因为上下文窗口的“共振”而发生变化。
