## 1. SAGE: 自进化 Agent 的统计准入闸门 (Statistical Acceptance Gate)
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2609.36043
- 一句话解释：提出了一种统计准入闸门（Gate），专门判定 Agent 是否应该把“自我修改的工作流/工具规则”持久化写入自己的技能文档。
- 它为什么重要：过去大家都在研究 Agent 怎么“提出改动（Optimizer）”，但 Agent 很容易因为一次偶然成功而把有害的逻辑永久写死。SAGE 补齐了“自我进化闭环”中最关键的一环：**给 Agent 自己的大脑加一个带统计检验的 CI/CD 门禁**。
- 技术趋势标签：`Spec-driven Development` `Self-evolving Agent` `Evaluation Gate` `LLM Workflow`
- 可复用模式：**“候选变更生成器 (Proposer) + 统计基线回归测试 (Gatekeeper) + 动态 Spec.md (Living Document)”**。
- 疯狂发明家灵感：
  1. 一个小实验：写一个本地单文件脚本，让 Agent 维护一份 `system_prompt.md`；每次任务失败后它可发起 PR 提议修改提示词，脚本用 5 个基准测试打分，均值提高才自动 `git commit`。
  2. 一个中型项目：**Auto-Drift** —— 结合你的 spec-driven 理念，开发一个本地代码 Agent，它不仅生成代码，还会在解决 bug 后自我迭代它的《交互规范与架构约定》，自动剔除会导致它死循环的代码习惯。
  3. 一个艺术/游戏/叙事方向：**“人格蜕皮”NPC**。NPC 的性格规范是动态文本，玩家与它的交流会促使它修改自己的“待人准则”，但必须通过“核心记忆守门人”的检验，形成一种缓慢且真实的性格成长/异化感。
- 对我项目的启发：对于 spec-driven 开发流程，核心痛点是 Spec 很容易腐烂或膨胀。这个模式证明了“把 Spec 当成被动检验文档”是过时的，**Spec 应该是由 Gate 守护的自演化生命体**。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 2. VectifyAI / PageIndex: 抛弃向量的推理型 RAG
- 来源：GitHub Trending
- 链接：https://github.com/VectifyAI/PageIndex
- 一句话解释：一种完全不依赖 Vector Embedding 和向量数据库，而是依靠文档结构树与 LLM 推理路径来定位内容的极简文档检索系统。
- 它为什么重要：向量检索把文本打碎成 chunk 会丢失全局层级、上下文语义和逻辑链条（在长文档、代码库、设定集中极为致命）。它回归到了人类翻书的方式：**目录树形索引 + 逐层推理剪枝**。
- 技术趋势标签：`Vectorless RAG` `Reasoning Retrieval` `Context Structuring` `Creative Tool`
- 可复用模式：**“树状结构化索引 (Tree of Content) + 规划器递归下钻 (Recursive Reasoning Extraction)”**。
- 疯狂发明家灵感：
  1. 一个小实验：用纯 Markdown 标题层级表示一个复杂的科幻世界观世界书，写一个 30 行的 Python 脚本，让本地小模型先选择章节目录，再命中段落，完全不加载任何向量模型。
  2. 一个中型项目：**SpecNavigator** —— 专为巨型软件 Spec/设计文档打造的交互式白板工具，用推理树即时高亮当前功能涉及的上下游约束，所见即所思。
  3. 一个艺术/游戏/叙事方向：**TRPG 动态地下城规则法典**。游戏跑团中包含几百页冷门规则，AI DM 通过目录推理即时调取奇幻法案，绝不发生向量检索常有的“幻觉拼接”。
- 对我项目的启发：在做 Minecraft 世界生成或游戏系统时，世界设定（Lore）和系统规约（Game Spec）往往高度结构化，向量检索极易破坏逻辑关系。改用 PageIndex 模式，能让系统推理更透明可控。
- 今天是否值得深入研究：是
- 建议行动：试用

## 3. 非对称智能体与认知多样性辩论 (Beyond Symmetric Agents)
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2609.35875
- 一句话解释：论文证实 Multi-Agent Debate（多智能体辩论）之所以能提升推理能力，核心动力不是“多几个模型投票”，而是**智能体之间的“认知多样性”（异构性格、不同推理侧重）**。
- 它为什么重要：戳破了“盲目堆砌同质 Agent”的幻觉。如果你用 3 个一模一样的提示词 Agent 讨论，收效甚微；但如果有意识地设计“激进派、悲观怀疑派、第一性原理派”，小参数模型甚至能越级击败大模型推理。
- 技术趋势标签：`Multi-Agent Debate` `Cognitive Diversity` `SLM (Small Models)` `Agent HCI`
- 可复用模式：**“对抗性认知矩阵 (Adversarial Cognitive Matrix)”** —— 在架构多智能体工作流时，硬编码异构的思考偏见（Biases）。
- 疯狂发明家灵感：
  1. 一个小实验：配置 3 个 3B 小模型：一个被设定为极度挑剔的“代码审计狂”，一个被设定为追求极简的“重构极客”，让他们审查同一个函数并输出融合版本。
  2. 一个中型项目：**Prompt Triad (提示词三人议会)** —— 针对创作者的 IDE 插件。在你写设计草案时，三只性格迥异的 Agent 会在侧边栏实时互喷并给出妥协后的最强方案。
  3. 一个艺术/游戏/叙事方向：**村落长老政治决策模拟**。在模拟经营游戏中，村子的法案生成由保守农夫、狂热祭司、贪婪商人三个异构小模型自动辩论决定，玩家通过贿赂或游说干预不同权重。
- 对我项目的启发：构建 Agent 工作流时，别再写“你是一个有用的专家助手”，而是把每个子 Agent 塑造成拥有**极端单一认知缺陷与执念**的角色，系统整体反而最稳定。
- 今天是否值得深入研究：是
- 建议行动：收藏

## 4. 社交模拟中的虚假真实效应 (Illusory Truth in Social Simulations)
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2609.36278
- 一句话解释：研究验证了 LLM Agent 在群体社交模拟中，像人类一样存在“重复暴露效应”（一件假事被反复提及后，Agent 会逐渐将其判定为真）。
- 它为什么重要：这是“智能体具有人类同款认知弱点”的实证。在自动化仿真中这可能是 Bug，但在**游戏叙事、世界生成、动态社会模拟**中，这是造出“活生生NPC社会”的极品特性。
- 技术趋势标签：`Generative Social Simulation` `Cognitive Biases` `Emergent Narrative` `Game Systems`
- 可复用模式：**“信息重述衰减/置信度强化循环 (Repetition-Belief Loop)”**。
- 疯狂发明家灵感：
  1. 一个小实验：搭建一个 5 人微型聊天室（本地模型），注入一条离谱传闻（如“村头的老王其实是龙变形的”），测试传闻转述几轮后会变成全体 NPC 的共识记忆。
  2. 一个中型项目：**RumorEngine (谣言传染引擎)** —— 针对 Minecraft / 模拟人生的插件系统，让村民在互相交谈时自主衍生都市传说、宗教禁忌和市场恐慌。
  3. 一个艺术/游戏/叙事方向：**交互式侦探游戏《三人成虎》**。玩家扮演信息操纵者，不需要自己去暗杀嫌疑人，只需在小镇的酒吧和市场散布特定重复片段，引导 AI 警长与村民相信某人是凶手并完成审判。
- 对我项目的启发：叙事世界的生命力不在于设定集写得多精美，而在于**设定如何在 Agent 之间被口口相传、磨损与神化**。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 今日模式总结

1. **Spec 活体化与自愈 (Self-Refining Spec-Gate)**：不再手工维护冗长规约，而是让 Agent 在实践中自我提议修改规则，并通过自动化准入闸门（Gate）保证系统不失控。
2. **结构优先替代嵌入黑盒 (Structure-First over Embeddings)**：从向量空间的高维隐空间暴力匹配，回归到人类可读的层次树结构（Tree-of-thought/PageIndex）。这为白盒化、可解释的可视化工作流带来巨大机会。
3. **异构与偏见即创造力 (Cognitive Asymmetry as Feature)**：同质化的智能体协同等于浪费算力；认知偏差（如偏执、重复效应、立场对立）才是驱动系统动态推理和涌现叙事的真正引擎。

## 今日可做小实验：Spec-Gatekeeper (自演化规约守门人)

**目标**：用 2 小时验证 SAGE 的核心逻辑——让一个 Prompt 针对测试集自我改写并完成自动准入验收。

- **项目名**：`Micro-SAGE`
- **输入**：
  1. 一份初始规约：`system_spec.md`（例如：“你是一个将复杂学术概念转化为赛博朋克黑话的翻译器”）。
  2. 3 个固定测试案例（Case 1, 2, 3）。
- **输出**：
  1. 发生变更后的 `system_spec.md`。
  2. 一份 Git Commit 记录，包含测试门禁的通过对比报告。
- **技术栈**：Python 3 + 任意本地或 API 模型（如 Ollama / Claude API / OpenRouter）
- **第一步怎么做**：
  1. 创建目录并新建 `tests.json`，放 3 个输入（如：“贝叶斯定理”、“反向传播”、“工作量证明”）。
  2. 写一个评测函数 `evaluate(spec)`：用这个 spec 运行 3 个输入，让一个评判模型从「黑话贴合度、信息保真度」打分（0-10 分），计算平均分。
  3. 写一个优化循环：让模型阅读当前的 `system_spec.md` 和上一次未拿满分的评价，输出一份“修改后的新 spec”。
  4. **核心闸门 (The Gate)**：仅当 `new_score > old_score + 0.5` 时，才执行代码自动覆写 `system_spec.md` 并打印 "Spec Evolved!"，否则直接拒绝并回滚。运行 3 轮观察它怎么自我微调！
