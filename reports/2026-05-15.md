## 1. PROMETHEUS: 文本到持久化世界模型的跨越
- 来源：arXiv cs.AI (2605.12835)
- 链接：https://arxiv.org/abs/2605.12835
- 一句话解释：将碎片化的文献、报告和模拟数据转化为一个**可导航、持久化的“世界模型”**，而不仅仅是摘要。
- 它为什么重要：它解决了 RAG 系统“只有记忆没有逻辑”的痛点，把信息编织成了因果网络。
- 技术趋势标签：#WorldModel #CausalReasoning #KnowledgeGraph
- 可复用模式：**“叙事地图化”**——将非结构化文本转化为可以被 Agent 物理探索的逻辑空间。
- 疯狂发明家灵感：
  1. **一个小实验**：喂给 AI 十本赛博朋克小说，生成一个基于 D3.js 的因果关联图，点击一个事件能看到它如何连锁导致了另一个事件。
  2. **一个中型项目**：一个自动“世界观构建”工具，输入历史书，输出一个可运行的 Minecraft 城镇配置文件（基于历史因果逻辑）。
  3. **一个艺术/游戏/叙事方向**：一个“活的百科全书”装置。观众投入一张新闻剪报，AI 将其融入现有的虚拟世界逻辑，并实时改变虚拟世界的气候或社会规则。
- 对我项目的启发：对于你的世界生成项目，不要只生成地形，要生成**“因果链条”**。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 2. MAP (Map-then-Act): 拒绝“盲人摸象”的 Agent 范式
- 来源：arXiv cs.AI (2605.13037)
- 链接：https://arxiv.org/abs/2605.13037
- 一句话解释：提出先建立**环境全局认知图**再采取行动，解决 Agent 在长程任务中因“边走边看”导致的试错成本过高问题。
- 它为什么重要：这是从“反应式 Agent”向“主动规划式 Agent”的进化，非常适合复杂游戏环境。
- 技术趋势标签：#Planning #SpatialIntelligence #MinecraftAgent
- 可复用模式：**“先扫描，后行动”**。在执行任何代码前，先建立一个环境的抽象表示（Metadata Map）。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个 Python 脚本，让 Agent 在操作你的文件系统前，先生成一个目录结构的“风险热力图”。
  2. **一个中型项目**：一个 Minecraft 建筑机器人，它先飞一圈生成整个区域的“脚手架蓝图”，然后再开始放置方块。
  3. **一个艺术/游戏/叙事方向**：一个“前瞻性叙事”系统。NPC 在和你对话前，先模拟出三种结局的概率图，并根据它“想要”的结局来选择当下的措辞。
- 对我项目的启发：在 Spec-driven development 中，增加一个“环境扫描”层，在生成 Spec 之前先感知现有代码库的拓扑。
- 今天是否值得深入研究：是
- 建议行动：试用（思路复用）

## 3. Visual Aesthetic Benchmark: AI 真的懂美吗？
- 来源：arXiv cs.HC (2605.12684)
- 链接：https://arxiv.org/abs/2605.12684
- 一句话解释：研究 MLLM（多模态大模型）是否能像人类一样做出**审美判断**，而不仅仅是给图片打分。
- 它为什么重要：对于艺术/设计背景的你，这是将“品味”量化为“算法过滤器”的基础。
- 技术趋势标签：#ComputationalAesthetics #MLLM #HCI
- 可复用模式：**“审美对齐循环”**。利用多模态模型作为你生成艺术作品的“策展人”。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个 Prompt 链，让 Claude 3.5 对比 10 张生成艺术图，并根据“包豪斯原则”选出最优秀的一张并说明理由。
  2. **一个中型项目**：一个“审美自动调优”的 Creative Coding 工具。你写代码，AI 实时运行并截图，根据审美评分自动调整代码中的颜色和参数。
  3. **一个艺术/游戏/叙事方向**：一个“只给美的人开门”的交互装置。只有当摄像头拍到的构图符合某种经典美学比例时，装置才会触发。
- 对我项目的启发：你的生成式系统需要一个“美学后验层”，用这个研究的指标来做筛选器。
- 今天是否值得深入研究：是
- 建议行动：收藏（作为论文引用或工具参考）

## 4. ARIS (Auto-Research-In-Sleep): 睡梦中的自动化研究员
- 来源：GitHub (wanshuiyin/Auto-claude-code-research-in-sleep)
- 链接：https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep
- 一句话解释：一个轻量级的自动化框架，让 Claude Code 等 Agent 在你睡觉时自主进行实验、代码审查和思路发现。
- 它为什么重要：它代表了**“异步开发”**。你不是在用 AI，你是在雇佣一个 24 小时不停歇的实习生。
- 技术趋势标签：#Automation #AutonomousAgent #SpecDriven
- 可复用模式：**“影子实验室”模式**。主进程开发，影子进程在后台疯狂尝试失败路径并记录教训。
- 疯狂发明家灵感：
  1. **一个小实验**：设定一个任务（比如：寻找 10 种实现水体渲染的新方法），让它运行一夜，早上起来看 Markdown 报告。
  2. **一个中型项目**：一个“代码进化池”。你写一个基础类，AI 在晚上生成 100 个变体，运行单元测试，保留性能最好的。
  3. **一个艺术/游戏/叙事方向**：一个“无限迭代的数字生命”。它在服务器上不断重写自己的视觉逻辑，每晚进化一次。
- 对我项目的启发：把你现在的 Spec-driven 流程自动化，实现“输入需求 -> 睡觉 -> 醒来拿 Demo”。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 5. Think Twice, Act Once: 验证器引导的行动选择
- 来源：arXiv cs.AI (2605.12620)
- 链接：https://arxiv.org/abs/2605.12620
- 一句话解释：在 Embodied Agent（具身智能）中引入**“验证器”**，在执行动作前先用视觉-语言模型预判该动作是否会导致错误。
- 它为什么重要：这正是 Spec-driven development 在物理/模拟世界的体现——**“测试驱动行动”**。
- 技术趋势标签：#EmbodiedAI #Verifier #CoT
- 可复用模式：**“先模拟，后提交”**（Sim-to-Submit）。
- 疯狂发明家灵感：
  1. **一个小实验**：做一个 Agent 操作浏览器的脚本，在点击任何按钮前，先截图问 AI：“点击这个按钮会跳转走吗？”
  2. **一个中型项目**：一个 Minecraft 逻辑电路助手。它在放置红石前，先“脑补”电路是否会短路。
  3. **一个艺术/游戏/叙事方向**：一个“谨小慎微”的交互装置。它试图触摸观众，但每次手移动前都会停顿，计算是否会冒犯对方，这种“迟疑感”本身就是一种艺术表达。
- 对我项目的启发：给你的 Agent 增加一个“悔棋”或“脑内预演”的逻辑层。
- 今天是否值得深入研究：否（看思路即可）
- 建议行动：收藏

- **输入**：一段简单的 p5.js 随机生成艺术代码。
- **输出**：3 段进化后的代码，每一段都比前一段更符合“极简主义”审美。

  4. 观察 AI 的审美逻辑是否一致。
