## 1. claude-code

- **来源**：GitHub Trending Python
- **链接**：https://github.com/anthropics/claude-code
- **一句话解释**：Anthropic 官方推出的终端 Agent 编程工具，直接在你的本地代码库里执行任务、跑 Git 工作流、解释代码。
- **它为什么重要**：它标志着 AI 辅助编程从“聊天窗口（Chat）”正式跨入“系统级 Agent（Terminal Agent）”时代。它不再是给你建议，而是直接在你的系统里“干活”。对于 Spec-driven development（规范驱动开发）来说，这是极佳的底层执行器。
- **技术趋势标签**：#Terminal-Agent #Spec-Driven #LLM-Workflow
- **可复用模式**：**“终端即画布”模式**。Agent 不需要复杂的 GUI，通过终端完全控制文件系统、执行测试和 Git 提交，形成“修改-测试-修复”的闭环。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 `spec.md` 描述一个简单的 p5.js 动态视觉，让 Claude Code 在终端里自主迭代，直到通过你用 Playwright 写的“视觉色彩占比检测”测试。
  2. **一个中型项目**：**“自动游戏平衡师”**。一个运行在 Minecraft 服务器后台的 Claude Code 实例，它读取玩家的死亡日志和装备数据（CSV），自动修改服务器的游戏规则脚本（Skript/Java），并自动重启服务器进行热更新。
  3. **一个艺术/游戏/叙事方向**：**“自编写的文字冒险游戏”**。游戏代码本身是不完整的，玩家每输入一个意想不到的动作，Claude Code 就会在后台实时重写游戏引擎的 Python 代码来支持这个新动作，并自动提交 Git 记录玩家的“开天辟地”史。
- **对我项目的启发**：你的 spec-driven workflow 不需要自己写复杂的 agent 执行器了，直接调用 Claude Code 作为你的“代码执行手”。
- **今天是否值得深入研究**：是
- **建议行动**：做demo（安装并尝试让它帮你重构一个现有的 creative coding 项目）

## 2. volcengine / OpenViking

- **来源**：GitHub Trending Python
- **链接**：https://github.com/volcengine/OpenViking
- **一句话解释**：为 AI Agent 设计的“自进化”上下文数据库，将 Agent 的记忆（Memory）、知识（RAG）和技能（Skills）统一管理。
- **它为什么重要**：目前的 Agent 记忆大多是静态的向量检索。OpenViking 提出了“自进化（Self-evolving）”概念，意味着 Agent 在运行过程中，其知识库和技能树会根据交互历史自动重构、合并、提炼。这非常适合用来做长期运行的虚拟生态或 NPC 系统。
- **技术趋势标签**：#Agent-Memory #Self-Evolving #RAG #Game-NPC
- **可复用模式**：**“经验-技能转化（Experience-to-Skill）”模式**。Agent 积累了一定数量的类似对话或操作后，自动将这些经验抽象固化为一个新的“Skill（技能/API 调用）”。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一个“健忘但会记笔记的 NPC”。你和它聊天，它会把聊天记录提炼成“世界观认知”，当认知冲突时，它会自动在数据库中发起“认知重构”。
  2. **一个中型项目**：**“数字炼金术士（Digital Alchemist）”**。在一个虚拟沙盒中，Agent 尝试不同的化学/物理组合，OpenViking 帮它记录失败经验。随着时间推移，它会自己总结出“炼金配方书”（Skills），并能传授给其他 Agent。
  3. **一个艺术/游戏/叙事方向**：**“世代遗传的叙事 Agent”**。一个叙事 Agent 扮演家族第一代，它的记忆和处事原则通过 OpenViking 提炼。当它“死去”时，其自进化出的“技能和记忆库”作为基因遗传给下一代 Agent，实现真正的数字家族传承。
- **对我项目的启发**：在做世界生成或多 Agent 模拟时，不要用硬编码的 RAG，用这种能“自我提炼”的记忆库，NPC 才能展现出突变和成长。
- **今天是否值得深入研究**：是
- **建议行动**：收藏（作为未来构建复杂 Agent 系统的记忆架构储备）

## 3. google-labs-code / stitch-skills

- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/google-labs-code/stitch-skills
- **一句话解释**：谷歌实验室开源的 Agent 技能库，遵循统一的 Agent Skills 开放标准，兼容 Claude Code、Cursor、Gemini CLI 等主流工具。
- **它为什么重要**：它在试图解决“Agent 的工具箱标准化”问题。以前你给 Cursor 写个插件，Claude Code 用不了。现在有了这个标准，你写一次“技能”（比如：操控 Blender 导出 3D 模型），所有主流 Agent 都能直接调用。
- **技术趋势标签**：#MCP #Agent-Skills #Standardization #Creative-Tools
- **可复用模式**：**“技能即协议（Skill as Protocol）”模式**。将复杂的创造性软件（如 Unity、Photoshop、Max/MSP）的 API 封装成符合 Stitch 标准的 Skill，让任何 AI 都能一键接入。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 Stitch Skill，连接到你的 Spotify，让 Claude Code 可以通过分析你当前的代码情绪，自动帮你切换终端背景音乐。
  2. **一个中型项目**：**“AIGC 实体木偶控制器（AI Puppeteer）”**。将 Arduino 控制舵机/LED 的指令封装成 Stitch Skill。你可以直接在 Cursor 里对 AI 说：“让这个实体雕塑根据我刚才写的诗跳个舞”，AI 会自动调用该 Skill 调试硬件。
  3. **一个艺术/游戏/叙事方向**：**“画廊策展人 Agent”**。将“投影仪控制”、“灯光 DMX512 协议”、“音响播放”封装为 Stitch Skills。一个 AI 策展人根据画廊里的观众人数和情绪，实时重写空间内的声光电效果。
- **对我项目的启发**：对于跨学科学生，这是连接“AI 脑”和“物理世界/艺术软件”的绝佳桥梁。你可以把你的 creative coding 库写成 Stitch Skill 供 Agent 调用。
- **今天是否值得深入研究**：是
- **建议行动**：试用（尝试写一个简单的自定义 Skill，看看它是如何与现有 Agent 绑定的）

## 4. Mesh LLM: distributed AI computing on iroh

- **来源**：Hacker News
- **链接**：https://www.iroh.computer/blog/mesh-llm
- **一句话解释**：在 P2P 网络（基于 iroh）上实现分布式 AI 计算，让多台设备（甚至手机、树莓派）协同运行大模型。
- **它为什么重要**：它打破了“AI 必须依赖中心化云端 GPU”的迷思。在艺术装置、去中心化游戏、局域网多玩家世界生成中，如果能利用现场所有观众/玩家的本地设备拼凑成一个“超级大脑”，将产生极具张力的 HCI 体验。
- **技术趋势标签**：#P2P-AI #Decentralized #Edge-Computing #Creative-Network
- **可复用模式**：**“蜂群智商（Swarm Intelligence）”模式**。不追求单体模型的强大，而是通过无中心网络，让轻量级设备通过协同涌现出复杂的决策。
- **疯狂发明家灵感**：
  1. **一个小实验**：用两台旧手机和一台电脑，搭建一个局域网 Iroh 节点，让它们共同预测/生成一段接龙小说，体验无服务器的本地 AI 协作。
  2. **一个中型项目**：**“局域网实体 Agent 生态箱”**。在展厅里放置 5 个树莓派（带小屏幕），每个树莓派运行一个局部模型。它们通过 P2P 物理网络相连，观众挡住其中一个，网络拓扑改变，Agent 的“集体意识”和生成的视觉艺术随之发生突变。
  3. **一个艺术/游戏/叙事方向**：**“暗网剧场（Darknet Theatre）”**。一个只能在特定 P2P 局域网内运行的多人交互叙事游戏。玩家的设备不仅是客户端，也是服务器的一部分。当玩家物理上靠近时，他们的设备通过 Mesh LLM 共同孕育出一个只属于他们这个物理空间的“幽灵 NPC”。
- **对我项目的启发**：对于艺术装置和边缘计算，这提供了一种摆脱 API 账单和网络延迟、实现“物理局域网自主艺术”的新路径。
- **今天是否值得深入研究**：是
- **建议行动**：做demo（在两台本地机器上跑通 iroh 上的 Mesh LLM）

## 5. stablyai / orca

- **来源**：GitHub Trending TypeScript
- **链接**：https://github.com/stablyai/orca
- **一句话解释**：一个专为“多 Agent 舰队（Fleet of parallel agents）”协同工作而设计的桌面与移动端开发环境（ADE）。
- **它为什么重要**：我们正在从“单 Agent 聊天”走向“Agent 军团协同”。Orca 提供了管理并行 Agent 的可视化界面和控制台（HCI 创新），解决了如何让人类直观地监督、调度、指挥一个“Agent 舰队”的难题。
- **技术趋势标签**：#ADE #Agent-Fleet #HCI-for-AI #Multi-Agent
- **可复用模式**：**“仪表盘指挥官（Dashboard Commander）”模式**。设计一个可视化界面，左边是任务流水线，右边是多个 Agent 在沙盒里的实时活动轨迹和通信气泡，人类作为“将军”进行高层干预。
- **疯狂发明家灵感**：
  1. **一个小实验**：在 Orca 中配置三个 Agent：一个写诗，一个将诗翻译成 Emoji，一个把 Emoji 渲染成 ASCII 艺术，观察并调整它们的并行管道。
  2. **一个中型项目**：**“虚拟游戏开发工作室”**。一个 Orca 预设模板，里面包含“关卡设计师 Agent”、“数值策划 Agent”和“文案策划 Agent”。你输入一个主题（如“重力颠倒的迷宫”），它们在并行的沙盒里互相讨论并输出完整的 Minecraft 结构生成代码。
  3. **一个艺术/游戏/叙事方向**：**“众神议事厅（The Pantheon）”**。一个交互式艺术装置，屏幕上是一个虚拟的议事厅（由 Orca 驱动的 Agent 舰队）。每个 Agent 代表一种哲学流派（虚无主义、存在主义、功利主义等）。观众在麦克风里输入一个社会议题，众神开始激烈辩论，并实时生成基于他们辩论的动态雕塑。
- **对我项目的启发**：在设计 Agent 工作流时，界面（HCI）非常重要。研究 Orca 是如何呈现多个 Agent 的状态和交互的，能极大启发你自己的自动化系统 UI 设计。
- **今天是否值得深入研究**：是
- **建议行动**：试用（下载其桌面端，看看它如何组织并行的 Agent 任务）

## 今日模式总结

1. **Agent 终端化与实体化 (Terminal & Physical Agentification)**：以 `claude-code` 和 `stitch-skills` 为代表，Agent 正在脱离网页聊天框，直接接管本地终端和系统级工具，通过统一的“Skill 协议”来控制现实世界和专业软件。
2. **去中心化与边缘协同 (Decentralized Edge Intelligence)**：以 `Mesh LLM` 为代表，AI 计算正在向 P2P 和本地设备群倾斜。不再依赖昂贵的中心化 API，而是通过局域网设备协同，这为物理艺术装置和本地游戏系统提供了无限可能。
3. **多 Agent 舰队的可视化交互 (HCI for Agent Fleets)**：以 `orca` 为代表，如何让人类高效率地指挥、观察、调试数十个并行工作的 Agent，正在成为新一代人机交互设计（HCI）的热点。

## 今日可做小实验

### 项目名：Claude-Code 驱动的“声音反应型” p5.js 画布 (The Audio-Reactive Spec Evolver)

- **输入**：
  - 一个初始的 `sketch.js`（画一个简单的圆）。
  - 一个包含你当前房间环境噪音/麦克风音量的数据文件 `volume.json`（由一个 10 行的 Python 脚本实时写入）。
  - 一个 `spec.md` 规范文件，写着：“当音量大于 0.5 时，画布必须呈现混乱的红色线条；当音量小于 0.1 时，画布必须呈现缓慢移动的蓝色波浪。”
- **输出**：
  - 一个在浏览器中实时运行、并根据你房间声音变化而不断被 **Claude Code 在后台重写** 的 p5.js 动态画布。
- **技术栈**：
  - Node.js (用于运行 live-server 和写入音量数据)
  - Python (用于读取麦克风音量并写入 JSON)
  - Claude Code (终端 Agent)
  - p5.js
- **第一步怎么做**：
  1. 新建一个文件夹，初始化 npm，安装 `live-server` 运行一个包含 `index.html` 和 `sketch.js` 的简单网页。
  2. 写一个简单的 Python 脚本 `sound_monitor.py`，使用 `sounddevice` 库读取麦克风音量，每 3 秒将当前音量级别写入 `volume.json`。
  3. 全局安装并登录 Claude Code (`npm i -g @anthropic-ai/claude-code` 并运行 `claude-code`)。
  4. 在终端中唤醒 Claude Code，对它说：“*请监视 `volume.json` 的变化。根据 `spec.md` 的规则，实时修改 `sketch.js` 中的 p5.js 代码。每次修改后，确保 live-server 刷新能正常显示，不要中断。*”
  5. 对着麦克风大喊一声，或者保持安静，观察 Claude Code 是如何在你没有动手写一行代码的情况下，自动重构你的 creative coding 画布的！
