## 1. SPIN: 工业级任务的结构化 LLM 规划
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2605.14051
- 一句话解释：通过将 LLM 的模糊规划转化为验证过的 DAG（有向无环图），解决 Agent 乱写工作流的问题。
- 它为什么重要：它是 **Spec-driven development** 的硬核体现。它不让 LLM 随性发挥，而是强制其输出符合逻辑结构的“图”，极大降低了自动化系统的崩溃率。
- 技术趋势标签：#Spec-Driven #Workflow #DAG
- 可复用模式：**“先验证结构，后执行步骤”**。在生成复杂系统（如 Minecraft 建筑或代码架构）前，先强制生成一个可校验的拓扑图。
- 疯狂发明家灵感：
  1. 一个小实验：做一个“食谱图生成器”，输入食材，它必须先输出一张合乎逻辑的烹饪流程 DAG，才能开始生成具体步骤。
  2. 中型项目：**Minecraft 自动化建造师**。用户说“造个城堡”，Agent 先生成 DAG（地基->墙->塔楼），每一步必须验证前置条件。
  3. 艺术/叙事：**非线性叙事生成器**。确保生成的支线剧情逻辑自洽，不会出现“角色已死但又说话”的逻辑 Bug。
- 对我项目的启发：在你的自动化工具链中，引入一个“结构校验层”，把 LLM 的输出限制在特定的 Spec 协议内。
- 今天是否值得深入研究：是
- 建议行动：做 demo (试着用 JSON Schema 强制 LLM 输出 DAG 结构)

## 2. SimPersona: 从原始点击流中学习离散买家画像
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2605.14205
- 一句话解释：不再用枯燥的 Prompt 定义 NPC，而是通过观察用户的真实行为轨迹（点击流）自动反推并建模出“有灵魂”的 Agent 画像。
- 它为什么重要：对于游戏系统和 HCI 非常关键。它提供了一种**“由内而外”生成个性**的方法，而不是靠人为预设。
- 技术趋势标签：#NPC #BehavioralModelling #HCI
- 可复用模式：**“轨迹即性格”**。记录用户在虚拟空间的位置/交互序列，将其转化为 Agent 的驱动特征。
- 疯狂发明家灵感：
  1. 一个小实验：记录你一周的 shell 命令历史，训练一个“命令行分身” Agent。
  2. 中型项目：**Minecraft 观察者 NPC**。它不说话，只是观察你在服里的行为（是喜欢挖矿还是拆迁），然后进化出对应的社交态度。
  3. 艺术/叙事：**自适应数字艺术展**。作品根据观众在展厅的走位路径，实时生成一个代表该观众个性的 Agent 形象。
- 对我项目的启发：思考如何把“用户行为数据”作为 Agent 生成系统的输入，而不仅仅是文字描述。
- 今天是否值得深入研究：是
- 建议行动：收藏

## 3. EASM: 情绪感知的状态化记忆架构
- 来源：arXiv cs.HC
- 链接：https://arxiv.org/abs/2605.14833
- 一句话解释：给 Agent 的长短期记忆加上一层“情绪权重”，让它能记住那些让它“生气”或“开心”的交互细节。
- 它为什么重要：解决了 LLM 记忆“冷冰冰”的问题。在艺术创作和人机交互中，**情绪的一致性**比事实的准确性更能建立连接。
- 技术趋势标签：#EmotionalAI #Memory #Personalization
- 可复用模式：**“情绪加权检索”**。在 RAG（检索增强生成）中，不仅搜索语义相似度，还搜索情绪匹配度。
- 疯狂发明家灵感：
  1. 一个小实验：写个脚本，把你的聊天记录按“情绪值”打标，做一个“坏情绪检索器”。
  2. 中型项目：**有脾气的创意助手**。如果你一直否定它的建议，它的记忆检索会变得消极，甚至拒绝工作。
  3. 艺术/叙事：**动态演化的交互式剧本**。角色对玩家的记忆是带感情色彩的，这直接决定了结局走向。
- 对我项目的启发：在你设计的 Agent 工作流中增加一个 `emotion_state` 变量，影响后续的 Tool Use 决策。
- 今天是否值得深入研究：是
- 建议行动：试用 (尝试在 Prompt 中引入情绪状态机)

## 4. PREPING: 无需任务的 Agent 预备记忆构建
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2605.13880
- 一句话解释：Agent 在正式干活前，先通过“闲逛”和“观察”环境来构建预备知识，解决“冷启动”问题。
- 它为什么重要：这非常像**世界生成（World Generation）**中的“前传”逻辑。Agent 不再是空降兵，而是“本地人”。
- 技术趋势标签：#ColdStart #WorldBuilding #AutonomousAgent
- 可复用模式：**“先探索，后行动”**。在分配任务前，先运行一个探索脚本生成环境快照。
- 疯狂发明家灵感：
  1. 一个小实验：让 Agent 先读完你整个项目的 README 和文件树，但不给它任务，只让它写一份“环境初印象”。
  2. 中型项目：**Minecraft 自动勘探员**。在玩家进入前，Agent 先生成一份地质报告和生存建议。
  3. 艺术/叙事：**生成式历史背景**。为你的游戏世界先跑一遍“历史模拟”，生成的记忆作为所有 NPC 的初始背景。
- 对我项目的启发：优化你的开发工作流，让 Agent 在写代码前先执行一个 `survey` 步骤来理解上下文。
- 今天是否值得深入研究：否 (理念重要，但实现可能较重)
- 建议行动：忽略 (暂存想法即可)

## 5. LOOP Skill Engine: 一次性录制与确定性回放
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2605.14237
- 一句话解释：结合了 LLM 的灵活性和传统宏录制的确定性，让 Agent 像人类录制宏一样学习复杂技能，然后 99% 成功率重放。
- 它为什么重要：**这是解决 LLM 随机性（Stochasticity）的神器。** 对于需要精确操作的 Creative Coding 或自动化工具极其有用。
- 技术趋势标签：#DeterministicAI #Automation #SkillLearning
- 可复用模式：**“LLM 编排 + 确定性脚本执行”**。用 LLM 决定“什么时候用什么宏”。
- 疯狂发明家灵感：
  1. 一个小实验：录制一段你在 Photoshop 或 Blender 里的操作序列，让 LLM 根据你的口令自动触发这段“技能”。
  2. 中型项目：**Creative Coding 技能库**。把复杂的 P5.js 绘图逻辑封装成“技能”，Agent 通过自然语言调用并微调参数。
  3. 艺术/叙事：**确定性叙事节点**。关键剧情通过录制的“技能”执行，保证视觉表现的完美，而分支逻辑交给 LLM。
- 对我项目的启发：不要试图让 LLM 每次都写代码，应该建立一个“技能库”，让它做选择题。
- 今天是否值得深入研究：**是 (强烈推荐)**
- 建议行动：做 demo

## 今日模式总结
1.  **结构化约束 (Structural Constraint)**：从随性生成转向 DAG 和 Spec 协议，确保复杂系统的稳定性。
2.  **具身记忆 (Embodied Memory)**：记忆不再是单纯的文本，而是带有情绪权重、环境预感和行为轨迹的综合体。
3.  **确定性技能化 (Skill Determinism)**：通过录制重放技术，将 LLM 的灵活性与传统自动化的可靠性结合。

## 今日可做小实验：【情绪驱动的创意终端】
- **项目名**：Mood-Terminal-Painter
- **输入**：用户的一段日常对话或心情描述。
- **输出**：根据对话中的“情绪记忆”实时生成的 P5.js 艺术画作片段。
- **技术栈**：Python (FastAPI) + OpenAI API (带情绪分析 Prompt) + P5.js (前端显示)
- **第一步怎么做**：
    1. 写一个简单的 Prompt，要求 LLM 将输入的文本转化为 5 个参数：`calmness`, `energy`, `chaos`, `warmth`, `sharpness` (0-1)。
    2. 将这些参数映射到 P5.js 的绘图函数（如：`chaos` 影响粒子扰动，`warmth` 影响色调）。
    3. 连续输入三段话，让 Agent 维护一个“情绪状态机”，观察画作是如何随着你的心情“进化”的。
