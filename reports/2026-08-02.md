## Karpathy 的单机自主科研 Agent Loop (karpathy/autoresearch)
- 来源：GitHub Trending Python
- 链接：https://github.com/karpathy/autoresearch
- 一句话解释：Karpathy 写的极简自循环 Agent，能在单卡上自动修改代码、训练模型、评测结果并自我迭代科研假设。
- 它为什么重要：它把“假设 -> 代码改动 -> 验证运行 -> 结果评估 -> 丢弃/Git Commit”这一整套 **Hypothesis-Driven (Spec-driven) 闭环** 给完全自动化了！代码极其干净，是极佳的闭环模板。
- 技术趋势标签：`Autonomous Research` `Closed-Loop Agent` `Self-Evolution`
- 可复用模式：自动修改代码 -> 沙盒无干预运行 -> 提取量化指标 -> 决策分支（保留/回滚代码）。
- 疯狂发明家灵感：
  1. 一个小实验：写一个闭环 Agent，让它自动修改一段 GLSL 着色器代码，无头渲染截图后算图像熵（视觉丰富度），自动寻找最狂野的算法。
  2. 一个中型项目：游戏平衡性自适应 Agent——在 Minecraft 或微型跑酷世界里无头运行，Agent 自动修改规则与地形 Spec 并跑通关测试，演化出“最反直觉但可通关”的关卡。
  3. 一个艺术/游戏/叙事方向：“自己进化规则的数字创世神”——Agent 在离线沙盒里持续修改细胞自动机规则，根据“系统涌现复杂度”指标自动保留规则，每天清晨为你输出一种全新的生命形态。
- 对我项目的启发： Agent 不仅可以帮你“写”代码，更可以作为你的“离线演化引擎”，趁你睡觉时跑上百轮参数与规则测试。

## 字节跳动长时程多 Agent 任务调度框架 (bytedance/deer-flow)
- 来源：GitHub Trending Python
- 链接：https://github.com/bytedance/deer-flow
- 一句话解释：结合沙盒、长短期记忆、技能树和子 Agent 网关，能稳定处理几分钟到数小时长任务的超级 Agent 架构。
- 它为什么重要：解决复杂项目中的“上下文漂移（Context Drift）”问题。要让 AI 做大型复杂项目（生成一整套带代码的游戏、几十万字的设定集），这种挂载沙盒与网关的分层架构是必经之路。
- 技术趋势标签：`Long-Horizon Agent` `Subagent Hierarchy` `Multi-Agent Gateway`
- 可复用模式：高层 Spec 拆解 -> 派发给异步子 Agent -> 隔离沙盒执行 -> 统一消息网关（Message Gateway）汇总状态。
- 疯狂发明家灵感：
  1. 一个小实验：搭建一个微型多 Agent 网关，并发启动 3 个 Agent：一个编剧、一个三维建模 Spec 生成器、一个着色器生成器，最终组合成一个 3D 房间。
  2. 一个中型项目：自动化游戏 Dungeons 生成器——输入一个世界观主题，后端运行数小时，自动产出地形 Spec、NPC 对话树、LUA 逻辑脚本并打包成可玩 Demo。
  3. 一个艺术/游戏/叙事方向：“跨昼夜的生成式世界”——一个离线跑在服务器上的地下城 Agent，持续在后台沙盒中演算世界变迁，每天向玩家推送变异后的游戏地图文件。
- 对我项目的启发：做复杂的生成式/艺术系统时，千万别试图用单一对话解决，要学会构造长时程、分工明确的 Agent 工作流（Flow）。

## 专为小说与互动游戏打造的叙事 AI Agent (Narcooo/inkos)
- 来源：GitHub Trending TypeScript
- 链接：https://github.com/Narcooo/inkos
- 一句话解释：将小说编写、剧本创作、翻译与互动游戏生成整合在同一套管线中的叙事 AI Agent。
- 技术趋势标签：`Narrative Systems` `Interactive Storytelling` `Creative Agent`
- 它为什么重要：把通用 LLM 转化为特定领域的创意工具（Creative Tool），必须用结构化的逻辑约束生成过程，这个项目示范了如何将“叙事结构”转化为 Agent 的操作步骤。
- 可复用模式：将世界观规则、NPC 心理状态、剧情分支映射为可检索的上下文图谱，动态注入生成链。
- 疯狂发明家灵感：
  1. 一个小实验：截取你在 Minecraft 里的聊天记录，让这个 Agent 自动解析玩家行为，并实时生成带有“克苏鲁神话”风格的节点式文本冒险剧本。
  2. 一个中型项目：基于 Spec 的互动剧本 Visual Debugger——在节点图里写剧情约束（Spec），Agent 填补对话，当 NPC 行为违背世界观设定时进行可视化报错。
  3. 一个艺术/游戏/叙事方向：开放世界中的“实时历史记载者”——NPC 发生的每一次冲突都会被 Agent 解析为历史文献，随玩家探索实时编撰为可阅读的“游戏内古籍”。

## 团队级 AI Agent 记忆基础设施 (TencentCloud/TencentDB-Agent-Memory)
- 来源：GitHub Trending TypeScript
- 链接：https://github.com/TencentCloud/TencentDB-Agent-Memory
- 一句话解释：将对话、文档和代码提炼为四类结构化资产（Chat Memory, Skill, LLM-Wiki, Code-Graph）的 Agent 记忆中枢。
- 它为什么重要：单纯的向量检索（Vector RAG）在复杂系统里极易失效。这个项目把记忆显式分层为“知识 Wiki”和“代码依赖图谱（Code-Graph）”，对 Spec-driven 架构非常有启发。
- 技术趋势标签：`Code-Graph Memory` `LLM-Wiki` `Agent Infrastructure`
- 可复用模式：知识不再是离散文本段，而是提取成“可调用的 Skill”与“强关系的 Graph/Wiki”。
- 疯狂发明家灵感：
  1. 一个小实验：写个脚本解析你当前的跨学科项目代码与设计笔记，提炼出一份 Agent 可读取的 Code-Graph。
  2. 一个中型项目：个人跨学科项目 Spec 进化器——AI 会根据你的项目历史，把你的设计偏好自动沉淀为“设计规范 Skill”，开新项目时自动加载。

## 今日模式总结

1. **闭环演化与假设驱动 (Hypothesis-Driven Evolution)**
   以 Karpathy 的 `autoresearch` 为代表：系统不再需要人工介入每一步，而是定义好规范（Spec）和评估指标（Metrics）后，让 Agent 在沙盒中不断修改代码、测试、自我迭代。
2. **长时程架构与状态沙盒 (Long-Horizon Sandbox Engineering)**
   以 `deer-flow` 为代表：解决 AI 飘忽不定的关键在于拆分。长任务必须有消息网关、独立的子 Agent 和沙盒运行环境，避免主流程上下文被污染。
3. **显式结构化记忆 (Explicit Knowledge & Graph Memory)**
   以 `TencentDB-Agent-Memory` 和 `inkos` 为代表：简单的向量检索时代结束了，未来的 Agent 记忆需要显式的上下文映射——包括 Code-Graph、LLM-Wiki 和特定领域的叙事结构图。

## 今日可做小实验

**实验项目名：** `Auto-Shader-Evolution`（自动进化着色器闭环）

- **输入：** 一段最基础的、能正常编译的单色 GLSL Fragment Shader 代码文件（如 `shader.frag`）。
- **输出：** 经过 5 轮“修改代码 -> 渲染 -> 计算视觉丰富度 -> 保留/回滚”循环后，进化出来的狂野 GLSL 着色器及其渲染图片。
- **技术栈：** Python + OpenAI / Claude API + `moderngl`（用于无头渲染 GLSL 截图） + `Pillow`（计算图像灰度直方图熵/视觉复杂度）。
- **第一步怎么做：**
  写一个 30 行 Python 脚本：
  1. 用 `moderngl` 加载基础 GLSL 代码，渲染成 512x512 的 PNG 图片。
  2. 用 `Pillow` 读取图片并计算图像的信息熵（Image Entropy，数值越高代表视觉元素越丰富）。
  3. 调通这个无头渲染与评估流程后，写 Prompt 让 LLM 尝试修改该 GLSL 代码（要求保持编译不报错），如果新代码渲染出来的熵高于上一轮，则保留代码，否则回滚！跑 5 轮看看它能进化出什么。
