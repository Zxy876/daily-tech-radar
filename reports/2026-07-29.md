## [Spatially-Anchored Previews] 空间锚定预览：VR 中基于 LLM 的几何体编辑

- **来源**：arXiv cs.HC
- **链接**：https://arxiv.org/abs/2607.23201
- **一句话解释**：在 3D/VR 界面中，不再让用户和 AI 玩文字对话，而是直接把 LLM 解析出的模糊意图转换成悬浮在空间中的“半透明幽灵预演（Ghosting Preview）”，让用户用视觉消歧代替语言沟通。
- **它为什么重要**：告别了传统的“对话框黑盒”。将生成式 AI 的概率推测过程**实体化、空间化**，是未来 3D 创作工具、空间计算以及 Minecraft/游戏关卡编辑器最核心的 HCI（人机交互）范式转变。
- **技术趋势标签**：HCI / Spatial Computing / Generative 3D Tool / LLM-Assisted Design
- **可复用模式**：**"Think-in-Space" Preview State（空间中间态预览）** —— 在用户点击“确认生成”之前，Agent 必须把其内部候选解渲染为低保真、可交互的空间幽灵线框。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一页 Three.js 网页。输入自然语言“在桌面放两盏灯”，LLM 返回 3 组坐标，网页上不直接生成灯，而是生成 3 组半透明的光斑幽灵，点击鼠标选定一组后才变成实体 3D 模型。
  2. **一个中型项目**：Minecraft “建筑预知” Mod。当玩家输入“生成一座哥特风格的长廊”，游戏不直接轰炸方块，而是在地面标记出半透明的光影建筑骨架，玩家走进去可以拉伸骨架修改布局，确认后再让 Agent 进行方块充填。
  3. **一个艺术/游戏/叙事方向**：幽灵建筑学（Ghost Architecture）解谜游戏。玩家扮演一个能看到“未来建筑可能态”的遗迹解构师，LLM 根据诗歌或古籍描述生成虚拟空间残影，玩家需要与这些空间残影互动、拼接以重构遗迹。
- **对我项目的启发**：做 Spec-driven 工具时，不要让 AI 一步到位（Overcommitment）。暴露 Agent 的“概率空间”作为中间 Spec UI，能大幅降低交互焦虑和修改成本。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## [SF-AMS] Agent 记忆系统的主动“策略性遗忘”

- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2607.22562
- **一句话解释**：解决长上下文 Agent 越聊越笨的问题——通过建立结构化记忆的主动“遗忘”机制，动态剪枝低价值和冗余信息，维持高效率的长短期记忆。
- **它为什么重要**：现在的 Agent 不是记性不好，而是“什么都记”导致提示词被噪音填满。让 Agent 学会像人类一样“主动遗忘/归档”，是构建永续运行（Long-running）NPC、Minecraft 自主建造 Agent 的关键技术。
- **技术趋势标签**：LLM Agent / Memory Management / Strategic Forgetting / Dynamic Context
- **可复用模式**：**Utility-Driven Memory Pruning（效用驱动的记忆剪枝）** —— 给每一条 Memory 附加动态衰减权重，当 Memory 超过阈值时，触发结构化“压缩与遗忘”算子，而不是简单的 FIFO 队列。
- **疯狂发明家灵感**：
  1. **一个小实验**：用 Python 写一个控制台对话 Agent，给每条 Memory 加上“情绪留存度”和“使用频次”的衰减公式，连续对话 20 轮后，打印出它主动“忘掉”了哪些废话，保留了哪些关键设定。
  2. **一个中型项目**：具备“创伤与淡忘”机制的 Minecraft NPC 村民。NPC 会记住玩家摧毁村庄的暴行，但随着时间和玩家的赎罪行为，LLM Agent 会对“仇恨记忆”进行权重降低和抽象归档（从具体的“他打破了我的门”变成抽象的“这人曾经有点危险”），动态改变 NPC 的态度。
  3. **一个艺术/游戏/叙事方向**：“阿尔茨海默式”解谜游戏。AI 主角是一个记忆不断流失的侦探，玩家需要在 AI 的记忆拓扑图中帮助它决定“遗忘什么、保留什么”才能凑齐线索，不同的遗忘策略会导致最终推理出完全不同的故事真相。
- **对我项目的启发**：在设计多 Agent 协作或自动化系统（如 Drift / Agent Workflow）时，不要盲目往 Vector DB 里扔数据，必须设计主动的 Memory Pruning 规则，避免 Agent 被历史废料“毒害”。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## [DeepLens] 5 阶段 Harnessing 流水线：小推理模型逆袭顶尖大模型

- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2607.22555
- **一句话解释**：提出一种名为 DeepLens 的 5 阶段 Harnessing 架构（事实提取 -> 知识检索 -> 差异分析 -> 诊断推理 -> 解释选择），通过严格的 Stage-Gated Workflow 设计，让小尺寸模型在复杂诊断任务上超越了单次 Prompt 的顶尖大模型。
- **它为什么重要**：证明了“工作流架构（Harness/Workflow） > 模型绝对参数量”。对独立开发者来说，用精细的 Spec 和 Workflow 编排本地小模型（如 Llama-3 8B / DeepSeek 7B），成本极低且效果反超黑盒大模型。
- **技术趋势标签**：Agentic Workflow / Small LLM Harnessing / Spec-Driven Architecture / Multi-Stage Pipeline
- **可复用模式**：**Stage-Gated Harnessing（分阶段关卡控制）** —— 将复杂任务分解为绝对隔离的若干阶段，上一阶段的输出是下一阶段严格的 Spec（JSON/Schema），严禁盲目一步到位。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个用开源小模型的 3 阶段 Code Generator 脚本：阶段 1 提取设计需求要素 -> 阶段 2 匹配代码规范 Spec -> 阶段 3 生成代码。对比直接单次 Prompt 生成的代码质量。
  2. **一个中型项目**：关卡设计 Spec 生成器。阶段 1 提取玩家情绪曲线 -> 阶段 2 检索游戏机制库 -> 阶段 3 布局结构校验 -> 阶段 4 导出为 Minecraft 结构文件（.nbt）。全流程用极小本地模型运行。
  3. **一个艺术/游戏/叙事方向**：“接力创世”艺术装置。5 个微型 AI Agent 依次排列，各自只负责极小的一个维度（1. 气味 -> 2. 色彩 -> 3. 材质 -> 4. 声音 -> 5. 空间渲染），上一级的输出成为下一级的严苛限制 Spec，形成高精度的生成链条。
- **对我项目的启发**：极其契合 Spec-Driven Development 理念！系统设计时不要试图写一段万能的超级 Prompt（Prompt Engineering），而是应该用软件工程思想拆解阶段（Stage），用严格的数据格式约束阶段间的传递。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 今日模式总结

1. **空间与视觉中介态（Spatial Intermediate States）**：不再直接跳到最终生成结果，而是将 LLM 的多可能性推测在界面中以“幽灵/预览”态展示，让人与 AI 在“中间态”高频交互。
2. **策略性遗忘（Strategic Forgetting）**：Agent 长久运行的核心不在于“无限上下文”，而在于给记忆建立衰减模型，主动修剪不重要的历史信息。
3. **分阶段关卡控制（Stage-Gated Harnessing）**：用高度定制、逐步校验的 Workflow 替代通用大模型的单次推理，小模型加严苛 Spec 可以产生暴击效果。

## 今日可做小实验

### 项目名：`GhostSpec-3D`（空间幽灵 Spec 预览器）

- **输入**：一句自然的 3D 布局指令（例如：“在桌子上摆一个红色苹果和一个咖啡杯”）。
- **输出**：一个在浏览器中运行的 Three.js 场景。输入指令后，场景中出现 2 组不同排列方案的“半透明幽灵 Wireframe”和确认按钮，点击后实体化。
- **技术栈**：HTML + Three.js + OpenAI/DeepSeek API (使用 JSON Mode)。
- **第一步怎么做**：
  1. 创建一个简单的 `index.html`，通过 CDN 引入 Three.js。
  2. 写一个简单的 LLM API 请求，要求 LLM 返回严格的 JSON Spec：
     `[{"object": "apple", "pos": [0,1,0], "color": "red"}, {"object": "cup", "pos": [0.5,1,0], "color": "blue"}]`
  3. 解析该 JSON，用 `mesh.material.opacity = 0.4` 和 `wireframe: true` 在 Three.js 场景中渲染出“半透明幽灵预览”，并绑定一个 HTML 确认按钮，点击后将 material 替换为不透明材质。
