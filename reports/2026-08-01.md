## [1] HexStrike AI：把 150+ 异构工具打造成 Agent 的肉身武器库
- 来源：GitHub Trending Python
- 链接：https://github.com/0x4m4/hexstrike-ai
- 一句话解释：通过 MCP (Model Context Protocol) 协议，把 150 多个黑客攻防命令行工具打造成一个统一的 Agent 服务端，让 LLM 变身全自动网络攻防指挥官。
- 它为什么重要：它展示了 **MCP 协议的暴击力**——你不需要重写任何底层工具，只需用 MCP 包装一层，LLM 就能瞬间获得极其庞大且精确的现实世界“工具操控权”。
- 技术趋势标签：MCP / Agent Tooling / CLI Automation / Orchestration
- 可复用模式：`统一协议（MCP）包裹异构CLI集群 -> LLM层负责意图拆解与编排 -> 自动化并发执行`
- 疯狂发明家灵感：
  1. **一个小实验**：写一个 MCP Server 把 Blender 的命令行模式包装起来（包含 10 个 Python 渲染脚本），让 Claude 仅凭自然语言就自动完成 3D 资产的烘焙、减面和导出。
  2. **一个中型项目**：“疯狂数字考古 Agent”——挂载 20 个老旧游戏资源解包工具（如 FFmpeg、QuickBMS、Spriters Resource CLI），让 Agent 全自动解包 2000 年代的经典游戏数据并分类重构成现代 Unity 格式。
  3. **一个艺术/游戏/叙事方向**：“赛博黑客控制台”沉浸式游戏——玩家扮演黑客组织高层，只需用自然语言下达战略指令，后台 Agent 实时调用真实的安全/网络 CLI 工具，将终端数据瀑布流实时转化为游戏的赛博 UI 视觉效果。
- 对我项目的启发：创意工具开发不用再花大把时间写复杂的按钮 UI，直接写一堆无头 CLI 工具并暴露为 MCP，让 LLM 当你的“全局控制台”。

## [2] TraceCoder：带“修改基因树”的可审计生成代码
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2607.26307
- 一句话解释：为 LLM 生成的代码引入“代码片段版本树（Position-Key Snippet Versioning）”与位置键追踪，使每一行代码的演化路径、修改动机和调试历史完全透明可查。
- 它为什么重要：极大解决了 AI 编程“黑盒生成”和“改着改着代码就崩盘”的痛点，这是实现真正可靠的 **Spec-Driven Development（规范驱动开发）** 的关键砖石。
- 技术趋势标签：Spec-driven Development / Traceable CodeGen / Code Versioning / HCI
- 可复用模式：`行级/节点级元数据标记 + 变更意图因果图 + 精确可回溯的演化树`
- 疯狂发明家灵感：
  1. **一个小实验**：做一个 VS Code 微型插件，高亮 AI 生成的代码，悬停时悬浮框不只显示代码，而是显示“AI 做出这行修改时对应的 Spec 规则和思考过程”。
  2. **一个中型项目**：“自愈与溯源演进引擎”——给 Minecraft / 游戏逻辑脚本建立 Spec 绑定的 Trace 图，只要游戏发生 Bug，系统能像 `git bisect` 一样精准定位到是哪一步 Prompt 修改打破了逻辑链。
  3. **一个艺术/游戏/叙事方向**：“代码基因演化图谱”生成艺术——将一段算法代码视作生命体，玩家通过修改规则文本来控制它的演化，系统实时将代码的演变路径可视化为一棵绚丽的树状“基因图谱”。
- 对我项目的启发：把 Spec 视作“绝对规范”，把代码视作“附带溯源标记的生成产物”，这能大幅提升代理工作流与程序化生成系统的稳定性。
- 今天是否值得深入研究：是
- 建议行动：做demo

## [3] CaM-Wolf：多模态因果感知狼人杀 Agent
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2607.26393
- 摘要/一句话解释：为狼人杀等社交博弈游戏中的 AI Agent 引入多模态感知（视觉/声音/文本）和因果推理图，让 Agent 具备真正的欺骗、说谎与深层社交博弈能力。
- 它为什么重要：非对称信息博弈是 AI 表现出“人类灵性”的最佳试验场。引入多模态与因果推断（Causal Reasoning），为复杂系统中的**涌现式叙事（Emergent Narrative）**提供了核心驱动力。
- 技术趋势标签：Multimodal Agents / Game Systems / Emergent Narrative / Causal Reasoning
- 可复用模式：`多模态信号输入 -> 动态因果信念图谱（Belief Graph）更新 -> 非对称博弈决策`
- 疯狂发明家灵感：
  1. **一个小实验**：搭建一个“微表情盲盒谈判 NPC”——通过摄像头看玩家表情，结合文本对话，实时维护一个对玩家的“信任/怀疑因果图”，并在终端打出 NPC 的心理变化图。
  2. **一个中型项目**：Minecraft 里的“密室潜伏者 Agent”——在多玩家服务器中加入一个具有多模态感知能力的 NPC，它会观察玩家的搭建行为、听玩家的语音，并在暗中推断玩家意图从而布下陷阱或建立联盟。
  3. **一个艺术/游戏/叙事方向**：“阿加莎式动态悬疑剧场”——由 5 个拥有隐秘因果信念图谱的 AI NPC 主持的交互剧场，玩家需要根据他们的肢体动作、话语矛盾来推翻他们的谎言并解开悬案。
- 对我项目的启发：NPC 不再是静态的对话树，而是可以被“因果信念图谱”驱动的概率推理机器，这能极大地丰富游戏系统的深度。
- 今天是否值得深入研究：是

## [4] Networked Intelligence：打破单窗口的共享上下文图谱 (Active Shared Context Graph)
- 来源：arXiv cs.HC
- 链接：https://arxiv.org/abs/2607.13220
- 一句话解释：摒弃传统“单人单聊天框”的 AI 交互范式，构建“动态共享上下文图谱”，让多人团队与多个 AI 能够在同一个可视化网络中并行探索与协同推理。
- 它为什么重要：它不盲目追求盲目加长 context window，而是通过**空间化/拓扑化 HCI** 重构了人与 AI 共同思考的方式，非常适合设计与跨学科团队。
- 技术趋势标签：HCI / Creative Tool / Context Engineering / Shared Knowledge Graph
- 可复用模式：`上下文空间节点化 -> 多人与多 Agent 拓扑同步 -> 异构分支并行推理与碰撞`
- 疯狂发明家灵感：
  1. **一个小实验**：写一个无限画布（Infinite Canvas）前端，节点可以是文本、图片或 Spec，拉一条线连到 Agent 节点就能自动将前置节点的上下文融合成新的思维分支。
  2. **一个中型项目**：“无形第三人脑暴助手”——一个常驻在 Canvas/Obsidian 图谱上的 Agent，它会实时监听团队多人的节点更新，自动在冲突概念或悬空节点之间连线并生成“思维桥梁提案”。
  3. **一个艺术/游戏/叙事方向**：“群智世界观构建仪”——多个创作者在巨大图谱上投放概念（如“蒸汽朋克”、“魔法真菌”），多个专职 AI（地理、历史、角色）根据图谱的链接密度实时生成 3D 拟态世界块。
- 对我项目的启发：把上下文从“隐式堆叠的文本历史”显式化为“可交互的空间图谱”，这绝对是下一代 Creative Coding 工具的核心方向。

## 今日可做小实验：Spec-Trace 极简代码改动溯源器

让我们结合 **TraceCoder** 的灵感，做个 2 小时内能搞定的微型控制台工具！

- **项目名**：`SpecTrace-CLI`
- **输入**：
  1. 一份简易 Spec 文件 (`spec.md`，比如：规定“所有变量名必须是动物名”以及“函数必须带有 Print 日志”)。
  2. 一段原始 Python 代码。
  3. 一句改动需求（比如：“增加一个计算斐波那契数列的函数”）。
- **输出**：
  1. 修改后的代码（每行末尾带有 ` # [Spec-01|Intent: ...] ` 注释）。
  2. 终端里用彩色树状图打出的 `Spec条目 -> 对应修改的代码行 -> 变更原因` 拓扑树。
- **技术栈**：Python + OpenAI/LiteLLM SDK + `rich` 库（用来画极其漂亮的终端树）。
- **第一步怎么做**：
  1. 打开终端，新建目录并安装依赖：`pip install openai rich pydantic`
  2. 创建 `main.py`，设计一个 Prompt 模版，要求 LLM 返回 Structured Output (JSON)，结构包含 `updated_code` 和一个列表 `traces: [{spec_id, line_number, rationale}]`。
  3. 读取本地 `spec.md` 和源码，调用 LLM，拿到 JSON 后使用 `rich.tree.Tree` 将 Trace 渲染在终端里！
