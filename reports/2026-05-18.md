## 1. Shadowbroker：全球剧院的“上帝视角”
- **来源：** GitHub Trending
- **链接：** https://github.com/BigBodyCobain/Shadowbroker
- **一句话解释：** 一个聚合了私人飞机追踪、间谍卫星、地震事件等全球数据的开源情报（OSINT）平台，并预留了 AI Agent 接口。
- **它为什么重要：** 它把原本支离破碎的真实世界遥感/追踪数据整合进了一个“统一界面”，这不仅是情报工具，更是一个**巨大的叙事引擎**。
- **技术趋势标签：** #OSINT #DataVisualization #RealWorldAgent
- **可复用模式：** “真实世界遥感数据 + LLM 关联分析”。
- **疯狂发明家灵感：**
  1. **一个小实验：** 挂载一个 Agent 监控马斯克的飞机轨迹，结合当地天气和新闻，自动生成“硅谷钢铁侠的今日心情预测”。
  2. **一个中型项目：** “末日生存仪表盘”——整合地震、卫星热异常（火灾）和航班流量，为数字游民自动规划最安全的避难迁徙路线。
  3. **一个艺术/游戏/叙事方向：** **《地球模拟器：真实现场》**。一个 Minecraft 服务器，其内部的天气、灾难、甚至某些 NPC 的移动路径，完全由 Shadowbroker 抓取的现实世界数据实时驱动。
- **对我项目的启发：** 如果要做世界生成或游戏系统，不要只用随机噪声，尝试用“真实世界的影子”作为随机种子。
- **今天是否值得深入研究：** 是
- **建议行动：** 做 demo（尝试拉取其 API 并让 LLM 解释一段轨迹数据）。

## 2. Semble：Agent 的“外科手术式”代码搜索
- **来源：** Hacker News / Show HN
- **链接：** https://github.com/MinishLab/semble
- **一句话解释：** 比 grep 节省 98% token 的代码搜索工具，专为 Claude Code 等 Agent 设计，避免 Agent 盲目读取整屏文件。
- **它为什么重要：** 在 Spec-driven development 中，最大的成本和瓶颈是 Token 消耗和上下文污染。Semble 提供了一种更廉价、更精准的方式让 Agent “看”代码。
- **技术趋势标签：** #AgentEfficiency #TokenOptimization #CodeSearch
- **可复用模式：** “语义索引 + 极简上下文返回”。
- **疯狂发明家灵感：**
  1. **一个小实验：** 将你的个人艺术项目库用 Semble 索引，看它能否在不读取整个 main.js 的情况下找到你定义的某个奇怪的 shader 变量。
  2. **一个中型项目：** “极低功耗的代码解释器”——在单片机或受限环境下，通过 Semble 远程指引 Agent 修改本地代码。
  3. **一个艺术/游戏/叙事方向：** **《代码考古学》**。一个交互艺术装置，观者输入一句话，Agent 使用 Semble 在海量开源代码中寻找“最像诗句”的代码行。
- **对我项目的启发：** 优化你的自动化工作流，不要把所有代码塞给 LLM，先用 Semble 做预筛选。
- **今天是否值得深入研究：** 是
- **建议行动：** 试用（集成到你目前的开发流中）。

## 3. Skillkit：Agent 的“便携式技能盘”
- **来源：** GitHub Trending
- **链接：** https://github.com/rohitg00/skillkit
- **一句话解释：** 让 AI Agent 的技能（Skill）变得可移植，一次编写，即可在 Claude Code、Cursor、Copilot 等 40 多个平台上使用。
- **它为什么重要：** 现在的 Agent 像碎片化的孤岛。Skillkit 试图建立一种“Agent 的 DNA 标准”，让你定义的“画图技能”或“部署技能”到处通用。
- **技术趋势标签：** #AgentInteroperability #SkillRegistry #SpecDriven
- **可复用模式：** “标准化动作定义 (MCP) + 多平台翻译层”。
- **疯狂发明家灵感：**
  1. **一个小实验：** 编写一个“Minecraft 指令集技能”，尝试让它在 Cursor 里写代码的同时，控制游戏里的方块生成。
  2. **一个中型项目：** “疯狂发明家技能商店”——建立一套你特有的、针对 Creative Coding 的 Agent 技能库（如：自动调色、自动生成 p5.js 模板）。
  3. **一个艺术/游戏/叙事方向：** **《技能交换集市》**。一个多 Agent 社交实验，不同的 Agent 拥有不同的 Skillkit 插件，它们必须通过互相“交换技能”来完成一个复杂的艺术创作任务。
- **对我项目的启发：** 你的 Spec-driven workflow 应该沉淀为一套 Skillkit 技能，而不是散落在各处的 Prompt。
- **今天是否值得深入研究：** 是
- **建议行动：** 收藏（作为 Agent 架构的参考）。

## 4. Shannon：自主式“白盒”渗透 Agent
- **来源：** GitHub Trending
- **链接：** https://github.com/KeygraphHQ/shannon
- **一句话解释：** 一个全自动的 AI 渗透测试员，它会读源码、找漏洞、写 Payload 并亲自执行攻击来验证漏洞。
- **它为什么重要：** 它展示了 Agent 如何进行**“对抗性闭环”**——不仅是发现问题，而是像黑客一样去“实验”和“证明”。
- **技术趋势标签：** #AutonomousAgent #Cybersecurity #AdversarialAI
- **可复ing模式：** “分析 -> 假设 -> 执行攻击 -> 验证成功”的闭环。
- **疯狂发明家灵感：**
  1. **一个小实验：** 把它跑在你之前写的一个烂代码项目上，看它能不能在 5 分钟内通过 SQL 注入把你的数据库删了。
  2. **一个中型项目：** “代码质量压力测试机”——一个 Agent，专门负责在你的 Dev 分支里寻找逻辑漏洞并提交“攻击报告”。
  3. **一个艺术/游戏/叙事方向：** **《数字寄生虫》**。一个艺术装置，一个基于 Shannon 逻辑的 Agent 试图在局域网内寻找各种屏幕的漏洞，并在上面“涂鸦”生成艺术。
- **对我项目的启发：** 这种“自我验证”的逻辑可以迁移到“自动 Debug”或“自动平衡游戏数值”中。
- **今天是否值得深入研究：** 是
- **建议行动：** 做 demo（在安全环境下运行）。

## 今日可做小实验：2 小时挑战

### 项目名：**Ghost in the Jet (喷气机里的幽灵)**
- **输入：** Shadowbroker 提供的特定名人私人飞机位置数据。
- **输出：** 一个自动生成的“虚构航海日志”，由 Agent 模仿该名人的语气，结合降落地点的实时天气和新闻编写。
- **技术栈：** Python + Shadowbroker API (or scraping similar data) + OpenAI/Claude API。
- **第一步怎么做：** 
    1. 克隆 Shadowbroker 仓库，跑通数据抓取部分。
    2. 选定一个追踪目标（如：著名的私人飞机尾号）。
    3. 写一个 Prompt：“你是一个正在这架飞机上的疯狂诗人，根据经纬度 {lat, lon} 和目的地 {dest} 的新闻，写一段 50 字的意识流日记。”
    4. 运行脚本，看看 AI 能否通过坐标产生令人惊讶的叙事关联。
