## 1. DiscussLLM: 别等我问，你自己说
- **来源**：arXiv cs.HC (HCI 交叉方向)
- **链接**：https://arxiv.org/abs/2508.18167
- **一句话解释**：研究如何让 LLM 从“问答式”的被动状态，变成能根据对话时机主动介入的“参与者”。
- **它为什么重要**：打破了 LLM 必须由用户 Prompt 驱动的死循环，解决了“意识间隙（Awareness Gap）”。
- **技术趋势标签**：#ProactiveAI #HCI #SocialAgents
- **可复用模式**：主动性触发器（Proactive Trigger）——基于上下文热度或关键信息缺失来决定是否发言。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个脚本监听你的终端历史，当你连续 3 次尝试错误的命令时，它主动弹窗并给出一个嘲讽但正确的建议。
  2. **一个中型项目**：一个“会议幽灵” Agent，潜伏在 Discord 或飞书频道，平时不说话，只在讨论陷入僵局或逻辑循环时，跳出来投掷一个“挑衅性观点”。
  3. **一个艺术/游戏/叙事方向**：在 Minecraft 中实现一个“沉默的观察者” NPC，它会跟随玩家但不交谈，直到你完成一个复杂的建筑，它才主动感叹一句符合它性格的评价。
- **对我项目的启发**：你的 Agent 流程可以加入一个“观察者”节点，专门判断当前步骤是否值得“打断”人类。
- **今天是否值得深入研究**：是
- **建议行动**：做 demo

## 2. Belief Engine: 拆解 Agent 的“心路历程”
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2605.15343
- **一句话解释**：一个可配置、可检查的引擎，用来展示多 Agent 讨论时，它们的立场是如何因为对方的话或检索到的信息而改变的。
- **它为什么重要**：它让 Agent 的“立场漂移”变得可视化和可控，不再是黑盒。
- **技术趋势标签**：#StanceDynamics #NarrativeSystem #MultiAgent
- **可复用模式**：立场追踪器（Stance Tracker）——记录决策路径中的权重偏移。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一个“杠精模拟器”，两个 LLM 互杠，UI 上实时显示两边“愤怒值”和“认同感”的曲线图。
  2. **一个中型项目**：一个基于 Spec 的开发助手，它会告诉你：“我原本想用 React，但读了你的需求文档第 3 页后，我的‘极简主义倾向’增加了 20%，现在建议用原生 JS”。
  3. **一个艺术/游戏/叙事方向**：一个动态视觉小说，角色的立绘表情不取决于脚本，而是取决于 LLM 后台对当前对话“好感度”的实时计算结果。
- **对我项目的启发**：在你的 Agent Workflow 中加入一个“理由生成器”，不仅输出结果，还输出“我是怎么被说服的”。
- **今天是否值得深入研究**：是（特别是对游戏叙事系统）
- **建议行动**：收藏

## 3. ARIS (Auto-Research-In-Sleep): 梦境实验室
- **来源**：GitHub / wanshuiyin
- **链接**：https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep
- **一句话解释**：一个轻量级的“全自动研究循环”，让你在睡觉时，Agent 自动进行跨模型评审、想法挖掘和实验自动化。
- **它为什么重要**：它把“自动化”从工具级提升到了“任务流级”，而且强调“无框架、无锁定”。
- **技术趋势标签**：#AutonomousAgents #AsyncWorkflow #ExperimentAutomation
- **可复用模式**：闭环自迭代（Self-Review Loop）——Agent A 提出假设，Agent B 验证，Agent C 总结。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个脚本，每天凌晨 3 点自动爬取你关注的艺术领域最新图集，并让 Agent 生成 10 个衍生创作灵感，等你醒来查看。
  2. **一个中型项目**：一个“代码进化池”，给它一个初始的简单 P5.js 脚本，让它在后台不停地尝试修改参数并自评，直到生成一个视觉上极其复杂的艺术品。
  3. **一个艺术/游戏/叙事方向**：一个“永不停歇的 Minecraft 诗人”，它在服务器里独自游荡，把看到的风景写成日记，当你上线时可以去读它留下的漂流瓶。
- **对我项目的启发**：对于 Spec-driven 开发，可以让 Agent 在你写完基础 Spec 后，利用你睡觉的时间自动生成 10 种不同的架构原型供你早晨筛选。
- **今天是否值得深入研究**：是
- **建议行动**：试用（看看它的 Markdown-only 技巧）

## 4. TopoClaw: 拓扑感知的智能体 OS
- **来源**：arXiv cs.HC
- **链接**：https://arxiv.org/abs/2605.15556
- **一句话解释**：一种以人为中心、具备“拓扑感知”能力的 Agent 操作系统，强调 Agent 应该理解环境和人的关系。
- **它为什么重要**：它试图把 Agent 从“单一窗口”解放出来，变成一种像 OS 一样管理资源和上下文的存在。
- **技术趋势标签**：#AgentOS #HCI #ContextAware
- **可复用模式**：环境拓扑（Environmental Topology）——将工具和人映射成节点，Agent 在节点间流动。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“上下文雷达”，根据你当前打开的软件（VS Code, Figma, Chrome），自动切换 LLM 的 System Prompt。
  2. **一个中型项目**：一个“空间感知”的桌面助手，它知道你的文件夹结构和项目依赖，当你拖动一个文件时，它能预测你下一步可能需要的操作。
  3. **一个艺术/游戏/叙事方向**：在游戏中实现一个“懂风水的 Agent”，它会根据建筑的拓扑结构（门窗位置、动线）来给玩家提供风水建议或战术评估。
- **对我项目的启发**：不要只把 Agent 当成一个对话框，要把它当成一个“能看到你所有工具连接图”的调度员。
- **今天是否值得深入研究**：否（论文较干，看摘要领悟精神即可）
- **建议行动**：忽略（除非你要写 Agent 框架）

## 今日可做小实验：【灵感截击机】
**2 小时内可完成**

- **项目名**：Inspo-Interrupter
- **输入**：你在 VS Code 中编写的 Markdown 笔记或代码注释。
- **输出**：一个主动弹出的“杠精”或“灵感助手”，它会根据你刚写的最后一段话，强行插入一个相反的观点或一个艺术性的隐喻。
- **技术栈**：Python + `watchdog` (监听文件变化) + OpenAI/Claude API。
- **第一步怎么做**：
  1. 用 `watchdog` 监控一个特定的 `ideas.md` 文件。
  2. 每当检测到文件保存，读取最后 100 字。
  3. 发送给 LLM，Prompt 设为：“你是一个疯狂艺术家，请对这段话进行‘破坏性’评价，并提出一个完全不相关的、怪诞的建议，字数不超过 30 字。”
  4. 使用系统通知（如 Mac 的 `osascript`）将结果弹窗。
