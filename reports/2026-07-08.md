## 1. MentalThink: Shaping Thoughts in Mental SVG World
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2607.03530
- **一句话解释**：这篇论文提出了一种让多模态大模型在“脑海”中画 SVG 矢量图来辅助视觉和空间推理的新范式。
- **它为什么重要**：传统的 AI 推理（Chain of Thought）都是纯文字的。而对于设计和空间任务，人类是“用图思考”的。MentalThink 让模型在给出答案前，先自己生成、渲染并修正一段 SVG 代码作为“视觉草稿”。这完美地将**符号编码（SVG）**与**多模态推理**结合了起来。
- **技术趋势标签**：#CreativeCoding #VisualReasoning #SVG #MultimodalLLM
- **可复用模式**：**Visual Chain-of-Thought (视觉思维链)**。不让模型直接输出答案，而是强迫它先生成一段可视化代码并在后台渲染，以此作为它的“工作记忆（Scratchpad）”。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 Prompt，让 Claude 3.5 在回答你任何布局问题前，必须先输出一段 `<svg>` 表达它的理解，并在前端实时渲染这个“脑回路图”。
  2. **一个中型项目**：**“SVG 物理沙盒代理”**。一个能通过编写和修改 SVG 代码来玩物理重力解谜游戏的 Agent。它通过观察自己画的 SVG 渲染图来调整下一步的画笔。
  3. **一个艺术/游戏/叙事方向**：**“情绪的矢量化流变”**。一个互动艺术装置，实时捕获观众的对话，AI Agent 之间进行多轮辩论，但它们的“辩论过程”不显示文字，而是实时渲染成一幅不断演变、自我修正的抽象几何 SVG 画作。
- **对我项目的启发**：在做世界生成（Minecraft）或 UI 自动生成时，不要让 Agent 直接生成最终代码。先让它生成一个“2D 简笔画/示意图”的 SVG 蓝图，进行自我视觉评估后，再翻译成 3D 结构或 React 代码。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 2. system_prompts_leaks
- **来源**：GitHub Trending
- **链接**：https://github.com/asgeirtj/system_prompts_leaks
- **一句话解释**：这是一个持续更新的仓库，泄露/提取了市面上最顶尖 AI 系统（包括 Claude Code、GPT-5.5 Thinking、Gemini 3.5、Cursor 等）的官方 System Prompt。
- **它为什么重要**：这是工业界最顶尖的 Agent 架构师们写出的“武林秘籍”。你可以直接看到 Anthropic 是如何规训 Claude Code 进行本地代码操作的，或者 OpenAI 是如何引导 Thinking 模型进行多步骤反思的。对于 Spec-driven 开发者来说，这是无价的参考。
- **技术趋势标签**：#PromptEngineering #AgentArchitecture #ReverseEngineering #SpecDriven
- **可复用模式**：**“元规训模式（Meta-Guiding）”**。学习大厂如何用极其严苛的 Markdown 结构、边界条件定义和“绝对不要（NEVER）”列表来锁定 Agent 的行为。
- **疯狂发明家灵感**：
  1. **一个小实验**：把 Claude Code 的 System Prompt 喂给本地的 Ollama/Llama3，看看在开源模型上能还原出几分“自动写代码”的神韵。
  2. **一个中型项目**：**“System Prompt 编译器”**。输入你对 Agent 的高维设计（例如：“我想要一个会阴阳怪气的游戏 NPC”），该工具会自动套用泄露模板中的硬核防注入、结构化思考框架，编译出一个工业级的 System Prompt。
  3. **一个艺术/游戏/叙事方向**：**“提示词监狱逃脱”**。设计一个解密游戏，关卡里的 NPC 身上绑着真实的 GPT-5.5 泄露提示词，玩家扮演黑客，必须通过社会工程学“套”出 NPC 脑中的终极秘密。
- **对我项目的启发**：直接抄作业！看看 Cursor 和 Claude Code 是怎么定义“工具调用（Tool Use）”和“错误重试”的，把这些设计模式直接搬进你自己的自动化开发工作流中。
- **今天是否值得深入研究**：是

## 3. Doom Researching: A Conceptual Framework
- **来源**：arXiv cs.HC (人机交互)
- **链接**：https://arxiv.org/abs/2607.02723
- **一句话解释**：这篇论文研究了“毁灭式搜索/研究”现象——用户沉迷于不停地向 AI 提问以获取解释，从而产生“我懂了”的认知幻觉，但实际上大脑已经放弃了深度思考。
- **它为什么重要**：作为设计+CS的跨学科学生，这是一个极佳的 HCI 课题。现在的 AI 工具都在追求“无阻力（Frictionless）”，而这篇论文提醒我们：**有时我们需要在人机交互中引入“有建设性的阻尼（Constructive Friction）”**，防止人类退化。
- **技术趋势标签**：#HCI #CognitiveOffloading #UXDesign #AIToolchain
- **可复用模式**：**“认知阻尼（Cognitive Friction）”**。在用户过度依赖 AI 生成时，主动切断或限制即时反馈，迫使用户进行反思。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 Chrome 插件，检测你和 ChatGPT 的对话。如果你连续 5 次直接复制它的代码而不做任何修改，它就会“锁死”对话框，逼你手写一段 50 字的“代码原理解释”才能解锁。
  2. **一个中型项目**：**“苏格拉底式 IDE (Socratic IDE)”**。一个不帮你写代码、甚至不给你直接答案的编程助手。它只通过提问、画示意图、指出潜在 Bug 来引导你一步步自己写出代码，专治“Cursor 依赖症”。
  3. **一个艺术/游戏/叙事方向**：**“记忆消逝的图书馆”**。一个单人交互叙事游戏，你向 AI 图书管理员询问世界观历史。你问得越多、越懒得思考，你的屏幕文字就会越模糊，直到你彻底忘记自己进来是要干什么的。
- **对我项目的启发**：在设计你自己的 AI 辅助工具或 Agent 工作流时，不要只想着“一键生成”。思考如何设计“人机协同的黄金比例”，让 AI 扮演“脚手架（Scaffolding）”而非“拐杖”。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 4. diegosouzapw / OmniRoute
- **来源**：GitHub Trending (TypeScript)
- **链接**：https://github.com/diegosouzapw/OmniRoute
- **一句话解释**：一个本地运行的免费 AI 网关，支持 231+ 提供商（包含 50 多个免费 API），内置了极度夸张的 RTK+Caveman 压缩算法，能帮你省下 15-95% 的 Token。
- **它为什么重要**：多 Agent 系统最大的痛点是**“Token 贵”**和**“速率限制（Rate Limit）”**。OmniRoute 提供了免费的聚合通道，更重要的是它的“堆叠压缩算法”，能把庞大的上下文压缩后发给模型，非常适合多 Agent 跑在本地的实验。
- **技术趋势标签**：#LLMToolchain #TokenCompression #AgentInfrastructure #LocalFirst
- **可复用模式**：**“代币压榨（Token Squeezing）”**。在将上下文发送给 LLM 之前，进行语义级的无损/有损压缩，剔除冗余代码和废话。
- **疯狂发明家灵感**：
  1. **一个小实验**：用 OmniRoute 将你的 Cline 或 Cursor 接入免费的 Gemini 1.5 Flash 接口，体验一下“零成本”自动写代码。
  2. **一个中型项目**：**“乞丐版 Agent 蜂群（Zero-Cost Agent Swarm）”**。用 OmniRoute 聚合 10 个不同的免费 API，搭建一个能够协同创作、自动测试、自动部署的本地多 Agent 游戏开发组。
  3. **一个艺术/游戏/叙事方向**：**“无限 NPC 广播电台”**。利用免费 API 和 OmniRoute 的压缩机制，低成本运行一个拥有 100 个 NPC 实时生存、对话、互相影响并广播的虚拟沙盒城镇，完全不用担心 API 账单爆炸。
- **对我项目的启发**：解决你做复杂 Agent 实验时的“账单焦虑”。用它作为你所有实验性项目的底层网关。
- **今天是否值得深入研究**：是
- **建议行动**：试用

## 今日模式总结

1. **视觉草稿纸模式 (Visual Scratchpad Pattern)**：从 *MentalThink* 中提炼。多模态模型在处理复杂逻辑、空间布局、代码生成时，引入一个“中间视觉介质”（如 SVG、Mermaid、ASCII Art）。模型先“画”再“说”，能极大地提升逻辑准确度。
2. **建设性阻尼模式 (Constructive Friction Pattern)**：从 *Doom Researching* 中提炼。未来的 HCI 设计趋势正在从“极简、无感”转向“有意的阻碍”。通过在人机交互中设计关卡和反思环节，提升用户的心理所有权（Psychological Ownership）和学习效果。
3. **语义压榨与多路复用 (Semantic Squeezing & Multiplexing)**：从 *OmniRoute* 中提炼。在多 Agent 时代，前端网关需要具备极强的“省钱”能力——通过本地压缩、智能回退（Fallback）和免费通道路由，把 Agent 的运行成本降到最低。

## 今日可做小实验：SVG 思维显微镜 (SVG-MindMapper)

这个小实验结合了 **MentalThink 的视觉思维链** 概念，让你一窥 AI 在思考复杂编程/设计问题时的“脑回路”。

- **项目名**：SVG-MindMapper
- **输入**：用户输入一个复杂的系统设计问题（例如：“设计一个我的世界红石自动农场的逻辑流”）。
- **输出**：一个双栏网页。左栏是 Claude 3.5 实时推理的文本；右栏是一个动态渲染的 SVG 拓扑图/示意图，实时展示模型当前思考到的节点和它们之间的关系。
- **技术栈**：
  - HTML / Tailwind CSS (前端界面)
  - Vanilla JS / Vite (极简前端构建)
  - Claude 3.5 Sonnet API (或通过 OmniRoute 接入)
- **第一步怎么做**：
  1. 建立一个简单的 HTML 页面，左边一个 `div#chat-log`，右边一个 `div#svg-canvas`。
  2. 撰写如下 System Prompt 喂给 Claude：
     > "你是一个视觉思考者。在回答用户的任何架构设计问题时，你必须交替进行文本思考和 SVG 绘制。你的输出格式必须是：
     > `[THINK]`（你的文本推理步骤）
     > `[SVG]`（一段完整的、自适应的 <svg>...</svg> 代码，可视化你刚才思考的系统结构。每次输出的 SVG 应包含上一步的内容并加入新节点，用颜色标记当前活跃的节点）"
  3. 用 JS 捕获 SSE (Server-Sent Events) 流式输出。当检测到 `[SVG]` 标签时，提取其中的代码，直接使用 `innerHTML` 渲染到右侧的 `div#svg-canvas` 中。
  4. 输入一个复杂问题，看着那个 SVG 像生命体一样，随着 AI 的思考一步步生长、变复杂。
