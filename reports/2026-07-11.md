## memtrace-public: 零 LLM 调用的 AI 编码 Agent 双时态图结构内存
- **来源**：GitHub Trending Python
- **链接**：https://github.com/syncable-dev/memtrace-public
- **一句话解释**：一个专为 AI 编码 Agent 设计的、基于 MCP (Model Context Protocol) 的双时态图结构内存系统，实现零 LLM 调用的精准上下文追踪。
- **它为什么重要**：现在的 AI 辅助编程（如 Cursor、Claude Code）在面对大型项目时，内存管理要么靠昂贵的 LLM 总结，要么靠不精准的向量检索。这个项目直接在本地用**双时态图（Bi-temporal graph）**记录代码实体和时间线。它支持 MCP 协议，意味着你可以直接把它挂载到你常用的 AI 工具链上，让 Agent 拥有真正的“长期记忆”而不花一分 Token 钱。
- **技术趋势标签**：#Agentic-Memory #MCP-native #Graph-DB #Zero-LLM-Overhead
- **可复用模式**：**零调用状态同步（Zero-LLM State Sync）**：利用本地轻量级图数据库和 Git 提交历史，在后台静默维护 Agent 的认知地图，只在 LLM 需要决策时提供精准的节点切片。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 MCP 插件，静默记录你每次保存文件时的 Git Diff 和你当时的光标停留时间，生成一个“程序员代码焦虑热力图”。
  2. **一个中型项目**：**“代码时空穿梭机”**：一个 Spec-driven 开发辅助器。当你对 Agent 说“回滚到我昨天尝试实现 WebGL 渲染但失败的那个版本”时，Agent 能通过双时态图，不仅找回代码，还能找回当时的“Spec 逻辑设计草稿”。
  3. **一个艺术/游戏/叙事方向**：**Minecraft 历史学家 NPC**：在 Minecraft 服务器里，用这个双时态图记录整个世界的发展（谁在什么时间、什么坐标、破坏或建造了什么）。NPC 不需要调用 LLM 就能“记住”整个世界的物理变迁史，并在玩家询问时进行“史诗般的叙事叙述”。
- **对我项目的启发**：在你的 Spec-driven 自动化流程中，不要再把整个 codebase 塞进 Prompt 了。用这种图结构作为 Agent 的“外部骨架”，能极大降低 Token 消耗并提升生成精度。
- **今天是否值得深入研究**：是
- **建议行动**：试用 / 跑通它的 MCP 示例

## 走向主动型 Agent：基于上下文图的主动推荐系统
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2607.07721
- **一句话解释**：论文提出了一种从“被动响应”（等你提问）转向“主动介入”（根据上下文图主动提供信息）的 Proactive Agent 框架。
- **它为什么重要**：现在的 AI 交互（HCI）都是“拉取模式”（Pull）——你输入 Prompt，它给回答。这很累。未来的艺术和开发工具应该是“推送模式”（Push）——Agent 默默观察你的画布、光标、甚至视线，并在你意识到需要之前，把灵感、资产或关联代码推到你面前。这篇论文给出了这种“主动性”的数学和逻辑框架。
- **技术趋势标签**：#Proactive-HCI #Context-Graph #Active-RAG #HCI-Design
- **可复用模式**：**影子上下文观察者（Shadow Context Observer）**：构建一个后台守护进程，将用户的低频操作（如：在 IDE 里停顿、在 Figma 里拉伸图形）转化为图节点，当图的某种“关联度”达到阈值时触发 Agent 动作。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 Python 脚本，监听你的 Terminal 报错。如果同一个错误你连续解决了 3 分钟没解决，它会自动在桌面弹出一个“AI 军师”，端着已经写好的 StackOverflow 解决方案等你。
  2. **一个中型项目**：**“通灵设计画布”**：一个创意编码画布。当你在 p5.js 里写下 `ellipse()` 且调整了三次半径时，后台的 Proactive Agent 预测到你可能想做“粒子排斥效果”，自动在右侧悬浮窗渲染出 3 种粒子系统的代码变体。
  3. **一个艺术/游戏/叙事方向**：**动态环境戏剧生成器**：在 3D 游戏空间里，系统根据玩家的视线停留时间、走动轨迹（构建成 Context Graph），主动在前方拐角处生成符合其情绪预期的 NPC 偶遇事件或环境音效变化。
- **对我项目的启发**：打破“输入框”的诅咒。在设计 Creative Tools 时，尝试用 Context Graph 去捕获用户的“无意识操作”，让 Agent 做到真正的“心领神会”。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## From Prompts to Contracts: 打造可审计、契约化的 Agent 工作流
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2607.08028
- **一句话解释**：提出了一种“Harness Engineering（治理工程）”方法，将模糊的 Prompt 转化为确定性的“契约（Contracts）”，确保 Agent 的输入输出边界可控、可审计。
- **它为什么重要**：你喜欢 Spec-driven development，而这个方向最大的痛点就是：LLM 太不可预测。这篇论文提出把软件工程中的“契约测试（Contract Testing）”引入 Agent。通过严格限定 Agent 的输入边界、路由规则和输出契约，让 Agent 像一个确定性的 API 一样安全可靠。
- **技术趋势标签**：#Spec-driven #Agent-Contract #Harness-Engineering #Reliable-AI
- **可复用模式**：**契约守卫型 Agent（Contract-Guarded Agent）**：在 LLM 的输入前置（Pre-conditions）和输出后置（Post-conditions）强制执行硬性规则校验（如 JSON Schema、AST 解析），不通过则自动触发 Self-Correction。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个 Python 装饰器 `@agent_contract(input_schema, output_schema)`，任何 LLM 函数只要输出不符合 schema，自动拦截并把报错喂回给 LLM 重新生成，直到合格才返回给主程序。
  2. **一个中型项目**：**“代码拼图自动化引擎”**：一个完全基于 Spec 契约的自动化流水线。你只需写出函数的 TypeScript Interface，Agent 会自动生成实现、测试用例，并反复运行测试，直到完全满足 Interface 契约。
  3. **一个艺术/游戏/叙事方向**：**规则怪谈游戏生成器**：游戏世界规则（契约）由代码硬性规定。LLM 扮演的“邪神”试图通过对话诱导玩家违反规则，但后台的“契约卫士”会严格监控 LLM 的每一句话，确保它不能破坏底层物理定律。
- **对我项目的启发**：这是构建复杂自动化系统（Automation Systems）的基石。不要试图用更长的 Prompt 去约束 Agent，用代码写好“契约”，让 Agent 在铁笼里跳舞。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 对抗性社会认识论（ASE）：混合群体的“谣言与信任”模拟
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2607.07760
- **一句话解释**：探讨在人类与 LLM 密集交互的社交网络中，信息是如何通过“证言链、机构认证、默契信任”被扭曲、过滤和操纵的。
- **它为什么重要**：这不仅是社会学，更是极好的**游戏设计/叙事系统底座**。如果你想生成一个逼真的虚拟城镇，NPC 之间不能只是友好地交换事实，他们应该有私心、会撒谎、会拉帮结派、会传播选择性忽略的事实。这篇论文为你提供了一套“对抗性信息流”的建模方法。
- **技术趋势标签**：#Social-Simulation #Multi-Agent #Game-Systems #Generative-Narrative
- **可复用模式**：**信息失真传播链（Distorted Information Chain）**：Agent 接收信息时，根据自身的“动机权重”（如贪婪、恐惧、嫉妒）对信息进行重写（放大、隐瞒、伪造），再传递给下一个 Agent。
- **疯狂发明家灵感**：
  1. **一个小实验**：制作一个“三人成虎”的命令行 Demo。输入一句真相（例如“镇长偷了面包”），让 5 个性格各异的 Agent 依次传递，看最后会变成什么离奇的谣言。
  2. **一个中型项目**：**“赛博水军模拟器”**：给定一个社会事件，设计一群具有不同利益立场的 Agent，观察它们如何在虚拟社交媒体上通过“选择性事实披露”引导舆论走向。
  3. **一个艺术/游戏/叙事方向**：**《唐顿庄园》式 AI 社交游戏**：在一个虚拟豪宅里，10 个 AI 仆人和贵族各怀鬼胎。玩家扮演侦探，需要通过在走廊“偷听”NPC 之间的对抗性对话，利用他们谣言中的漏洞拼凑出谋杀案的真相。
- **对我项目的启发**：为你的游戏系统和世界生成注入“不完美信息”。完美的 Agent 索然无味，会撒谎和产生认知偏差的 Agent 才能创造伟大的叙事。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 今日模式总结

1. **从“拉取”到“推送”的主动式交互 (Proactive Push HCI)**：未来的创意工具不再等待用户输入 Prompt，而是通过静默观察上下文图谱（Context Graph）主动触发 Agent 提供辅助。
2. **契约化硬约束 (Contractual Guardrails)**：在 Spec-driven 开发中，用强类型的 Schema 和本地双时态图代替模糊的自然语言，作为 Agent 行为和记忆的物理边界。
3. **对抗性多智能体社会学 (Adversarial Multi-Agent Social Dynamics)**：在多智能体系统（如游戏、模拟器）中，引入信息失真、谣言传播和动机过滤，能创造出极具戏剧张力和高真实度的涌现行为。

## 今日可做小实验：2小时极速挑战

### 项目名：**MCP-Git-Chronicle（基于 MCP 的 Git 情绪编年史）**
一个可以在 2 小时内跑通的、结合了“主动上下文”与“本地图结构记忆”的极简 MCP 插件。

*   **输入**：你每次执行 `git commit` 时的代码 diff，以及你写下的 commit message。
*   **输出**：一个本地生成的 HTML 知识图谱，展示“代码修改 -> 你的情绪状态（由 LLM 自动分析 commit 语气得出） -> 代码复杂度风险”的关联网络。
*   **技术栈**：
    *   Node.js (用于编写 MCP Server)
    *   `@modelcontextprotocol/sdk` (快速搭建 MCP 通道)
    *   `simple-git` (自动提取最近一次 commit 差异)
    *   `vis.js` (极简的前端图谱可视化库，直接单 HTML 文件渲染)
*   **第一步怎么做**：
    1. 初始化一个 Node.js 项目，安装 `@modelcontextprotocol/sdk`。
    2. 写一个简单的本地脚本，通过 `simple-git` 获取当前仓库的最新 commit diff。
    3. 创建一个 MCP Tool，当 Cursor 或 Claude Code 调用它时，读取这个 diff 并让 LLM 评估：“这段代码改动是否会导致技术债？作者写 commit 的时候是愤怒、焦虑还是平静？”
    4. 将评估结果以 JSON 格式追加写入一个本地的 `memory_graph.json` 文件（格式为：`{source: "file_name", target: "emotion", relation: "written_in"}`）。
    5. 用一个极简的 HTML 模板，用 Vis.js 读取这个 JSON 并渲染出你自己的“代码-情绪”脑图。
