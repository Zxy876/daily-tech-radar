## TimeCapsule：只喂给 AI 维多利亚时代文本的“认知孤岛”语言模型
- 来源：arXiv cs.HC
- 链接：https://arxiv.org/abs/2607.24750
- 一句话解释：把一个 1.2B 的小模型限制在 1800-1875 年的文本里训练，制造一个对现代完全无知、只能基于 19 世纪认知去“产生幻觉”的数字历史流放者。
- 它为什么重要：打破了现代 LLM 追求“全知全能”的惯性，反向将“幻觉（Hallucination）”和“认知封锁（Epistemological Isolation）”作为艺术与叙事媒介。
- 技术趋势标签：`Small Model Fine-tuning` / `Epistemological AI` / `Generative Worldbuilding` / `Creative Hallucination`
- 可复用模式：**知识隔离箱 (Knowledge Isolation Chamber)** —— 故意裁剪/特定化模型的训练或上下文数据，迫使其产生特定历史或特定世界观下的特有推演逻辑。
- 疯狂发明家灵感：
  1. **一个小实验**：训一个只读过 1990 年代《电子游戏软件》杂志的 1B 模型，让它猜测 2026 年的“元宇宙”和“AI 游戏”长什么样。
  2. **一个中型项目**：NPC 意识形态编译器：为 RPG 游戏中的不同部落生成完全知识隔离的微型模型（如只懂中世纪炼金术的巫师模型 vs 只懂蒸汽机械的工匠模型），让它们交谈时产生完全真实、无法调和的“认知代沟”。
  3. **一个艺术/游戏/叙事方向**：互动装置《1900 年的未来报纸》：观众输入现代新闻（如“SpaceX 降落火箭”），系统用 19 世纪蒸汽朋克语境和以太物理学假说将其翻译并打出报纸。
- 对我项目的启发：在 Minecraft 或生成式世界系统中，给不同区域的 NPC 配备“知识断层”的专用微型模型，比直接用泛泛的通用大模型更有世界观沉浸感。
- 今天是否值得深入研究：是
- 建议行动：收藏

## Language as a Material Interface：把“语言”当作可雕刻的物理材质来做 LLM 交互
- 来源：arXiv cs.HC
- 链接：https://arxiv.org/abs/2607.24753
- 一句话解释：打破“写指令 Prompt -> 拿结果”的工具范式，把语言看作有质感、有声学特征、可拉伸与多时间线演化的“实体材质”。
- 它为什么重要：现在的 Prompting 太像给外包发需求单，极大地限制了 Creative Coding 和艺术创作。将语言“物理化/材质化”是下一代创作者工具（Creative Tools）与 HCI 的核心趋势。
- 技术趋势标签：`Generative HCI` / `Creative Coding` / `Non-directive Prompting` / `Tactile NLP`
- 可复用模式：**多维语言雕刻 (Textile Temporal Molding)** —— 不做一次性文本生成，而是将语言拆解为波形、音韵、联想拓扑图，像操作 3D 软体一样实时塑形 LLM 的输出。
- 疯狂发明家灵感：
  1. **一个小实验**：做个 WebGL 画布，把文本框变成“液体”：输入的文字越长粘度越高，语音输入的频率与音量直接绑定到 LLM 调用的 `temperature` 和 `top_p` 参数上。
  2. **一个中型项目**：节点式“诗歌音色合成器”：界面不是代码节点，而是“文本张力”、“隐喻粘性”节点，通过拖拽连线和手柄拉伸控制生成的生成式文本形态。
  3. **一个艺术/游戏/叙事方向**：游戏《声响文字学》：玩家不通过输入具体文字命令过关，而是通过调整文本的“重音”、“韵律”和“声学质感”来改变虚拟游戏世界的物理重力与风向。
- 对我项目的启发：Spec-driven 模式下的 Spec 不一定非要是严密的技术文档，也可以是这种带有“物理材质感”的隐喻约束结构。
- 今天是否值得深入研究：是
- 建议行动：做demo

## Beyond Memory：让 Agent 记住“死胡同”与“反悔记录”的协作底层
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2607.24759
- 一句话解释：针对 Agent 协作中“成功经验被保留，失败尝试被擦除”的问题，构建了一个能自动记录“走过的死胡同 (Dead Ends)”与“撤回的主张 (Walked-back Claims)”的结构化存储底座。
- 它为什么重要：Agent 经常反复踩同一个坑，就是因为内存压缩策略（Memory Compaction）往往只保留“最终正确答案”。把“踩坑过程”作为一等公民存储，对防止 Drift 和提升 Agent Workflow 极为关键。
- 技术趋势标签：`Agent Memory` / `Failure Trajectory` / `Spec-driven Workflow` / `Knowledge Substrate`
- 可复用模式：**负向经验树 (Negative Knowledge Tree)** —— 在 Agent 执行任务时，显式记录“尝试过但失败了的操作 + 理由”，并作为前置 Guardrail 喂给下一个思考循环。
- 疯狂发明家灵感：
  1. **一个小实验**：给你的 Git 仓库写一个 Hook + Agent，专门收集你 `git reset` 或删掉的代码段，自动生成一份“失败设计坟场 (.deadends)”文档。
  2. **一个中型项目**：Spec-driven 的“防踩坑 Agent”：在根据 Spec 编写代码或系统架构时，优先扫描项目中的 `.graveyard` 节点，避免 Agent 自动调用废弃 API 或死循环架构。
  3. **一个艺术/游戏/叙事方向**：叙事解谜游戏《未选择的路》：展示游戏中所有“死去的可能性/被废弃的推理”，玩家需要通过拾取 NPC 的“撤回记忆”来破解当前的谜题。
- 对我项目的启发：为自己的 Agent 自动化工作流加上“失败轨迹库”，而不是只优化 Prompt 试图让它一次成功。
- 今天是否值得深入研究：是
- 建议行动：试用

## Memory into Media：评估 AI 将“口述历史/记忆”转化为“三维视觉场景”时的信息失真
- 来源：arXiv cs.HC
- 链接：https://arxiv.org/abs/2607.24756
- 一句话解释：探索将第一人称的口述记忆利用 AI 转化为三维视觉场景时，到底丢失了什么、扭曲了什么，并构建了一套“叙事转化真实度”的评价体系。
- 它为什么重要：在 AI 驱动的世界生成（Worldgen）、游戏剧情生成和虚拟场景构建中，从文本回忆到 3D/视觉场景的自动化翻译正在变成基础设施。度量“意图与气味的流失”是 HCI 与生成式系统的边缘地带。
- 技术趋势标签：`Generative Narrative` / `Memory Visualization` / `HCI Evaluation` / `Worldbuilding`
- 可复用模式：**双重转译校验 (Double-Translation Audit)** —— 从第一人称主观记忆中抽象出“情绪与细节密度”标尺，校验 AI 生成的三维场景是否过度“平庸化/被算法美化”。
- 疯狂发明家灵感：
  1. **一个小实验**：录制一段你童年房间的语音口述，用 LLM 抽取场景描述并出图，再用视觉分析 Agent 评估两者的“记忆丢失矩阵”。
  2. **一个中型项目**：Minecraft 记忆重现引擎：输入一段老人对老家老宅的口述记录，自动化生成带有“记忆不确定性”（如模糊不清的方块、半透明遮挡、漂浮的物件）的 Minecraft 场景。
  3. **一个艺术/游戏/叙事方向**：叙事解谜游戏《虚构的怀旧》：玩家需要对比 NPC 的口述音频与 AI 生成的“记忆假象”房间，找出被 AI 算法美化或误解的细节来拼凑真相。
- 对我项目的启发：生成系统不能只追求“画面精美”，带有“主观偏差”和“模糊感”的生成才是叙事和游戏系统的灵魂。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 今日模式总结

1. **负向知识与特异性封锁 (Negative & Isolated Knowledge)**：不再追求全知全能与绝对完美的通用内存，而是故意利用“知识封锁”建立特异性世界观（TimeCapsule），或者显式保留“失败尝试”避免 Agent 踩坑（Beyond Memory）。
2. **非指令化的“材质化”HCI 交互 (Materialized LLM HCI)**：让文本/Prompt 摆脱传统的打字框，转变为具有物理属性（粘性、声学、时间线）的可操控材质。
3. **主观记忆到空间媒介的度量转译 (Subjective-to-Spatial Translation)**：探索主观文本如何转化为 3D/游戏/视觉媒介，并建立对“AI 翻译失真”的评估与艺术化利用。

## 今日可做小实验

### 项目名：`DeadEnd-Extractor` (代码失败坟场提取器)
- **输入**：本地 Git 仓库中未 commit 的修改，或者 `git diff` 里被删除的代码段。
- **输出**：自动生成的 `DEADENDS.md`，记录：“尝试过但废弃的逻辑”、“报错原因”、“给 Agent 和自己的警告”。
- **技术栈**：Python 3.10+、`gitpython` (或 `subprocess` 调 git)、OpenAI / Claude SDK。
- **第一步怎么做**：
  1. 在终端写一行 Python 脚本，用 `subprocess.check_output(["git", "diff", "HEAD"])` 获取你今天删掉或修改的代码。
  2. 拼接 Prompt 给 LLM：“这是我刚刚废弃/重写的一段代码。请分析：1. 我原计划干什么？2. 为什么这段代码不可行？请写成一行警告。”
  3. 将输出追加写入当前目录的 `DEADENDS.md` 中。
