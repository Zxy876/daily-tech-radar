## ESP32-AI: 在 8 美元的微控制器上运行 28.9M 参数本地 LLM
- 来源：Hacker News / GitHub
- 链接：https://github.com/slvDev/esp32-ai
- 一句话解释：把一个 28.9M 参数的极小 LLM 直接塞进 8 美元的 ESP32 芯片，不连网也能原生推理。
- 它为什么重要：它把 LLM 从昂贵的云端 API 和显卡解绑，让 AI 真正落入边缘侧、物理实体和无网环境。
- 技术趋势标签：Edge AI / Embedded System / Tangible HCI / Physical Computing
- 可复用模式：**物理实体与微型脑结合**（传感器 -> 本地极小模型 -> 物理执行器）。
- 疯狂发明家灵感：
  1. **小实验**：做一只“有脾气”的 ESP32 物理桌宠，根据光照和摸摸传感器的输入，通过本地模型输出带有情绪的 LED 律动和微型墨水屏话语。
  2. **中型项目**：离线野外探险 RPG 实体道具——一把“能够辨识周围环境并给予解谜提示”的离线魔法手电筒。
  3. **艺术/游戏/叙事方向**：寄生在旧时代电子废料（如旧电话机、GameBoy）里的离线 AI 灵体艺术装置。
- 对我项目的启发：如果想做结合物理世界的游戏或交互装置，不需要带高功耗电脑，ESP32 就可以当作实体 Agent 的内核。

## context-mode: 针对 AI Agent 的上下文沙盒与 98% 瘦身工具
- 来源：GitHub Trending TypeScript
- 链接：https://github.com/mksglu/context-mode
- 一句话解释：通过 MCP + Hooks 截断和沙盒化工具的冗长输出，把 Agent 的 Context 占用最高降低 98%，同时保留会话记忆。
- 它为什么重要：Agent 频繁失忆或产生幻觉，通常是因为工具返回的庞大数据（大型 JSON、巨量代码）占满了上下文。解决 Agent 性能衰退的关键是 **Context Engineering（上下文工程）**。
- 技术趋势标签：Agent Workflow / Context Engineering / MCP / LLM Toolchain
- 可复用模式：**源头过滤模式 (Filter-at-Source)**：在数据塞给 LLM 之前，先在 Tool 这一层做本地规则截断与结构提取。
- 疯狂发明家灵感：
  1. **小实验**：写一个 MCP Hook 中间件，自动把你终端里复杂的 `git diff` 或测试日志压缩成 5 行结构化摘要再交给 Claude/Cursor。
  2. **中型项目**：Minecraft 世界动态监听 Agent：监听几千个方块和 NPC 的状态变化，但只把玩家视线 10 格内的“增量改变”过滤并翻译成 Agent 上下文。
  3. **艺术/游戏/叙事方向**：一个“选择性遗忘”的叙事 Agent，根据故事情绪变化动态决定保留哪些记忆，丢弃哪些细节。
- 对我项目的启发：适合用来优化你的 Spec-driven 自动化工具或构建 Drift 工作流，防止 Agent 在读写大型工程时被大量无用上下文卡死。
- 今天是否值得深入研究：是
- 建议行动：试用

## ego-lite: 共享真实登录态的 Agent 极速无感浏览器
- 来源：GitHub Trending
- 链接：https://github.com/citrolabs/ego-lite
- 一句话解释：让 Claude Code 或 Codex 等 AI Agent 能够直接复用你本地浏览器的登录 Cookie，无感、静默地帮你在真实网站上做自动化操作。
- It 为什么重要：传统 Playwright 自动化需要重新处理登录验证或暴露账号密码。ego-lite 实现了人类与 Agent 在同一浏览器身份下的无缝协作。
- 技术趋势标签：Agentic Automation / HCI / Stealth Browser / Co-existence
- 可复用模式：**影子公司模式 (Shadow Session Sharing)**：Agent 静默使用人类的身份凭证在后台跑长任务，不干扰人类前台交互。
- 疯狂发明家灵感：
  1. **小实验**：写一个脚本让 Agent 在后台静默巡检你常用的设计社区或 GitHub，把新出的创意作品自动整理成你的专属 Moodboard。
  2. **中型项目**：无缝的 Figma/Webflow 联动生成器：让后台 Agent 登录你的 Web 账号，自动帮你在后台把设计稿转成真实 UI 组件。
  3. **艺术/游戏/叙事方向**：一个“数字替身”艺术项目：AI Agent 在后台替你漫游互联网，记录它对你平时关注的数字世界的“独家观察日记”。
- 对我项目的启发：可以作为设计与开发自动化流程中的静默执行层，省去繁重的身份验证逻辑。

## PageIndex: 抛弃向量数据库，基于推理与树状结构的 Reasoning RAG
- 来源：GitHub Trending Python
- 链接：https://github.com/VectifyAI/PageIndex
- 一句话解释：不依赖 Vector Embedding 和向量切片，直接构建文档的层次树状结构，通过 LLM 的推理能力像人类看书一样去检索信息。
- 它为什么重要：传统向量 RAG 会因为数据切块（Chunking）破坏文本的逻辑连贯性，而基于树状索引的 Reasoning-RAG 能在保持完整上下文语义的同时做到精确定位。
- 技术趋势标签：Vectorless RAG / Spec-Driven / Reasoning System / Structural Retrieval
- 可复用模式：**树状推演检索 (Hierarchical Index Reasoning)**：先看目录树（Tree Structure），由 LLM 推理出答案可能在哪个分支，再深入分支抓取。
- 疯狂发明家灵感：
  1. **小实验**：把一份长达 50 页的复杂项目 Spec 转换为 JSON 树大纲，用提示词让 LLM 做出“目录级寻路”，对比它和向量检索的准确度。
  2. **中型项目**：Minecraft 庞大 Mod 规则与设定集的精确 Reasoning-RAG 引擎，让 NPC 能顺着规章树准确查阅复杂的游戏世界法则。
  3. **艺术/游戏/叙事方向**：非线性互动树状小说引擎：玩家任意提问，系统沿着树状 Lore 脉络解密世界观隐喻。
- 对我项目的启发：**极为契合 Spec-Driven 开发**！ Spec 本身就是高度结构化的文档，用 PageIndex 思想做 Spec 检索比普通 Vector RAG 效果好得多。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 今日可做小实验

基于今天得到的启发，为你设计一个 2 小时可完成的 Spec-Driven 自动化小实验：

### 项目名：`SpecTree-Navigator`（基于树状索引的 Spec 上下文精准抽取器）

- **输入**：一份复杂的 Markdown 格式项目架构规范文档（`Spec.md`），以及一个具体的需求问题（如“用户鉴权模块的核心流程和接口是什么？”）。
- **输出**：不使用任何 Vector Embedding/数据库，仅输出 LLM 在 Spec 目录树中的寻路轨迹（如 `[Root -> 3.安全与鉴权 -> 3.2 JWT机制]`），并只截取该节点下最小精简上下文和对问题的解答。
- **技术栈**：Python + `pathlib` + LiteLLM (或任意 LLM API)
- **第一步怎么做**：
  1. 用 Python 写一个简单的正则解析器（约 30 行），读取 `Spec.md` 的 `#` / `##` / `###` 标题，构建出一个只包含标题和节点 ID 的 JSON 目录树。
  2. 构造一个 Prompt 给 LLM：“这是项目的目录树结构 `{JSON_TREE}`，请推断解决问题 `{QUESTION}` 需要阅读哪几个节点 ID？只返回节点 ID 列表。”
  3. 脚本根据 LLM 返回的节点 ID 抽取对应小节拼成最终 Context，验证其 Token 消耗是否比原文减少了 80% 以上。
