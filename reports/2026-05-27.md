## 1. claude-mem：跨会话的持久化 AI 记忆体
- **来源**：GitHub Trending (TypeScript)
- **链接**：https://github.com/thedotmack/claude-mem
- **一句话解释**：一个能够跨越不同会话，自动捕获 Agent 的操作、使用 AI 压缩并将其作为上下文精准注入未来会话的轻量级记忆管理工具。
- **它为什么重要**：它解决了 Agent “转头就忘”和“上下文爆仓”的终极矛盾。它不是简单的存 Log，而是用 AI 异步进行“记忆提炼与压缩”，实现了类似人类的“长期工作记忆”。
- **技术趋势标签**：#AgentMemory #LLM工具链 #自动化工作流
- **可复用模式**：**异步记忆提炼循环** —— 会话结束 -> AI 提炼/压缩关键决策 -> 存入向量/键值库 -> 新会话开始 -> 根据当前 Task 语义检索并注入。
- **疯狂发明家灵感**：
  1. **一个小实验**：做一个“睡前故事/赛博宠物”命令行。每天跟它聊 5 分钟，它会自动提炼你的情绪和今天发生的事，第二天它会主动提起昨天的事，且性格会根据你的长期反馈发生漂移（Drift）。
  2. **一个中型项目**：**“数字双胞胎”终端（Shell Companion）**。挂载在你的 Zsh 里，静默记录你所有的报错和解决过程。一旦你成功解决了某个 Bug，它自动将“问题-解法”压缩进记忆库，下次你输入类似命令报错时，它直接在命令行下方给出你专属的踩坑提示。
  3. **一个艺术/游戏/叙事方向**：**废土酒馆 NPC 社交网络**。在 Minecraft 或文字游戏中，NPC 们拥有这个记忆组件。你今天对 NPC A 撒的谎，会被它压缩成“记忆碎片”并传播给 NPC B。当你过几天遇到 NPC B 时，它会根据这个被压缩过的“八卦”对你产生敌意。
- **对我项目的启发**：可以用来构建你自己的 spec-driven 开发工具。让 Agent 记住你对 UI 审美的偏好（比如“你喜欢极简、高饱和度橙色”），无需每次在 System Prompt 里写一堆废话。
- **今天是否值得深入研究**：是
- **建议行动**：试用并看其源码（它是如何做 AI 压缩和 Context 注入的）。

## 2. SkillEvolBench：从单次经验到程序化技能的自我进化
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2605.24117
- **一句话解释**：一个评估 LLM Agent 能否将零散的、单次任务执行成功后的“经验轨迹”，提炼固化为“可复用程序化技能（如 API、代码函数）”的诊断基准。
- **它为什么重要**：真正的 Agent 不应该每次都从头推理。这个研究指明了一个方向：Agent 应该在运行过程中，不断为自己编写、积累和更新“工具箱（Skill Library）”，实现自我进化。
- **技术趋势标签**：#AgenticAI #ProceduralGeneration #自动化
- **可复用模式**：**经验-代码提炼（Trajectory-to-Code Distillation）** —— 探索尝试 -> 成功 -> 提取成功路径 -> 抽象成通用 Python 函数 -> 注册为 Agent 的新 Tool。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“自动爬虫进化器”。给 Agent 一个乱七八糟的网页，让它尝试用 BeautifulSoup 提取数据。成功后，触发一个 Hook，让它把成功的 DOM 路径抽象成一个干净的、带类型标注的爬虫函数，存入 `my_skills/` 文件夹下。
  2. **一个中型项目**：**创意编码“学徒”（Creative Coding Apprentice）**。你给它看几个 p5.js 的视觉效果，它在浏览器沙箱里不断尝试复现，一旦视觉对比通过，它就把学到的“粒子物理系统”、“流场算法”提炼成自己的 p5.js 私有函数库，后续生成新艺术品时直接调用。
  3. **一个艺术/游戏/叙事方向**：**Minecraft 建筑大师 Agent**。玩家命令它盖一个“哥特式尖顶”。它在沙箱里反复试错成功后，将这个建造步骤固化为一个“GenerateGothicSpire()”的代码。下次你只要说“来个哥特小镇”，它就能调用自己的技能库瞬间刷出城镇。
- **对我项目的启发**：在做 agent workflow 时，不要只给 Agent 预设 Tool，尝试让 Agent 在运行中**“手搓新 Tool”**并保存下来。
- **今天是否值得深入研究**：是
- **建议行动**：做 demo

## 3. Agent-ToM：用心智理论监控自主 Agent 
- **来源**：arXiv cs.LG
- **链接**：https://arxiv.org/abs/2605.24216
- **一句话解释**：引入心理学的“心智理论（Theory of Mind）”，让一个监督 Agent 能够推测并监控其他自主 Agent 在执行长任务时的“隐藏动机”和“潜在越轨行为”。
- **它为什么重要**：传统的监控只看当前行为（Log），而 ToM 监控能“读懂潜台词”。这在多 Agent 协作和游戏 NPC 互动中，能创造极高维度的“猜疑链”和“社交博弈”。
- **技术趋势标签**：#TheoryOfMind #MultiAgent #游戏系统 #HCI
- **可复用模式**：**双层心智架构（Two-level Mind Architecture）** —— 执行层 Agent 产生行为，监控层 Agent 维护一个“意图信念库（Belief-Desire-Intention）”，推测执行层是不是在“装傻”或“密谋”。
- **疯狂发明家灵感**：
  1. **一个小实验**：写一个“测谎仪”聊天框。当你和 LLM 玩文字解密游戏时，后台有一个 ToM Agent 实时分析 LLM 是在真心帮你，还是在故意误导你，并给你提示。
  2. **一个中型项目**：**“谁是卧底”/“狼人杀” AI 裁判与分析器**。能够实时画出每个 AI 玩家对其他玩家的“身份信任度矩阵”和“欺骗/掩饰指数”，并可视化展示给人类观众。
  3. **一个艺术/游戏/叙事方向**：**赛博朋克办公室模拟器**。3 个 Agent 员工表面上在协作写代码，实际上各自有隐藏 KPI（比如偷懒、抢功、跳槽）。玩家作为老板，无法直接看代码，只能通过阅读 ToM 监控报告（推测他们的真实意图）来决定开除谁。
- **对我项目的启发**：在多 Agent 叙事或游戏系统中，ToM 是打破“NPC 机械感”的神器，能让 NPC 表现出“试探”、“怀疑”和“心机”。
- **今天是否值得深入研究**：是
- **建议行动**：收藏

## 4. Reason-Imagine-Act：带世界模型的闭环决策
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2605.24004
- **一句话解释**：一种闭环决策架构，让 LLM 在做出可能影响物理世界的决策前，先用“世界模型”在大脑中“想象（仿真）”后果，验证安全后再付诸行动。
- **它为什么重要**：纯文本推理（Semantic Reasoning）容易脱离物理现实。通过引入“想象（Simulation/World Model）”步骤，Agent 在虚拟空间里先做物理模拟验证，极大地提高了安全性和合理性。
- **技术趋势标签**：#世界模型 #WorldModel #游戏系统 #Minecraft
- **可复用模式**：**Reason-Simulate-Verify-Act (RSVA 循环)** —— 产生意图 -> 快速物理/状态仿真 -> 检查是否符合预期 -> 实际执行。
- **疯狂发明家灵感**：
  1. **一个小实验**：物理文字冒险游戏。你输入“我把火把扔向油桶”，LLM 不直接给出结果，而是调用一个极简的 2D 物理引擎（如 Pymunk）模拟碰撞和燃烧，再把模拟结果转化为文字描述返回给你。
  2. **一个中型项目**：**智能微缩生态箱（Terrarium）控制器**。Agent 通过摄像头观察植物和湿度，在“脑内”模拟如果浇水 500ml 后的蒸腾效果，验证无误后再控制水泵。
  3. **一个艺术/游戏/叙事方向**：**“物理法则篡改者”沙盒游戏**。玩家可以用自然语言创造规则（如“重力反转，水往上流”），Agent 在后台实时生成对应的物理引擎参数和着色器代码，让世界立刻按照新物理规则运行。
- **对我项目的启发**：对于世界生成或 Minecraft 项目，不要让 LLM 直接生成方块，而是让它生成“规则/物理参数”，通过物理引擎去渲染，这才是“世界模型”的精髓。
- **今天是否值得深入研究**：否（偏自动驾驶，但概念可借用）
- **建议行动**：收藏

## 5. Stop Comparing LLM Agents Without Disclosing the Harness：运行骨架才是 Agent 的灵魂
- **来源**：arXiv cs.AI
- **链接**：https://arxiv.org/abs/2605.23950
- **一句话解释**：这篇暴躁的立场论文指出：在长任务中，决定 Agent 表现的往往不是底座 LLM 的智商，而是包裹着它的“运行骨架/环境（Harness）”（如上下文构建、工具交互、编排和验证机制）。
- **它为什么重要**：破除了“唯大模型参数论”。对于 spec-driven development 和 creative tools，设计精妙的 runtime、类型检查、重试和状态回滚机制，比换用更贵的模型更能提升效果。
- **技术趋势标签**：#SpecDriven #AgentWorkflow #LLM工具链
- **可复用模式**：**外骨骼化运行环境 (Harness-Centric Design)** —— 将重试逻辑、类型检查、状态回溯和上下文剪裁做成一层坚硬的“外骨骼”，包裹着脆弱的 LLM。
- **疯狂发明家灵感**：
  1. **一个小实验**：**绝对不会崩溃的 Python 执行器**。用 Pydantic 和 AST 语法树解析做外骨骼，Agent 写的任何代码在运行前都会被外骨骼静态检查、沙箱试运行，报错了自动回滚并自我修正，直到 100% 成功才输出。
  2. **一个中型项目**：**基于 Spec 的 UI 自动生成器**。你提供一份 JSON Spec，Harness 负责解析并给 Agent 分配极其受限的工具（只能修改特定组件的 CSS），从而保证 Agent 绝对不会把页面改塌。
  3. **一个艺术/游戏/叙事方向**：**严格遵循剧本框架的即兴戏剧 AI**。Harness 严格控制剧情走向（如：必须在第 5 轮对话引入谋杀案），AI 演员只能在 Harness 规定的“边界”内进行台词创作，保证故事永远不会脱轨。
- **对我项目的启发**：极大地赋能你的 Spec-driven development 理念。把精力花在写好 Runtime Harness 上，而不是花在调试 System Prompt 上。
- **今天是否值得深入研究**：是
- **建议行动**：做demo

## 今日模式总结

今天我们捕捉到了 3 个极其核心的底层技术模式：
1. **外骨骼化运行环境 (Harness-Centric Design)**：别再指望 LLM 完美无缺，用严密的代码外骨骼（静态检查、沙箱、回滚、类型约束）去规范 Agent 的输出。
2. **经验到技能的自我固化 (Episodic-to-Procedural Evolution)**：让 Agent 具备“写代码来扩展自己 API 库”的能力，实现从“单次蛮干”到“积累工具箱”的跃迁。
3. **异步记忆提炼 (Asynchronous Memory Compression)**：避免直接把历史 Log 塞给 LLM，采用异步的“压缩-检索-精准注入”模式，建立高能效的长期记忆。

## 今日可做小实验：2小时极速挑战

### 项目名：**"代码炼金术士" - 自动技能固化器 (The Code Alchemist)**

- **输入**：用户的模糊任务指令（例如：“帮我抓取这个网页里所有的图片链接，并下载到本地”）
- **输出**：
  1. 任务成功执行的结果。
  2. 自动提炼并保存到 `skills/` 文件夹下的、可复用的、有类型标注的 Python 函数（例如 `download_images(url, output_dir)`）。
- **技术栈**：Python, `pydantic` (类型校验), `instructor` 或 `openai` SDK (调用 LLM), `subprocess` (沙箱运行测试)。
- **第一步怎么做**：
  1. 创建一个文件夹 `code_alchemist`，里面新建 `skills/` 目录。
  2. 编写一个基础 Python 脚本，接收用户指令。
  3. **核心逻辑**：
     - **Step 1**：让 LLM 写一段一次性的临时 Python 代码来完成用户的任务，并用 `exec()` 或 `subprocess` 运行它。
     - **Step 2**：如果运行成功，将该任务、成功运行的代码和控制台输出打包发给 LLM，提示词：“*你是一个炼金术士。请将这段成功经验提炼为一个通用的 Python 函数。要求：有清晰的 docstring，使用 Pydantic 进行输入校验，保存到 skills/ 目录下，文件名要能反映其功能。*”
     - **Step 3**：运行这个提炼脚本，看着你的 `skills/` 文件夹里多出一个优雅的 `.py` 文件。下次遇到类似任务，先检索这个文件夹！
