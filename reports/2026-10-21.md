# 疯狂发明家技术雷达 - 2026-10-21

从今天的技术动态来看，一个极其明显的趋势是：**围绕“编码 Agent 原生协议/工作流（Claude Code/Codex 等）”的基础设施和环境扩展正在全面爆发**。抛开泛泛的推理优化，我为你筛选了 4 个最能刺激艺术、游戏系统与 Agent 工作流交叉灵感的项目：

## 1. Graphify：摒弃向量检索的代码与文档“确定性 AST 知识图谱”
- 来源：GitHub Trending Python
- 链接：https://github.com/Graphify-Labs/graphify
- 一句话解释：通过确定性 AST 解析（不用向量数据库）将整个代码库、Schema、PDF 转化为带因果关系的图谱，并暴露为 Agent 的直连 Skill。
- 它为什么重要：当前 RAG 普遍过度依赖模糊的向量相似度，导致 Agent 理解复杂系统拓扑时经常“幻觉”。这个项目用确定性 AST 语法树建图，每条边都有明确解释，是做系统级理解、严谨架构生成（Spec-driven）的核心基石。
- 技术趋势标签：`Code Graph` `Deterministic RAG` `AST` `Agent Skills`
- 可复用模式：**AST-to-Graph determinism** —— 不用语义相似度检索，而是静态分析代码/数据流图，把全局依赖关系直接丢给 Agent 推理。
- 疯狂发明家灵感：
  1. **一个小实验**：把一个微型 roguelike 游戏项目的 ECS（实体组件系统）用 Graphify 建图，让 Claude Code 检查是否有“循环依赖的逻辑死锁”。
  2. **一个中型项目**：**“Living Architecture 3D”**：将 Graphify 导出的图结构喂给 Three.js/Force-directed graph，实时渲染出代码拓扑，并在你敲代码时动态高亮 Agent 正在穿梭思考的路径。
  3. **一个艺术/游戏/叙事方向**：**交互叙事 AST**：把叙事分支（Twine/Ink 脚本）解析成图谱，Agent 扮演反派角色，沿着图谱的边寻找玩家尚未封堵的“叙事逻辑漏洞”并发动叙事突袭。
- 对我项目的启发：如果要做世界生成或规则系统，不要一上来就用 Vector RAG，先用 AST 建立硬性的因果图（Causal Graph），Agent 才能真正理解世界的物理/魔法法则。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 2. Headroom：在 Tool-calling 到达 LLM 前的极限中间件压缩器
- 来源：GitHub Trending Python
- 链接：https://github.com/headroomlabs-ai/headroom
- 一句话解释：专门给 Coding Agent 和 MCP Server 准备的透明代理，把工具吐出的海量 JSON/日志/Chunk 无损压缩 60%-95% 后再喂给模型。
- 它为什么重要：多 Agent 编排和世界模拟中最致命的瓶颈是上下文窗口被冗余的结构体（例如游戏状态、Minecraft 方块数据、API 日志）挤爆。这个项目在协议层做结构化语义压缩，能大幅降低延迟和 Token 成本。
- 技术趋势标签：`MCP Middleware` `Token Compression` `Agent Efficiency` `Context Optimization`
- 可复用模式：**Proxy-layer semantic squashing** —— 在感知端（环境/工具）与思考端（LLM）之间设立过滤器，剥离机器冗余，保留意图语义。
- 疯狂发明家灵感：
  1. **一个小实验**：在本地 MCP 服务器前挂载 Headroom，传入一个 10,000 行的 Minecraft NBT/方块空间 JSON，测算压缩率并测试 Agent 是否仍能正确执行建造指令。
  2. **一个中型项目**：**“微型世界状态广播网”**：为多智能体城镇模拟写一个事件总线，所有 NPC 的长篇行为日志经由 Headroom 压缩为极度紧凑的“世界脉搏流”，允许百个 Agent 跑在单台低配机器上。
  3. **一个艺术/游戏/叙事方向**：**高频感知数字生物**：让 Agent 能够以 10Hz 的极高频率接收游戏物理引擎数据（位置、碰撞、速度），而不会在一分钟内爆掉 100k 的上下文窗口。
- 对我项目的启发：对于复杂生成式系统，必须把“上下文压缩器”作为标准中间件，否则 Agent 永远被困在低频低维的交互中。
- 今天是否值得深入研究：是
- 建议行动：试用

## 3. Artemis：自然语言驱动的无死角 Android 自主操作代理
- 来源：GitHub Trending Python
- 链接：https://github.com/google/artemis
- 一句话解释：Google 推出的端到端 Android 自动化系统，在基准测试上达到 99%+ 准确率，无缝桥接 Claude Code 等现代 Agent。
- 它为什么重要：过去 UI Agent 经常迷失在无障碍树（Accessibility Tree）或像素视觉差中。Google 把它做到了 99% 的工程可用级。这意味着手机不再只是个消费端，而是可以变成“由 Agent 接管的硬件外设”。
- 技术趋势标签：`Device Agent` `GUI-Automation` `Embodied Agent` `Mobile HCI`
- 可复用模式：**Log-reflex Loop** —— 深度结合系统 Logcat 日志捕获与视觉多模态，用底层系统真实状态闭环修正 Agent 的下一步盲动。
- 疯狂发明家灵感：
  1. **一个小实验**：给 Artemis 一个指令：“打开手机相机，拍下桌上的水杯，用即时修图软件调成赛博朋克风并设为壁纸”。
  2. **一个中型项目**：**“物理手机寄生虫（Digital Parasite）”**：把一台闲置安卓手机挂载在工位上，Agent 每天根据你的日程自动去各种真实 App（社交媒体、日历、外卖）中抓取物理现实碎片，编译成一天的世界日志。
  3. **一个艺术/游戏/叙事方向**：**ARG（平行实境游戏）的真实接线员**：一个运行在真实手机上的 AI 角色，玩家给它打电话、发 WhatsApp，它能够自主操作手机各种 App 去“替玩家查案”，模糊游戏与真实设备的界限。
- 对我项目的启发：在 HCI 设计上，Agent 的输出不一定是一段代码或一张图，可以是一次“对物理设备的远程夺舍操作”。
- 今天是否值得深入研究：否（依赖 Android 环境配置成本较高）
- 建议行动：收藏

## 4. Ruflo：多玩家蜂群智能协同框架（Multi-player Swarms Harness）
- 来源：GitHub Trending TypeScript
- 链接：https://github.com/ruvnet/ruflo
- 一句话解释：专为 Claude Code / Hermes 等现代 Agent 设计的分布式多 Agent 蜂群容器，集成自学习记忆系统和多 Agent 协同网络。
- 它为什么重要：很多 Multi-agent 库（如 Autogen, CrewAI）过度臃肿且脱离最新终端 Agent 的原生体验。Ruflo 是原生针对现代本地 Agent 协议构建的分布式编排器，主打“多玩家（Multi-player）”与“联合（Federation）”，非常贴合游戏/涌现系统。
- 技术趋势标签：`Swarm Intelligence` `Multi-Agent System` `Adaptive Memory` `Federated Agents`
- 可复用模式：**Swarm Harness Protocol** —— 统一约束多个 Agent 的角色状态、自适应长程记忆，使其像多人联机游戏一样加入/离开协同网络。
- 疯狂发明家灵感：
  1. **一个小实验**：创建 3 个性格对立的微型 Agent（极简主义建筑师、野蛮主义者、废土拾荒者），在同一个本地文件夹内争夺同一个文档的修改权。
  2. **一个中型项目**：**“自主代码生态池（Code Ecosystem）”**：一个 Agent 专门写 BUG 生成机制，一个 Agent 扮演黑客攻破系统，第三个 Agent 作为防御者修补架构，观察其演化。
  3. **一个艺术/游戏/叙事方向**：**“无尽剧本研讨室”**：为叙事游戏搭建多 Agent 编剧群，其中一个负责“提供逻辑合理的推演”，另一个负责“引入不可预测的宿命悲剧”，实时生成可交互的 TRPG 剧本树。
- 对我项目的启发：多智能体系统的本质就是“游戏规则设定”。把 Agent Harness 视作游戏引擎中的 Ruleset，可以让生成式世界更加自洽。
- 今天是否值得深入研究：是
- 建议行动：做demo

## 今日模式总结

1. **去向量化的“强拓扑结构”（Deterministic Topologies over Vectors）**：
   从 Graphify 可以看出，开发者对概率性向量召回的容忍度正在降低。无论是代码分析还是世界观构建，**AST、有向无环图（DAG）、因果知识图谱** 正在重新成为 Agent 精确行动的中枢。
2. **中间件级的内容压缩（Context Squashing at Middleware）**：
   Headroom 展现了 Agent 工具链进化的下一站：不再指望 LLM 拥有无限且廉价的上下文，而是在协议层（MCP/Proxy）拦截数据流，将其进行**高密度符号化压缩**后再交付认知层。

## 今日可做小实验

### 实验名称：`AST-Graph-Narrative` —— 基于确定性语法树的因果世界规则验证器
用 Graphify 的核心思路（AST 解析因果关系，而非向量相似度），构建一个不可违背的游戏规则检查器。

- **输入**：一段极简的 JSON/DSL 格式世界法则（包含物品合成、空间移动约束）。
- **输出**：一个自动生成的“拓扑因果关系图”，并在 Agent 试图生成违背物理/规则的行动时，直接通过图的最短路径报错打回。
- **技术栈**：Python, NetworkX（或 AST 模块）, Claude API
- **第一步怎么做**：
  1. 用 Python 写一个 20 行脚本，用 `networkx.DiGraph` 定义三个因果节点：`[钥匙] -> opens -> [铁门]`，`[铁门] -> contains -> [宝箱]`。
  2. 让 Agent 接收用户输入（例如“我直接伸手拿宝箱”）。
  3. 脚本不使用 LLM 检索，直接在 Graph 中判断 Agent 的行动路径是否缺失前置边，如果是，将图的断点原因直接作为 System 错误反馈给 Agent 重新规划。感受一下“确定性图结构约束 Agent”的爽快感。
