## [MirrorCraft] 当 Minecraft 世界隐蔽修改规则，Agent 如何不崩溃？
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2607.29218
- 一句话解释：在 Minecraft 中动态修改游戏底层机制（如合成表改变、掉落物置换），测试 LLM Agent 在规则突变下的归纳推理与适应能力。
- 它为什么重要：大部分 AI 游戏体只是在“死记硬背”固定的 Wiki。真正有趣的涌现和智能，来自于**规则被打破后的推演与突变**——这不仅是智能基准，更是极佳的游戏机制设计视角。
- 技术趋势标签：`Minecraft` `Game Systems` `Dynamic Rules` `Agent Adaptation`
- 可复用模式：**隐性规则诱发测试（Hidden Rule Perturbation）** —— 接口保持不变，但改变底层逻辑，强制 Agent 形成新假设并进行自省。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个极简网格环境，把“按上变向左”设为隐藏规则，看 LLM 几步能更新内建物理假说。
  2. **一个中型项目**：Minecraft 疯人院 Mod —— 打造一个物理/合成法则每日随机突变的模拟世界，让 Agent 尝试求生并记录它们的“迷信行为”。
  3. **一个艺术/游戏/叙事方向**：**《失语法则》交互叙事游戏** —— 玩家与 AI NPC 处于一个自然法则逐渐失效的世界，NPC 必须通过观察玩家的荒谬行为来重新推演“神意”（规则）。
- 对我项目的启发：在设计 Agent 或 Spec 时，加入“假设检验”机制，别让 Agent 盲目依赖固化的系统 Prompt，而是具有试错自省能力。
- 今天是否值得深入研究：是
- 建议行动：做demo

## [SESA] 自己给自己出题、解题并进化技能树的自演进化 Agent
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2607.29468
- 一句话解释：Agent 通过 Self-Play 自动提出难题（Pose）、解决难题（Solve），并将解决策略打包为可复用的程序化技能（Remember）。
- 它为什么重要：它把零散的 CoT（思维链）推理转化为了**可积累的代码/技能资产**。这与 Spec-Driven 开发和自动化系统的终极目标完全一致。
- 技术趋势标签：`Procedural Skill` `Self-Play` `Agent Memory` `Auto-Curriculum`
- 可复用模式：**“提问者-解答者-技能归档器”三元环（Pose-Solve-Archive Loop）**。
- 疯狂发明家灵感：
  1. **一个小实验**：让一个 LLM 随机提出 p5.js 视觉效果需求，另一个 LLM 实现并把复用率高的图形逻辑自动封装为 `.js` 模板库。
  2. **一个中型项目**：自演化的 Creative Coding 助手 —— Agent 自动探索图形算法，将成功的设计风格打包成可调参的 Shader 节点树。
  3. **一个艺术/游戏/叙事方向**：**《自生成工匠》** —— 一个在沙盒世界里自己发明工具、构建建筑范式的 AI 工匠，玩家通过收集它发明的“工具卡牌”与其合作。
- 对我项目的启发：Agent 的持久化记忆不应当只是文本日志，而应当是**可执行的代码/技能库（Skill-as-Code）**。
- 今天是否值得深入研究：是
- 建议行动：试用

## [Analytic Memory] 分析型记忆：AI 记忆不再只是检索，而是可“计算”的时空账本
- 来源：arXiv cs.AI
- 链接：https://arxiv.org/abs/2607.29440
- 一句话解释：突破传统 RAG 的“按相似度搜片段”，为多模态 Agent 建立能够跨时空进行聚合、统计与逻辑计算的“分析型记忆”。
- 它为什么重要：传统的检索记忆只能回答“我见过什么”，而分析型记忆能回答“这种行为模式在过去三天出现的频率趋势是什么”，是构建真正长期跨度 HCI 的关键。
- 技术趋势标签：`Multimodal Memory` `Analytic Memory` `HCI` `Generative Systems`
- 可复用模式：**时空聚合数据流（Spatiotemporal Analytic Ledger）** —— 在 Memory 上层挂载一个可编程计算引擎，而非直接把原始日志丢给 Vector Store。
- 疯狂发明家灵感：
  1. **一个小实验**：写一个轻量脚本记录你半天的屏幕截图，让 Agent 计算并绘制你的“注意力集中度与应用切换频率”导数曲线。
  2. **一个中型项目**：设计过程隐形侦探 —— 自动追踪创作软件（如 Figma/Blender）操作历史，分析并生成你的“设计思维惯性报告”。
  3. **一个艺术/游戏/叙事方向**：**《回忆计算器》交互装置** —— AI 扫描观众的照片库，不展示原图，而是将观众几年的生活轨迹“计算”并现场绘制成一副抽象的心理地形图。
- 对我项目的启发：为自动化工作流注入一个“指标分析层”，让系统能像监控仪表盘一样审视自己的历史轨迹。
- 今天是否值得深入研究：是
- 建议行动：收藏

## [Meta-Routing] 组合式元路由：Agentic Workflow 的智能调度指挥官
- 来源：arXiv cs.LG
- 链接：https://arxiv.org/abs/2608.00106
- 一句话解释：训练轻量级元路由器（Meta-Router），根据任务复杂度动态编排 Agent 是直接回答、分解任务、写代码还是派发给特定专家。
- 技术趋势标签：`Agentic Workflow` `Meta-Routing` `Spec-Driven` `Automation`
- 它为什么重要：写死的工作流（如固定 LangGraph 节点）太僵硬，全交给大模型决策又贵又慢。元路由实现了工作流拓扑结构（Topology）的**自适应流式编排**。
- 可复用模式：**分层意图路由（Hierarchical Intent Router）** —— 基于规则或小模型根据上下文 Spec 动态切换工作流管道。
- 疯狂发明家灵感：
  1. **一个小实验**：构建极简 Router 脚本，根据用户输入 Prompt 的结构复杂度，自动分流到 Fast-LLM、RAG 管道或多 Agent 协作网络。
  2. **一个中型项目**：Spec-Driven 代码生成引擎 —— 输入一个需求 Spec，Meta-Router 自动决定是串行写代码、并行写测试，还是调用静态分析工具。
  3. **一个艺术/游戏/叙事方向**：**《AI 剧场导演系统》** —— 根据现场观众的反应实时评估“混沌度”，Meta-Router 动态切换演员 Agent 的推理深度与剧本分支。
- 对我项目的启发：在设计系统的 Spec 时，不要死板定义 Flow，而是定义 Router 的决策规范（Router Spec）。
- 今天是否值得深入研究：否（概念重要，但具体实现可直接先用轻量代码模拟）
- 建议行动：试用

## 今日模式总结

1. **技能与记忆的代码化/结构化（Skill-as-Code & Analytic Memory）**：AI 的长期演化正从“追加 RAG 纯文本”向“编译为可执行代码/计算账本”转变。
2. **法则扰动与自适应（Hidden Rule Perturbation）**：从“拟合静态环境”走向“在未知/突变法则下动态推演假设”，这是游戏 AI 和健壮 Agent 的新趋势。
3. **元路由驱动拓扑（Meta-Routing Topology）**：工作流编排不该写死，也不该全交给耗时的大模型，应该用轻量路由规范进行流式编排。

## 今日可做小实验：RuleShift-Agent（规则突变求生 Agent）

一个 2 小时内可完成的实验，体验 AI 在物理规则突变下的假设推演过程：

- **项目名**：`RuleShift-Agent`
- **输入**：一个简易文本网格环境，隐藏逻辑被修改（例如：动作 `'UP'` 实际效果是向左走；`'EAT_APPLE'` 实际效果是扣血）。
- **输出**：Agent 的终端实时日志，包含它维护的 `<Hypothesis>`（对世界物理规则的假设）与更新轨迹，最终成功脱困。
- **技术栈**：Python + OpenAI / Claude API (或 Ollama 本地模型)。
- **第一步怎么做**：
  1. 创建一个 Python 文件，写一个 5x5 的文本 GridWorld 类，写死隐藏规则字典：`rule_map = {'UP': 'LEFT', 'EAT': 'DAMAGE'}`。
  2. 编写 Prompt，要求 Agent 每次行动返回固定格式：
     ```json
     {
       "Hypothesis": "我猜测 UP 实际上是向左移动...",
       "Action": "MOVE_RIGHT"
     }
     ```
  3. 将环境反馈（如 `"你执行了 UP，但坐标变成了 [0, 1]"`）喂回 Agent，观察它几轮内能校正假说并通关。
